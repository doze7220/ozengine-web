### 2. 現在進行中のタスク・懸念事項（毎セッション更新）
* **A. 次フェイズ／Interruptへ持ち越す事項**
  * フレーム処理の外からのシーン操作で `init`・`destroy` が例外を投げると、ループは止まらず、スタックが途中の状態で残る。今回は `oz/ENGINE_API.md` 15章に書くだけとした。対処するかは別Phaseで判断する（発注者に報告済み）。
  * `oz/src/` の非公開フィールドの書き方が混在している（`Time`・`Scenes`・`GameLoop` は `#`、`Screen`・`Layers`・`DebugOverlay` は `_`）。動作に影響はない。
  * `js/main.js` の責務定義の2行目は目印の外にあり、見本を消すと実態と合わなくなる。Phase 01-04 で見直す。
  * `js/main.js` の確認用コードの `trail` のコメント「押している間の跡」は実際の動作（すべての移動の跡）と違う。動作に影響はなく、Phase 01-04 で確認用コードごと置き換える。
  * `js/main.js` の確認用コードの `SampleLoadScene.init` の JSDoc「BGM と SE を鳴らして」は、入力の前なら実際には鳴らない。動作に影響はなく、Phase 01-04 で確認用コードごと置き換える。
  * Phase 01-04: 最初の入力より前の音の要求は捨てる（発注者の決定）ので、BGM は最初の入力への反応の中で `playBgm` を呼ぶ。ボタンが消費した押下はシーンの `onPointer` に届かないので、必要なら `onPress` でも呼ぶ。
  * 素材（`assets/images/sample.png`、`assets/sounds/sample_se.mp3`、`assets/sounds/sample_bgm.mp3`）は発注者が音を聞いて選んだものではない。合わなければ差し替える。
  * `oz/index.js` を import した時点で `window` が必要になった（`Sound` が入力の登録を読み込み時に行うため）。P1 後に `node --test` を入れるときは、スタブを用意してから動的 import するか、登録の時期を見直す。
  * AudioContext が `running` になると再開用のイベントを解除するので、iOS の割り込みなどでブラウザが止めた場合は自動で再開しない。今回は対応していない。
  * タブを裏に回しても音は止まらない（REQの決定）。止めたくなったら別の作業として扱う。
  * 憲法3章「時間の受け渡し」に対する `AudioContext.currentTime` の例外は、`PROJECT_ARCHITECTURE.md` 3章に書いたが、憲法の本文には書いていない。憲法に明記するかは別途判断する。
  * `Assets`・`Sound`・`Storage` は Node のスタブと発注者のテストプレイで確認した。読み込み失敗の確認は任意としたので、実行されたかは記録していない。
