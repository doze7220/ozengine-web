## 機能バックログ

### エディタの P5（塗り）の後
* 土台の機体は、エディタの P5（塗り）のあとで本番の絵に差し替える。それまでは書き直した手書きの `ship.js` を使う

### P3：方針
本リポジトリの作業だけで閉じるフェイズにする（2026-11-09 発注者決定）。VANGUARDRIFTER の進み具合は完了条件に入れない。
* 完了条件：次の3点がそろうこと
  * 本リポジトリから新規プロジェクトを作れる（作り方の手順、ゲーム用のルール、deny 設定がそろっている）
  * 土台の機体を、スマホの実機でバーチャルコントローラーを使って操作できる（GitHub Pages で確認する）
  * 「P3：スマホ対応」の残りの項目が済んでいる
* 順番：「P3：最初に整えるもの」を先に済ませる。済んだら VANGUARDRIFTER のプロジェクトを作り、P3 の残りと並行して進められる

### VANGUARDRIFTER のリメイク（フェイズとは別に進める）
ゲームは新しいプロジェクトフォルダで作る。エンジンの検証が目的なので、コアループを1周遊べること（タイトル、プレイ、結果を経てタイトルに戻る）をゲーム側のマイルストーンの目標にする。ステージやキャラクターの作り込みは目標に入れない。
* 不足の連絡：ゲーム側で見つかったエンジンの不足は、本リポジトリの `_doc/BRIDGE_FROM_VANGUARDRIFTER.md` で受け取り、その都度 Interrupt で `oz/` と `oz/ENGINE_API.md` を直す。エンジン側の作業量は先に決めず、「P3 以降で検討する機能」の候補も、実際に必要になったものだけ入れる
* スプライト：エディタの完成は待たない。足りない絵は書き出し形式（既定の export で `draw` を持つ）に合わせて AI に JS を書かせてつなぎ、エディタが追いついたらファイルを差し替える

### P3：最初に整えるもの
* 新規プロジェクトの作り方：`template-app` を元にして、本リポジトリの `index.html`、`oz/`、`js/`、`assets/` をコピーする。`ozengine sample` を検索して目印の付いたコードを消し、`assets/` の中身を入れ替える（バーチャルコントローラーの既定の画像は、同じファイル名で上書きする）。以後のエンジン更新は `oz/` の置き換えだけで行う
* ゲーム用のルール：`template-app` は汎用のままにする。貼り付ける文面（`oz/` を編集しない、`oz/src/` を読まない、機能が足りないときは回避策を書かず、不足を RES に記録する。エンジン側で直してから `oz/` を置き換える）と設定例をエンジン側で持ち、立ち上げの Step 2 で憲法に組み込む
* Claude Code の deny 設定（`oz/src/` の読み書き禁止、`oz/` の編集禁止）と、`oz/` のハッシュ照合
* Phase 01 の持ち越し（`COWORK_STATUS.md` 2章）：スプライトの規約の案内の置き場所を判断する。`PROJECT_ARCHITECTURE.md` 4章の `js/main.js` の行にある「見本の部分」の記述を見直す

### P3：スマホ対応
* バーチャルコントローラー
  * エンジン（`oz/`）は、マルチタッチの受信、指の追跡、スティックとボタンの当たり判定、押下状態を持つ。配置、見た目の描画、キーの割り当てはゲーム側で持つ
  * 仮想入力は `Engine.isKeyDown`・`onKeyDown` に流し、ゲームのロジックが PC とスマホを意識しなくて済むようにする。`onPointer` は単一ポインタのまま変えず、コントローラーが処理した指は届けない
  * 既定の画像は本リポジトリで用意して `assets/images/vpad/` に置き、各アプリで書き換える。エンジンからは `assets/` を参照せず、土台の `js/` が読み込んで描く
  * 既定の画像と描画コードには `ozengine sample` の目印を付けない。使わないゲームは `js/main.js` の設定で OFF にする。OFF のときは画像を読み込まず、何も描かない
  * 目印を付けた部分をすべて消しても起動できることを、ON と OFF の両方で確かめる
  * アナログ値（スティックの倒し具合）は、必要になってから読み取りの API を足す
* iOS の割り込みなどでブラウザが止めた AudioContext が自動で再開しない問題を扱う（`COWORK_STATUS.md` 3章）
* 高解像度画面での Canvas 解像度（`devicePixelRatio` 対応）を判断する
* スマホ実機で確認する（2本指の同時操作、ボタンの押しやすさ）。P1 から持ち越した、タッチの最初の押下と音の出始めの確認も行う（`COWORK_STATUS.md` 2章）
* 実機確認は GitHub Pages で行う（2026-11-09 発注者決定）。公開の設定は発注者が行う。公開先のパスはリポジトリ名の下（`/ozengine-web/`）になるので、`/` から始まるパスを使わない。非公開のリポジトリで Pages を使うには有料のプランが必要になる

### P4：ゲームブックRPG（企画：`D:\ozlab\_attic\ideas\gamebookRPG.md`）
ゲームは新しいプロジェクトフォルダで作る。P3 と同じく、本リポジトリのフェイズはエンジン側の作業だけで閉じ、ゲーム側で見つかった不足は連絡票と Interrupt で直す。
* フォントの読み込み
* PC の見開きとスマホの単ページの切り替え
