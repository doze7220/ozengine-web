# マイルストーン・バックログメモ（OZ Engine）

本ファイルは発注者（人間）の作業メモであり、DIR/REQ/RESのような確定記録ではない。`Phase XX-00`（DIR策定）の材料として使う。

* **フェイズ管理**：Phase大番号の並びと大まかなテーマのみを書く。サブフェイズ分解（`Phase XX-01`〜）はDIRが正本であり、本ファイルには書かない。DIRを発行したら該当行に `[DIR発行済み: YYMMDD_HHMM]` を付記する。
* **機能バックログ**：DIR策定時に、そのPhaseで扱う項目を拾う。実装が完了した項目は本ファイルから物理的に削除する（完了記録として残す必要はない。完了の記録はRES側が担う）。

## フェイズ管理

P1：最小エンジンとゲームの土台
P2：スプライトJSの結合（M1の達成）
P3：VANGUARDRIFTER の移植（候補）

### M1 の定義
OZ Vector Editor で描いた絵をJSで書き出し、そのファイルに差し替えるだけでゲームの土台に表示されること。線画の機体でも完了とする（塗りつぶしはエディタの P5 以降で対応する）。

## 機能バックログ

### P1：完了条件
* `js/` に `requestAnimationFrame`・`addEventListener`・`getContext` が残っていないこと（grep で確認する）
* ルートの `index.html` を静的サーバで開くと動くこと
* `ozengine sample` の目印が付いた部分をすべて消しても、エラーなく起動できること（一時的なコピーで確かめる）
* `oz/src/` を読めないように設定した別のAIが、`oz/ENGINE_API.md` だけを見て `js/` を作れること。詰まった箇所はドキュメントの不足として直す

### P1：エンジンの抜き出し元（`D:\ozlab\phaseout`。参考のみで、phaseout 自体は変更しない）
* シーン：`js/scene/BaseScene.js`、`js/core/SceneManager.js`。スタック管理と切り替え後の時間スパイク対策を流用する。グリッチ遷移と `stopBGM` の呼び出しは持ち込まない
* レイヤー、ループ、時間：`js/render/MasterRenderer.js`。1枚の Canvas に順に描く仕組みを流用し、ループと時間を分離する。12層の固定定義と `GameState` への依存は持ち込まない
* 固定ティック：`js/core/physics.js` の 1000/60 の蓄積処理と5ティック上限を参考にする
* 入力：`js/core/InputManager.js`。論理座標変換と優先度付き配信を流用する。押下しか扱っていないので、移動、離す、キーボードを追加する
* ボタン：`js/core/UIManager.js`。当たり判定を流用する。ただし描画中の位置更新はやめて、シーンごとの登録にする
* サウンド：`js/render/SoundManager.js`。ロード、再生、フェードだけを抜き出す
* セーブ：`js/core/config.js` の単一JSONと版番号の仕組み
* アセット：phaseout には相当するものがない（`new Image()` が各所に分散している）ので新規に設計する
* 時間と描画のルール：`PROJECT_ARCHITECTURE.md` の Global Invariants 7章・8章

### P1：ゲームの土台の内容（元：`D:\ozlab\_attic\proto\vernier.html`）
各機能を1か所ずつ使うだけにして、作り込まない。新規プロジェクトのコピー元になるので、見本として読めるように作る。
* 目印：`js/` のコードは新規プロジェクトにもコピーされる前提なので、消す前提のコードに `/* ozengine sample */` を付ける（書き方は憲法3章）
* 構成：`js/main.js`（`Engine.start` とレイヤー定義を1か所にまとめる）、`js/scenes/`（シーンの書き方の見本）、`js/effect/`（星、トレイル、風）、`js/entities/`（機体の動き）に分ける。新規プロジェクトでは目印の付いたコードを消して書き始める
* ループと時間：エンジンに任せる。スローを1キーで切り替える
* Canvas：固定の論理解像度にする
* レイヤー：星、トレイル、機体、風、UI に分ける
* シーン：タイトル（今の自動操縦をデモとして流す）→ プレイ → ポーズ（シーンを積む）
* 入力：キーで旋回と加速。タップでも開始できるようにする
* スプライト：機体を規約どおりのJSとして手書きする
* アセット：画像を1枚（`D:\ozlab\vanguardrifter\assets\dd.png` など）
* サウンド：ブースト時のSEとBGMを1つずつ（素材は phaseout から借りる）
* UI：DOM の見出しをやめて、Canvas のボタンを1つ置く
* セーブ：ミュート設定だけ保存する
* デバッグ：FPS表示
* カメラ：`js/` 側に置いたままにする（エンジンには入れない）
* 注意：元のコードはフレーム単位で動いていて、144Hz だと速くなる。固定ティックに載せれば調整値はそのまま使える
* 注意：噴射口の描画は `(-18, ±12)`、トレイルの起点は `(-43, ±12)` でずれている。意図の有無を確認する

### P2：OZ Vector Editor 側の作業（`D:\ozlab\ozvectoreditor` のリポジトリで行う）
* 書き出しの薄い版を、エディタの P4 より前に作る（今ある図形の線画だけ）
* 書き出す内容は `PROJECT_ARCHITECTURE.md` 2.1章の規約に従う（`format`、`draw`、`source`）
* エディタの「ファイル入力（JS形式）」は、将来の野望へ移す

### P3 以降で検討する機能
* 新規プロジェクトの作り方：`template-app` を元にして、本リポジトリの `index.html`、`oz/`、`js/`、`assets/` をコピーする。`ozengine sample` を検索して目印の付いたコードを消し、`assets/` の中身を入れ替える。以後のエンジン更新は `oz/` の置き換えだけで行う
* ゲーム用のルール：`template-app` は汎用のままにする。貼り付ける文面（`oz/` を編集しない、`oz/src/` を読まない、機能が足りないときは回避策をゲーム側に書く）と設定例をエンジン側で持ち、立ち上げの Step 2 で憲法に組み込む
* Claude Code の deny 設定（`oz/src/` の読み書き禁止、`oz/` の編集禁止）と、`oz/` のハッシュ照合
* カメラ、当たり判定、Entity基底クラス、オブジェクトプール、パーティクル
* 重い `draw` を画像に焼き付けるキャッシュ
* 遷移演出（フェードなど）
* UI部品（`phaseout` の `js/render/UIComponents.js` のタブやスクロール）
* ゲームパッド、マルチタッチ
* スプライトのアンカー、当たり判定の形（エディタにも機能の追加が必要）、発光の表現

### 様子を見て判断する項目
* 描画の補間（スローがカクつくようなら）
* 高解像度画面での Canvas 解像度（ぼやけが気になるようなら）
* `ENGINE_API.md` のAPI一覧を JSDoc から生成するツール（手書きでズレるようなら）
* JSDoc を使った型チェック
* 小さなゲーム向けの、1枚のHTMLへの結合
* 複数のスプライトを一括で再書き出しするツール
