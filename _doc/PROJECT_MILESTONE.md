## 機能バックログ

### エディタの P5（塗り）の後
* 土台の機体は、エディタの P5（塗り）のあとで本番の絵に差し替える。それまでは書き直した手書きの `ship.js` を使う

### VANGUARDRIFTER のリメイク（フェイズとは別に進める）
ゲームは新しいプロジェクトフォルダで作る。エンジンの検証が目的なので、コアループを1周遊べること（タイトル、プレイ、結果を経てタイトルに戻る）をゲーム側のマイルストーンの目標にする。ステージやキャラクターの作り込みは目標に入れない。
* 不足の連絡：ゲーム側で見つかったエンジンの不足は、本リポジトリの `_doc/BRIDGE_FROM_VANGUARDRIFTER.md` で受け取り、その都度 Interrupt で `oz/` と `oz/ENGINE_API.md` を直す。エンジン側の作業量は先に決めず、「P3 以降で検討する機能」の候補も、実際に必要になったものだけ入れる
* スプライト：エディタの完成は待たない。足りない絵は書き出し形式（既定の export で `draw` を持つ）に合わせて AI に JS を書かせてつなぎ、エディタが追いついたらファイルを差し替える

### P4：キャンバスキャッシュ
重い描画を前もって別の Canvas に描いておき、毎フレームはその画像を貼るだけにする仕組みを入れる。スプライトJSに限らず、画像の加工、図形、文字なども焼き付けの対象にする（phaseout では SVG と画像も使っていた）。他の文脈と切り離すため、独立したフェイズにする（2026-11-10 発注者決定）。
* 抜き出し元：`D:\ozlab\phaseout\js\render\SpriteCacheManager.js`（参考のみで、phaseout 自体は変更しない）。画像の読み込みと画素の加工（`getImageData`）、宝石・火花・パーティクル・波紋の図形、スコアの文字の焼き付けと、フェイズの切り替わりでの作り直し（白・黒の色違い）を行っている。ゲーム固有の中身（宝石の形、スコアの文字など）は持ち込まない
* エンジン側に置く：焼き付けには別の Canvas の `getContext` が必要で、憲法3章により `js/` には書けない。エンジンは焼き付ける仕組みだけを持ち、何をどう描くかはゲーム側が渡す。`PROJECT_ARCHITECTURE.md` 4章で `Assets` の「キャッシュ生成」は責務違反としているので、置き場所（新しいモジュールにするかなど）を決める
* 呼び出し方：焼き付けた結果を `draw(ctx)` を持つオブジェクトとして返せば、呼ぶ側はスプライトJSと同じ書き方のまま差し替えられる
* 大きさ：焼き付ける Canvas の大きさが要る。エディタの書き出しには `bounds` があるが、手書きのつなぎのスプライトにはない。`bounds` を使うなら、`oz/ENGINE_API.md` 23章の「`draw` 以外のキーは、エンジンも利用側も読まない」を見直す
* 解像度：焼き付けた画像は、拡大・回転で少しぼやける。Phase 03-03 で Canvas の画素数を「表示サイズ × min(`devicePixelRatio`, 2)」にした（倍率は利用側に公開していない。`PROJECT_ARCHITECTURE.md` 3章「Canvas の画素数」）。これに合わせて、焼き付ける解像度を決める
* 作り直し：色違いや演出の切り替えで、焼き付け直せるようにする
* 時期：P3 の後。VANGUARDRIFTER で重くなった場合は、この P4 を前倒しする
