# ゲームの憲法に貼り付けるルールの文面（GAME_RULES）

## この文面の使い方（この章は貼り付けない）
*   新規プロジェクト（ゲームのプロジェクト）の立ち上げの Step 2 で、ゲームの `PROJECT_CONSTITUTION.md` の3章（絶対禁止事項）の末尾に、下の囲みの中身をそのまま貼る。囲みの外（この章を含む）は貼らない。
*   貼った後、3章の既存の規則と重なる・食い違う箇所があれば、既存の規則の側を直す。貼った文面は変えない。
*   OZ Engine を更新して、この `GAME_RULES.md` が変わったときは、貼った部分を新しい文面に差し替える。
*   フレームワーク・ビルドツールの禁止、責務定義、JSDoc などの一般的な規則は、この文面に入れていない。Step 2 の憲法の最適化で決める（OZ Engine は、ビルドなしの ES Modules と import map を前提にしている）。

## 貼り付ける文面

ここから貼り付け（囲みの中だけ）

````markdown
*   **前置き（エンジンとゲーム側）:** `oz/` は OZ Engine（GitHub `doze7220/ozengine-web`、ローカル `D:\ozlab\ozengine-web`）から丸ごとコピーしたエンジン本体である。以下では `oz/` を「エンジン」、`index.html`・`js/`・`assets/` を「ゲーム側」と呼ぶ。エンジンの使い方の唯一の資料は `oz/ENGINE_API.md` である。
*   **エンジンの編集禁止:** `oz/` の中のファイルを編集・追加・削除・移動してはならない（`oz/ENGINE_API.md`・`oz/FINGERPRINTS.txt`・`oz/VERSION` も含む）。シェルのコマンドやスクリプトで書き換えることも禁止する。エンジンの更新は、発注者が `oz/` を OZ Engine のリポジトリの `oz/` で丸ごと置き換えることでだけ行う。
*   **エンジンの内部を読むことの禁止:** `oz/src/` のファイルを読んではならない。ファイルを読むツールに限らず、シェルのコマンド（`cat`・`grep` など）やスクリプトで中身を表示・検索することも禁止する。エンジンについて知るには `oz/ENGINE_API.md` だけを読む。`oz/VERSION` と `oz/FINGERPRINTS.txt` は読んでよい。`oz/` の指紋の照合は発注者が行い、AI は実行しない。
*   **エンジンの不足への対応:** 必要な機能が `oz/ENGINE_API.md` に無い、または書かれたとおりに動かないときは、ゲーム側に回避策（代わりの実装、`oz/src/` の内部への依存など）を書いてはならない。作業を止め、不足を RES に記録し、発注者の承認を得て OZ Engine のリポジトリの連絡票 `D:\ozlab\ozengine-web\_doc\BRIDGE_FROM_<GAMENAME>.md` に書いて伝える（書き方は OZ Engine のリポジトリの `_doc/newgame/NEW_GAME_GUIDE.md` 10章）。エンジン側で直った `oz/` に置き換わってから作業を再開する。
*   **入口の一本化:** エンジンは `import { … } from 'oz'` でだけ使う。`./oz/index.js` などのパスや `oz/src/` を import してはならない。
*   **基礎処理の直書き禁止:** `js/` に `requestAnimationFrame`・`addEventListener`・`getContext` を書いてはならない（ループ・入力・描画先の用意はエンジンが行う）。必要な機能がエンジンにないときは「エンジンの不足への対応」に従う。
*   **スプライトJSの手編集禁止:** `assets/sprites/` のスプライトJSのうち、OZ Vector Editor が書き出したものは手で編集してはならない（直すときはエディタで描き直して書き出し、ファイルを差し替える）。エディタで描けない絵が必要な場合に限り、REQ で明示されたときだけ、つなぎのスプライト（既定の export で `draw(ctx)` を持つ形。`oz/ENGINE_API.md` 23章）を手で書いてよい。エディタで描けるようになったら書き出しファイルに差し替える。
*   **ロジックと描画の分離:** `update` などの更新処理の中で描画してはならない。`draw` の中で状態を変更してはならない。
*   **時間の受け渡し:** 経過時間は、エンジンが渡す `update(dt)` の `dt` と `draw` の `time` だけを使う。ゲーム側で `performance.now()`・`Date.now()` などで時間を取って動きに使ってはならない。
*   **Canvas 状態の保護:** `ctx` の状態を変更する描画処理は、`ctx.save()` と `ctx.restore()` を対で使い、変更を外に漏らしてはならない。
*   **グローバル汚染の禁止:** `window` にプロパティを追加してはならない。すべてのオブジェクトはモジュールの中に閉じ込める。
````
