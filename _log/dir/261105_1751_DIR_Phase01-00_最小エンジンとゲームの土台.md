## 1. 大ゴール
`oz/` に最小のエンジンを作り、その上で動くゲームの土台を `index.html`・`js/`・`assets/` に作る。`D:\ozlab\phaseout` の基礎機能を共通化し、ゲームごとに作り直さないようにするために、最初に必要な作業である。Phase 02 では、このPhaseで手書きした機体のスプライトJSを OZ Vector Editor の書き出しファイルに差し替えて M1 を達成する。

* **完了の目安**: ゴール型。次の4点がすべて成り立つ状態を達成状態とする。
  * `js/` に `requestAnimationFrame`・`addEventListener`・`getContext` が残っていない（grep で確認する）。
  * ルートの `index.html` を静的サーバで開くと動く。
  * `ozengine sample` の目印が付いた部分をすべて消しても、エラーなく起動できる（一時的なコピーで確かめる）。
  * `oz/src/` を読めないように設定した別のAIが、`oz/ENGINE_API.md` だけを見て `js/` を作れる。詰まった箇所はドキュメントの不足として直す。

## 4. サブフェイズごとの実装要件

### Phase 01-01: エンジンの骨格（ループ、時間、画面、レイヤー、シーン）
* **目的**: 静的サーバで開くとエンジンのループが動き、シーンがレイヤーごとに描画される状態にする。
* **実装要件**:
  * ルートの `index.html` を静的サーバで開くと、固定の論理解像度の Canvas に確認用の図形が動いて表示される。
  * リフレッシュレートが異なる画面でも、図形の動く速さが同じである。
  * タブを裏に回してから戻しても、図形が大きく飛ばない。
  * 利用側で定義した複数のレイヤーが、定義した順に奥から手前へ重なって表示される。
  * `debug` を有効にすると FPS が最前面に表示され、無効にすると表示されない。
  * `oz/ENGINE_API.md` を読むだけで、ここまでの機能の使い方が分かる。
* **持ち越し事項**: なし
* **メモ**:
  * 入力がまだないため、動作の確認は `js/main.js` に置く最小の確認用コードで行う。確認用コードは Phase 01-04 で置き換える。確認用コードにも憲法3章の `js/` のルールを適用する。
  * `timeScale` の変更、シーンの切り替え、シーンを積む・戻す操作は、このサブフェイズで実装と `oz/ENGINE_API.md` への記載までを行い、画面での確認は Phase 01-02 へ先送りする（発注者の決定）。
  * 参考にする phaseout のファイルは次のとおり。
    * シーン: `js/scene/BaseScene.js`、`js/core/SceneManager.js`。スタック管理と切り替え後の時間スパイク対策を流用する。グリッチ遷移と `stopBGM` の呼び出しは持ち込まない。
    * レイヤー、ループ、時間: `js/render/MasterRenderer.js`。1枚の Canvas に順に描く仕組みを流用し、ループと時間を分離する。12層の固定定義と `GameState` への依存は持ち込まない。
    * 固定ティック: `js/core/physics.js` の 1000/60 の蓄積処理と5ティック上限を参考にする。
    * 時間と描画のルール: phaseout の `PROJECT_ARCHITECTURE.md` の Global Invariants 7章・8章。
  * 決定事項: `scene` と `layers` は必須とし、欠けるとエラーにする。目印の付いた部分を消すと、`js/main.js` に目印のない `new Scene()` とレイヤー1枚が残り、そのまま起動する。

### Phase 01-02: 入力とボタン
* **目的**: ポインタとキーボードの入力、および Canvas 上のボタンの当たり判定を使えるようにする。
* **実装要件**:
  * クリックまたはタップした位置が論理座標で得られ、ウィンドウの大きさを変えてもずれない。
  * ポインタの押下、移動、離す操作をシーンで受け取れる。
  * キーを押している間の状態と、押した瞬間を取得できる。短く押したキーを取りこぼさない。
  * シーンを積むと、ポインタ入力は最前面のシーンだけに届く。
  * シーンごとに登録したボタンの矩形の内側を押すと反応し、外側を押すと反応しない。
  * ボタンが入力を消費すると、そのシーンの `onPointer` には届かない。
  * シーンから外れたシーンのボタンは反応しない。
  * `oz/ENGINE_API.md` を読むだけで、入力とボタンの使い方が分かる。
  * 確認用コードで、タップとキーにより `timeScale` の変更、シーンの切り替え、シーンを積む・戻す操作を実行できる。
  * `timeScale` を小さくすると、図形が遅く動く。
  * シーンを切り替えた直後に、動きが飛ばない。
  * シーンを積むと背面のシーンの動きが止まって表示は残り、戻すと動きが再開する。
* **持ち越し事項**: Phase 01-01 から先送りした画面での確認（`timeScale` の変更、シーンの切り替え、シーンを積む・戻す）。上記の実装要件に含めた。
* **メモ**:
  * 参考にする phaseout のファイルは次のとおり。
    * 入力: `js/core/InputManager.js`。論理座標変換と優先度付き配信を流用する。押下しか扱っていないので、移動、離す、キーボードを追加する。
    * ボタン: `js/core/UIManager.js`。当たり判定を流用する。描画中の位置更新はやめて、シーンごとの登録にする。
  * ボタンの描画はエンジンに入れない（`PROJECT_ARCHITECTURE.md` 4章）。
  * 決定事項: 入力は `timeScale` に関係なく、毎フレーム1回、固定ティックの前に配る。`timeScale` が `0` の間も入力は届き、ボタンやキーで再開できる（発注者の決定。`PROJECT_ARCHITECTURE.md` 3章に反映済み）。

### Phase 01-03: アセット、サウンド、セーブ
* **目的**: 画像と音声のロード、音の再生、設定の保存を使えるようにする。
* **実装要件**:
  * 一覧に書いた画像と音声のロードが終わってから、ロードした画像を表示できる。
  * SE を再生でき、BGM をループ再生できる。
  * BGM をフェードで開始および停止でき、音量を変えられる。
  * 最初のポインタまたはキー入力の後に音が鳴り、それ以前の再生要求でエラーが出ない。
  * 保存した値が、ページを再読み込みしても残っている。
  * 保存データの版番号が異なるときは、エラーなく既定値で始まる。
  * `oz/ENGINE_API.md` を読むだけで、アセット、サウンド、セーブの使い方が分かる。
* **持ち越し事項**: なし
* **メモ**:
  * 参考にする phaseout のファイルは次のとおり。
    * サウンド: `js/render/SoundManager.js`。ロード、再生、フェードだけを抜き出す。
    * セーブ: `js/core/config.js` の単一JSONと版番号の仕組み。
  * アセットは phaseout に相当するものがない（`new Image()` が各所に分散している）ので、新規に設計する。
  * スプライトJSの読み込みは `import` で行い、Assets の対象にしない（`PROJECT_ARCHITECTURE.md` 4章）。
  * 確認用の素材を `assets/` に置く場合は、Phase 01-04 で使う素材と揃える。
  * 決定事項: `Sound` が自分で入力イベントを登録し、そのイベントの中で AudioContext を再開する。最初の入力より前の音の要求は捨てる（発注者の決定。`PROJECT_ARCHITECTURE.md` 3章に反映済み）。

### Phase 01-04: ゲームの土台
* **目的**: `D:\ozlab\_attic\proto\vernier.html` を元に、エンジンの各機能を1か所ずつ使う見本を `js/` に作り、大ゴールの完了の目安をすべて確かめる。
* **実装要件**:
  * 起動するとタイトルが表示され、自動操縦の機体がデモとして動く。
  * タップまたは Canvas 上のボタンでプレイを開始できる。ページに DOM の見出しはない。
  * プレイ中はキーで機体が旋回および加速する。
  * ポーズすると背面の表示を残して動きが止まり、解除すると再開する。
  * 1つのキーでスローと等速を切り替えられる。
  * 星、トレイル、機体、風、UI が、この順に奥から手前へ重なって表示される。
  * 機体は `assets/sprites/` のスプライトJSで描かれている。
  * 画像を1枚表示している。
  * ブースト時に SE が鳴る。
  * 最初の入力で BGM が流れ始める。
  * ミュートの設定が、ページを再読み込みしても残っている。
  * FPS を表示できる。
  * リフレッシュレートが異なる画面でも、機体の動く速さが同じである。
  * 完了の目安の4点（1章）を満たす。
* **持ち越し事項**: `js/main.js` の責務定義の2行目が目印の外にあり、見本を消すと実態と合わなくなる点を見直す。確認用コードの `trail` のコメントと `SampleLoadScene.init` の JSDoc が実際の動作と違う点は、確認用コードの置き換えで解消する。最初の入力より前の音の要求は捨てられるので、BGM は最初の入力への反応の中で `playBgm` を呼ぶ。ボタンが消費した押下はシーンの `onPointer` に届かないので、必要なら `onPress` でも呼ぶ。
* **メモ**:
  * `js/` の実装は、`oz/src/` を読めないように設定した実装AIが `oz/ENGINE_API.md` だけを見て行う。決定事項: 一時的な拒否設定で読めなくし、`js/` のタスクが終わったら設定を削除する。
  * 実装AIが詰まった箇所は、RESに不足として記録する（憲法3章）。ドキュメントやエンジンの修正は、`js/` の実装とは別のタスクで行う。
  * `js/` の構成は `PROJECT_ARCHITECTURE.md` の1章・4章に従う。`js/main.js` に `Engine.start` とレイヤー定義をまとめ、`js/scenes/` にシーン、`js/effect/` に星、トレイル、風、`js/entities/` に機体の動きを置く。カメラは `js/` 側に置く。
  * 新規プロジェクトのコピー元になるので、見本として読めるように作る。消す前提のコードには憲法3章の目印を付ける。
  * 手書きのスプライトは、憲法3章によりREQで明示された場合に限り作成できる。このサブフェイズのREQに、機体の手書きを明記する。
  * 素材は Phase 01-03 で `assets/` に置いた次のものを使う。合わなければ発注者が差し替える。
    * 画像: `assets/images/sample.png`（元は phaseout の `phaseout.png`）。
    * SE: `assets/sounds/sample_se.mp3`。
    * BGM: `assets/sounds/sample_bgm.mp3`。
  * 元のコードはフレーム単位で動いていて、144Hz だと速くなる。固定ティックに載せれば調整値はそのまま使える。
  * 決定事項: 元のコードでは、噴射口の描画が `(-18, ±12)`、トレイルの起点が `(-43, ±12)` でずれている。トレイルの起点は元のままとする（発注者の決定）。
