## 【実装要件】
`oz/` にエンジンの骨格（ループ、時間、画面、レイヤー、シーン、デバッグ表示）を作り、ルートの `index.html` を静的サーバで開くと、確認用の図形がレイヤーごとに動いて表示される状態にする。

*   **要件1: ループと時間**
    *  開発資料3章の順序で動かす。ただし入力の確定と配信（手順2と、手順3の `Input`）は Phase 01-02 で追加するので、今回は作らない。
    *  固定ティック（`tickRate`、既定 60）で `update` を呼ぶ。リフレッシュレートが異なる画面でも、動く速さが同じになる。
    *  タブを裏に回してから戻しても、図形が大きく飛ばない。1フレームの蓄積の上限は5ティック分とする。`gameTime` も同じ上限に従い、戻ったときに飛ばない。
    *  `timeScale` を小さくすると遅く動く。`0` なら `update` は呼ばれず、`draw` は続く。`timeScale` を利用側から読み書きする方法を公開APIとして用意する。
    *  `draw` に渡す `time` は、開発資料2.4章の `realDelta`・`gameTime`・`timeScale` を持つ。
*   **要件2: 画面**
    *  `Engine.start` に渡した `width` / `height` を Canvas の解像度にする（高解像度画面への対応はしない）。
    *  Canvas は、縦横比を保ったまま、ウィンドウに収まる最大の大きさで表示する。ウィンドウの大きさを変えると追従する。
    *  中央寄せと余白の黒は、`index.html` の CSS で行う。エンジンはページに要素を追加しない。
    *  スクリーン座標と論理座標の変換は Phase 01-02 の入力で初めて使うので、今回は作らない。
*   **要件3: レイヤー**
    *  利用側が `layers` に渡した名前の配列の順に、奥から手前へ描く。各レイヤーの中では、スタックの下のシーンから順に `draw(ctx, layer, time)` を呼ぶ。
    *  呼び出しごとに `ctx` の状態を `save` / `restore` で保護する。
*   **要件4: シーン**
    *  `Scene` 基底クラスは `init`・`update`・`draw`・`destroy` を持ち、中身は何もしない。`new Scene()` をそのまま「何も描かないシーン」として使える。`onPointer` は Phase 01-02 で追加するので、今回は作らない。
    *  シーンの切り替え（スタックを全部外して1つ積む）、積む、戻すを公開APIとして用意する。積むと背面のシーンは `update` だけが止まり、`draw` は続く。戻すと `update` が再開する。
    *  シーンを操作した直後に動きが飛ばない。シーン操作が起きたフレームでは残りのティックを回さず、蓄積を捨て、次のフレームの `realDelta` も蓄積に入れない。
    *  スタックが空になったときの挙動（何も呼ばれず、エラーにならない）を決めて `oz/ENGINE_API.md` に書く。
*   **要件5: デバッグ表示**
    *  `debug` が有効なら FPS を最前面に表示し、無効なら表示しない。実行中に切り替える機能は作らない。
    *  FPS の計算（状態の更新）と描画は分ける。憲法3章「ロジックと描画の分離」を守ること。
*   **要件6: 起動設定**
    *  `Engine.start` は開発資料2.2章の設定を受け取る。`canvas`・`width`・`height`・`layers`・`scene` は必須で、欠けていれば原因が分かるエラーを投げる（シーンの渡し忘れに気づけるようにする）。
*   **要件7: 確認用コード（`index.html`、`js/main.js`）**
    *  `index.html` は開発資料1章の import map を定義し、Canvas を1つ置いて `js/main.js` を読み込む。ページに DOM の見出しは置かない。
    *  `js/main.js` に、確認用の図形を動かす最小のコードを置く。`Engine.start` に渡す論理解像度は 1280×720 とする。レイヤーは3枚とし、色の違う3つの図形を各レイヤーに描く。図形は重なり合い、重なり順がレイヤーの定義どおりであると見て分かるようにする。シーン内で描く順序はレイヤーの定義順と逆に書き、順序がレイヤー定義で決まることを確かめられるようにする。
    *  図形は `update(dt)` で動かし、画面の左右を行き来する。端から端までを約4秒で動くようにして、ストップウォッチで速さを確かめられるようにする。
    *  URL の末尾に `?debug` を付けて開くと `debug` が有効になり、付けないと無効になる。
    *  確認用コードはすべて憲法3章の `ozengine sample` の目印で囲む。目印の付いた部分を消すと、目印のない「`new Scene()` とレイヤー1枚」で、真っ黒な画面のままエラーなく起動するように書く。
    *  確認用コードは Phase 01-04 で置き換える仮のものである。開発資料4章は `js/main.js` に描画処理を置くことを禁じているが、今回の確認用コードに限って例外とする（目印の中に限る）。開発資料はこの例外のために更新しない。
    *  確認用コードにも憲法3章の `js/` のルールを適用する。`requestAnimationFrame`・`addEventListener`・`getContext` を書かない。
*   **要件8: `oz/ENGINE_API.md`**
    *  読むだけでここまでの機能が使える内容にする。`index.html` の書き方、`Engine.start` の設定、シーンの作り方と操作、レイヤーの重なり方（手前のシーンの奥のレイヤーは、奥のシーンの手前のレイヤーより先に描かれること）、`time` と `timeScale` の使い方、`debug`、シーン操作を呼んでよい場所（`draw` の中では呼ばない）を書く。
    *  動きは `update(dt)` で進め、`time.gameTime` は周期的な動きに使う、という指針を書く。
    *  今回作っていない機能（入力、ボタン、アセット、サウンド、セーブ）は載せない。
*   **要件9: `oz/VERSION`**
    *  開発資料1章の構成に合わせて作り、`0.1.0` の1行だけを書く。

## 【計画書に必ず含めるべきタスクごとの作業】
AIが作成する計画書（RES）のタスクリストには、個別の実装タスクの後に、以下の作業を必ず含めること。
*   コード修正完了後、JSDocコメントの記載漏れがないことを確認する。
*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **依存の向き** : 開発資料3章の依存の向きを守る。`Scenes` は `Time` を import しない。シーン操作の時間リセットは、`GameLoop` が `Scenes` の状態を見て `Time` に伝える形にする。
*   **入口の一本化** : 利用側に公開するものは `oz/index.js` の再exportだけにする。`Time`・`Screen`・`Layers`・`GameLoop` のクラスをそのまま公開する必要があるかを検討し、公開面を最小にする。
*   **時間の受け渡し** : 時間を取得するのは `GameLoop` と `Time` だけにする。`DebugOverlay` を含む他のモジュールは引数で受け取る。
*   **先回り実装の禁止** : `Input`・`Buttons`・`Assets`・`Sound`・`Storage` のファイルや呼び出しの空枠を作らない。
*   **`js/` の実装** : `js/main.js` を実装するタスクでは `oz/src/` を読まず、`oz/ENGINE_API.md` だけを参照する（憲法3章）。そのため、`oz/ENGINE_API.md` が揃うタスクの後に置き、計画書に明記する。分からないことはRESに不足として記録する。
*   **公開APIとドキュメント** : 公開APIを追加するタスクと同じタスクで `oz/ENGINE_API.md` を更新する（憲法3章）。
*   **スコープの粒度** : タスクは1〜数ファイル単位に分ける。
