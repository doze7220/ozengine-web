## 【実装要件】
このエンジンを使うゲームから、「同じ SE を、鳴らすたびに音程を変えて鳴らしたい（連続して鳴らすときに、1回ごとに少しずつ高くしたい）」という要望が届いた。現在の `Sound.playSe(名前)` には、音程（再生速度）を指定する方法がない。`playSe` に第2引数 `{ rate }` を足す。

*   **要件1: `oz/src/Sound.js` の `playSe` に `rate` を足す**
    *  呼び方は `Sound.playSe(名前, { rate })` とする。`rate` は再生速度で、音程と長さが一緒に変わる（`1` で元の高さ。`2` で1オクターブ上になり、長さは半分）。
    *  第2引数を省いたとき、または `rate` を省いたとき（`undefined`）は、`1` として扱い、今と同じ動きにする。
    *  `rate` は `0` より大きい有限数とする。それ以外（`0` 以下、`NaN`、`Infinity`、数値以外。`null` と文字列を含む）は `RangeError` を投げ、音は鳴らさない。
    *  エラー文は、既存の `readFadeSeconds` の文面に合わせ、`` `[oz] ${apiName}: rate は0より大きい有限数で指定してください: ${String(rate)}` `` とする（`apiName` は `'Sound.playSe'`）。
    *  検証は、`readFadeSeconds` と同じ形の内部関数（公開しない。名前は `readRate`）を `readFadeSeconds` の直後に足して行う。`options` の読み方は `readFadeSeconds` と同じ（`options?.rate`）にする。
    *  `playSe` の中では、`rate` の検証を最初に行い、その次に名前の確認（`requireSound`）を行う（`playBgm` が `fadeMs` の確認 → 名前の確認の順であることに合わせる）。これにより、音を捨てる場合（読み込みに失敗した名前、最初の入力より前、ブラウザが音を止めている間）にも `rate` の検証が行われる。
    *  再生速度は、`AudioBufferSourceNode` の `playbackRate`（`source.playbackRate.value`）に設定する。`detune` は使わない。
    *  `playSe` の JSDoc を直す（第2引数の説明、既定値、`@throws {RangeError}`）。足した内部関数にも JSDoc を書く。
    *  `playBgm`・`stopBgm`・音量・AudioContext の再開の処理は変えない。BGM に `rate` は足さない。
*   **要件2: `oz/ENGINE_API.md` 21章（サウンド）を直す**
    *  章の先頭の表の `Sound.playSe(名前)` の行を、`Sound.playSe(名前, { rate })` に直し、内容に「`rate` は再生速度（既定値 `1`）」を足す。
    *  「SE」の項に、次の内容を足す。
        *  `rate` の意味：その1回の再生速度で、音程と長さが一緒に変わる。`1` で元の高さ、`2` で1オクターブ上になり長さは半分、`0.5` で1オクターブ下になり長さは2倍。
        *  既定値：第2引数を省いたとき、または `rate` を省いたときは `1`（今までと同じ鳴り方）。
        *  エラーの条件：`rate` は `0` より大きい有限数で、そうでなければ（`0` 以下、`NaN`、`Infinity`、数値以外）`RangeError` になり、音は鳴らない。
        *  半音の計算：半音単位で上げ下げするときは `rate = 2 ** (半音の数 / 12)` で計算できること。短いコードの例を1つ付ける（鳴らすたびに半音ずつ高くする例。音の名前は `'se'` のような中立の名前にし、特定のゲームの名前や用語は書かない）。
        *  重ねて鳴らす SE のそれぞれに、別の `rate` を指定できること。
    *  「ブラウザが音を止めたとき」の「名前の確認と `fadeMs` の確認は、止まっている間も行う。」に、`rate` の確認を足す。
    *  「最初の入力まで」の「名前の確認（一覧にない名前のエラー）と `fadeMs` の確認は、入力の前でも行う。」に、`rate` の確認を足す。
    *  「読み込みに失敗した名前」に、読み込みに失敗した名前でも `rate`（`playSe`）と `fadeMs`（`playBgm`）の確認は行い、不正な値なら `RangeError` になることを足す（`fadeMs` は今のコードですでにそう動いている。`playBgm` のコードは変えない）。
    *  21章の上に挙げた箇所以外と、ほかの章は変えない。
    *  `oz/src/` を読まなくても、利用側が `rate` を使える内容にする（憲法3章「公開APIとドキュメントの同時更新」）。
*   **要件3: `oz/FINGERPRINTS.txt` を作り直す**
    *  要件1・要件2の変更がすべて済んだあとに、【関連する責務】の「作り直しのコマンド」を Git Bash で、リポジトリのルートで実行して作り直す。一覧を手で編集しない。
*   **要件4: 検証コマンドを実行する**
    *  `node --input-type=module --check < oz/src/Sound.js` が通ることを確かめる。
    *  リポジトリのルートで `node --test`（引数なし）を実行し、結果が `fail 0` であることを確かめる。
*   **要件5: 自動テストは足さない**
    *  `test/` にファイルを足さず、既存のテストも変えない。
    *  理由（RES に書く）：`Sound` は読み込み時に `window` へイベントを登録するため、自動テストの対象外と決められている（【関連する責務】の「自動テストの規則」）。対象にするには、偽の `window` を置いてから動的 import するか、登録の時期を見直すかを先に決める必要があり、その判断は保留中で、本 Interrupt の範囲に入らない。今回の動作は、発注者がブラウザで確かめる。

## 【関連する責務】
* `Sound`（`oz/src/Sound.js`） : AudioContext の管理（最初の入力と、ブラウザが止めたあとの入力での再開を含む）、音声のデコードと名前での保持、SEとBGMの再生、フェード、音量を担う。BGMの状態遷移（ゲーム側の判定）とファイルの読み込みは持たない。他のエンジンモジュールに依存しない。公開するのは `Sound` オブジェクトと、`Assets` 専用の `decodeSound`・`storeSound` である。
* `Sound.playSe` の今の動き : 名前の確認（一覧にない名前、ロードの終わっていない名前は `Error`）を最初に行う。読み込みに失敗した名前、最初の入力より前、ブラウザが音を止めている間は、エラーにせず何もしない。
* `Sound.playBgm`・`Sound.stopBgm` の `fadeMs` : `readFadeSeconds` で検証する。`0` 以上の有限数でなければ `RangeError`。`playBgm` は `fadeMs` の確認 → 名前の確認の順に行う。
* 憲法3章「時間の受け渡し」 : `Sound` は音の予定時刻にだけ `AudioContext.currentTime` を使ってよい。本作業では時刻を新しく使わない。
* 憲法3章「公開APIとドキュメントの同時更新」 : 公開APIを追加・変更するタスクでは、同じタスク内で `oz/ENGINE_API.md` を更新する。`oz/src/` を読まなくても利用側を実装できる内容を保つ。
* 憲法3章「先回り実装の禁止」 : REQで求められていない機能を実装しない。
* `oz/index.js` : 公開APIの入口。再export だけを書く。`Sound` はすでに公開されており、本作業では変更しない。
* 指紋一覧（`oz/FINGERPRINTS.txt`）の規則 :
    * 形式は、1行に1ファイル、`<SHA-256 の16進64文字><空白2つ><oz/ からの相対パス>`、パスのバイト順、LF で終わる。一覧ファイル自身は含めない。指紋は中身から CR を取り除いてから求める。
    * `oz/` の中のファイル（`ENGINE_API.md` だけの変更を含む）を変更するタスクの最後に作り直し、`node --test` が `fail 0` であることを確かめる。一覧を手で編集しない。一覧が古いと `test/FINGERPRINTS.test.js` が失敗する。
    * 作り直しのコマンド（Git Bash、リポジトリのルートで実行）:

      ```bash
      (cd oz && find . -type f ! -path ./FINGERPRINTS.txt | sed 's|^\./||' | LC_ALL=C sort | while IFS= read -r f; do printf '%s  %s\n' "$(tr -d '\r' < "$f" | sha256sum | cut -c1-64)" "$f"; done > FINGERPRINTS.txt)
      ```

* 自動テストの規則 : `test/` のテストは `node --test`（引数なし）で実行する。`Sound` はテストしないモジュールである（読み込み時に `window` を使うため、対象にするときに登録の時期を検討する、と決められている）。
