## 【実装要件】
描く処理を前もって別の Canvas に焼き付けておき、毎フレームはその画像を貼るだけにする仕組み（以下「キャンバスキャッシュ」）をエンジンに入れる。焼き付ける対象は、スプライトJSに限らず、`draw(ctx)` で描けるもの（図形、文字を含む）すべてとする。焼き付けた結果は `draw(ctx)` を持つオブジェクト（以下「焼き付け」）として返し、呼ぶ側はスプライトJSと同じ書き方のまま差し替えられるようにする。多数のスプライトを同時に描くゲームで、毎フレームのベクターの描画の負荷を減らすためのものである。

本作業はエンジン（`oz/`）だけを変える。ゲームの土台（`js/`・`assets/`・`index.html`）は変えない（土台を焼き付けで描くのは、本作業の後の別の作業で行う）。

*   **要件1: 公開API（決定事項）**
    *  `oz/index.js` から、新しい公開オブジェクト `CanvasCache` を再exportする。処理は新しいモジュール `oz/src/CanvasCache.js` に置く（開発資料4章で `Assets` の「キャッシュ生成」は責務違反のため、`Assets` には入れない）。
    *  `CanvasCache.create(source, options)` で焼き付けを作り、焼き付けのオブジェクトを返す。
        *  `source`（必須）: 描く処理。`draw(ctx)` を持つオブジェクト（スプライトJSの既定の export など）、または `ctx` を受け取る関数。エンジンは、焼き付けるときにこれを呼ぶだけで、絵の中身を知らない。
        *  `options.bounds`（必須）: 焼き付ける範囲 `{ minX, minY, maxX, maxY }`。`source` の座標（拡大前の px）での最小・最大で、OZ Vector Editor の書き出しにある `bounds` と同じ形である。スプライトJSなら `sprite.bounds` をそのまま渡せる。`bounds` を持たない描く処理（手書きのスプライト、図形、文字）では、呼ぶ側が同じ形で範囲を書く。
        *  `options.scale`（任意、既定 `1`）: 表示する倍率（論理座標での拡大率）。
    *  焼き付けのオブジェクトは次の3つを持つ。
        *  `draw(ctx)`: 焼き付けた絵を描く（要件2）。
        *  `refresh()`: 今の `source` の見た目で焼き直す（要件4）。
        *  `dispose()`: 焼き付けを手放す（要件5）。
    *  `options` の項目名・メソッド名は上記のとおりとする。上記以外の公開API（倍率の取得など）は作らない。

*   **要件2: 描かれる位置と大きさ**
    *  焼き付けの `draw(ctx)` を呼ぶと、「`ctx.save()` → `ctx.scale(scale, scale)` → `source` を描く → `ctx.restore()`」と直接描いたときと、同じ位置・同じ大きさに絵が出る。呼ぶ側は `scale` を自分で掛けない。
    *  呼ぶ側は、スプライトJSの `draw(ctx)` と同じく、`ctx` の変換（`translate`・`rotate`・`scale`）を掛けてから `draw(ctx)` を呼べる。焼き付けの `draw(ctx)` は `ctx` の状態を元に戻して終わる。
    *  呼ぶ側が変換で拡大・縮小・回転を掛けていないとき、焼き付けた画像の1画素が画面の1画素に対応するように描く（直接描いたときよりぼやけさせない）。回転して描いたときにギザギザが目立たないよう、画像の補間は切らない。
    *  `bounds` の外側の絵は切れる。ただし、`bounds` のちょうど縁に接する線のにじみ（アンチエイリアス）が欠けないよう、エンジンが外側にわずかな余白を取る（量は計画で決める）。OZ Vector Editor の `bounds` は線の太さの半分を外側に含む。手で範囲を書くときは、呼ぶ側が線の太さを含める。

*   **要件3: 焼き付ける解像度と自動の焼き直し**
    *  焼き付ける解像度（画像の画素数）は、エンジンが「`scale` × 画面の実際の画素の倍率」で決める。ここでの「画面の実際の画素の倍率」は、論理座標の1単位が Canvas の何画素に当たるか（Canvas の画素数 ÷ 論理解像度）である。開発資料3章「Canvas の画素数」のとおり、これはウィンドウの表示サイズと `devicePixelRatio`（上限 2）で決まり、ウィンドウの大きさや画面の向きで変わる。
    *  この倍率は利用側に公開しない（開発資料3章）。呼ぶ側は画面の画素の倍率を知らなくてよい。
    *  `CanvasCache` がこの倍率とその変化を知る方法は、計画で決める。開発資料3章の依存の向きを守り、`Screen` などのエンジンモジュールが `CanvasCache` を import しない形にする（例: `Engine` が起動時に倍率の求め方を `CanvasCache` へ渡す）。`CanvasCache` は他のエンジンモジュールを import しない。
    *  ウィンドウの大きさや画面の向きが変わって倍率が変わったら、エンジンが手放していないすべての焼き付けを自動で焼き直す。焼き直したあとも、呼ぶ側は同じオブジェクトをそのまま使える。焼き直す時期（倍率が変わったとき、次に描くとき、など）は計画で決める。倍率が変わった後に、古い解像度の絵が描かれ続けないこと。
    *  焼き付けた画像を、`scale` と大きく違う倍率（呼ぶ側の `ctx.scale` など）で描くと、拡大ではぼやけ、縮小では細い線が淡くなる。これは直接描いたときと同じ性質で、本作業では対処しない（要件8で注意として書く）。

*   **要件4: 明示の焼き直し**
    *  `refresh()` を呼ぶと、その時点の `source` を呼び直して焼き付ける。色や演出を切り替えたあとに、新しい見た目で描くために使う。焼き直したあとも同じオブジェクトをそのまま使える。

*   **要件5: 手放す（決定事項）**
    *  `dispose()` を呼ぶと、その焼き付けは自動の焼き直しの対象から外れ、焼き付けた画像を保持しなくなる。
    *  手放したあとに `draw(ctx)`・`refresh()` を呼ぶとエラーにする（使い回しの間違いにすぐ気づけるようにするため）。エラーの形は要件7と同じ。
    *  `dispose()` を2回以上呼んだときは何もしない。

*   **要件6: 作れる時期（決定事項）**
    *  `CanvasCache.create` は `Engine.start` の後に使う。前に呼ぶとエラー（`[oz] CanvasCache.create: Engine.start の前には使えません`。ほかの API と同じ文面）。
    *  焼き付けは `create` の中ですぐに行う（最初に描くフレームで止まらないようにするため）。シーンの `init` で作り、`destroy` で手放す使い方を想定する。

*   **要件7: 引数が正しくないとき**
    *  ほかの API と同じ形のエラー（`Error`、先頭が `[oz] CanvasCache.create:`、項目名を含む）にする。少なくとも次をエラーにする。
        *  `source` が無い、または `draw` を持つオブジェクトでも関数でもない。
        *  `options` が無い。`bounds` が無い、または `null`（OZ Vector Editor は図形が0個のとき `bounds` を `null` にする）。
        *  `bounds` の4つの値のどれかが有限の数値でない。範囲が空（`maxX <= minX` または `maxY <= minY`）。
        *  `scale` が正の有限数でない（0 以下を含む）。
    *  手放したあとの `draw`・`refresh` のエラー（要件5）も、先頭を `[oz] ` で始め、どの操作かが分かる文面にする（文面は計画で決める）。
    *  焼き付けの途中で `source` が例外を投げたときの扱い（そのまま投げる、など）と、焼き付けに使う Canvas の `ctx` の状態をどう保つかは計画で決め、要件8で書く。
    *  ブラウザの Canvas の大きさ・メモリの上限（特に iPhone の Safari）を超える焼き付けの扱いは計画で検討し、対処しない場合はRESの懸念事項に挙げる。

*   **要件8: `oz/ENGINE_API.md`**
    *  キャンバスキャッシュの章を新しく設ける（章の番号・置き場所は計画で決める）。`oz/src/` を読まなくても利用側が使える内容とし、少なくとも次を書く: 何のためのものか、`CanvasCache.create` の引数（`source`・`bounds`・`scale`）、描かれる位置と大きさ（要件2）、使い方の例（シーンの `init` で作り、`draw` で描き、`destroy` で手放す。スプライトJSの `bounds` を渡す例と、手で範囲を書く例）、自動の焼き直し、`refresh()`、`dispose()`、作れる時期、エラー。
    *  注意として次を書く: `scale` と大きく違う倍率で描くと、拡大ではぼやけ、縮小では細い線が淡くなること（大きさを変えて描くなら、その大きさの `scale` で別に焼き付ける）。`bounds` の外は切れること。時間で変わる絵（アニメーション）は焼き付けの対象にしないこと（焼き付けた時点の見た目のまま描かれる）。色違いが要るときは、色ごとに別の描く処理を渡して焼き付けること。見た目を変えたら `refresh()` を呼ぶこと。
    *  1章の「使えるもの」の一覧に `CanvasCache` を加える。
    *  23章「スプライトJS」の「`draw` 以外のキー（…）は、エンジンも利用側も読まない」を、「エディタの書き出しの `bounds` は、キャンバスキャッシュの範囲として読んでよい（`null` のことがある）。それ以外のキーは読まない」という趣旨に改める。

*   **要件9: 自動テスト**
    *  Node.js には Canvas が無い。Canvas を使わずに確かめられる部分（引数の検証、焼き付ける画像の画素数と余白の計算など）を、`test/CanvasCache.test.js` で確かめる。そのために、`oz/src/CanvasCache.js` の中の Canvas を使わない関数を名前付きで export してよい（`oz/src/VirtualPad.js` の `validatePadLayout` と同じ扱い。`oz/index.js` からは再exportしない）。
    *  開発資料4章「自動テスト（`test/`）の規則」に従う。特に、`window` 以外のグローバルに代入しない、テストのためにソースを変えない、`oz/index.js` を import しない。テストできない部分（Canvas への焼き付け、自動の焼き直し）は、テストしないことを計画に書き、要件10の確認の範囲に入れる。

*   **要件10: テストプレイ（ブラウザのコンソールでの確認。決定事項）**

    *  発注者が、土台を開いたブラウザのコンソールに貼り付けて確かめられる手順を、RES の目視確認推奨箇所に書く。貼り付けるコードと、期待する結果（表示される値やエラーの文面）を対にして書く。コードを読まない発注者が、貼り付けて結果を見比べるだけで済む形にする。少なくとも次を確かめられるようにする。

        *  作った焼き付けを、コンソールで作った確認用の Canvas（ページに追加しなくてよい）に描いて、例外が出ないこと。
        *  要件7のエラー（`bounds` が `null`、範囲が空、`scale` が 0 など）と、手放したあとに `draw` を呼んだときのエラーが、期待する文面で出ること。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : 憲法3章の絶対禁止事項に反する設計をしてはならない。特に、エンジンから `js/`・`assets/` を参照しない、エンジンにゲーム固有の値を固定値で書かない、公開APIは `oz/index.js` からのみ export する、独自に時間を取得しない（`performance.now()` などを使わない）、`window` にプロパティを足さない（焼き付けの一覧などの状態はモジュールの中に閉じる）、`ctx` の状態を外へ漏らさない。
*   **焼き付け先の Canvas（決定事項）** : 焼き付け先には、ページに追加しない Canvas（`document.createElement('canvas')` で作ってページに追加しないもの、または `OffscreenCanvas`。どちらにするかは計画で決める）を使う。ページに追加しない Canvas を作ることは、憲法3章「エンジンのDOM操作の制限」の「ページのDOMを操作」に当たらないものとして扱う。ページに要素を追加してはならない。
*   **責務の分離** : 焼き付け・焼き直し・手放しは `oz/src/CanvasCache.js` に置く。`Engine` に置いてよいのは、起動時の `CanvasCache` への受け渡し（倍率の求め方など）だけで、焼き付けの処理を `Engine` に書かない。`Screen` の責務（表示サイズと画素数の調整）を `CanvasCache` に持ち込まない。責務の範囲が変わるモジュールは、ファイル先頭の責務定義と開発資料4章の責務表の更新予定に挙げる。
*   **変更してよいファイル** : `oz/src/CanvasCache.js`（新規作成）、`oz/src/Engine.js`（`CanvasCache` への受け渡しのみ）、`oz/index.js`（`CanvasCache` の再exportのみ）、`oz/ENGINE_API.md`、`oz/FINGERPRINTS.txt`（作り直しのみ）、`test/CanvasCache.test.js`（新規作成）、`PROJECT_ARCHITECTURE.md`（最終の固定タスクのみ）、作業計画書（本RES）に限る。`oz/src/Screen.js` は、倍率の変化を知らせるために変更が避けられない場合に限り変更してよく、その場合は理由を計画に書き、`test/Screen.test.js` が通ることを確かめる（`test/Screen.test.js` 自体の変更が要る場合は、計画に書く前に疑問点として報告する）。`js/`・`assets/`・`index.html`・`oz/VERSION`・`PROJECT_CONSTITUTION.md`・`CLAUDE.md`・`README.md`・既存の `test/*.test.js`・`_doc/` は変更しない。
*   **外部依存の禁止** : 外部ライブラリ・npm パッケージ・`package.json`・ビルドを使わない。
*   **参考にしてよい実装** : `D:\ozlab\phaseout\js\render\SpriteCacheManager.js`（別のゲームのキャッシュの実装）を読んでよい。参考のみとし、変更しない。ゲーム固有の中身（宝石・エフェクト・設定値など）や、画素の加工は持ち込まない。
