## 【実装要件】
いまの FPS の表示は、起動設定の `debug` が真のときだけ左上に出て、実行中には切り替えられない（`oz/ENGINE_API.md` 14章）。FPS の値をゲームが読む口もない。これを、実行中に表示を出し入れでき、表示の位置を四隅から選べ、ゲームが FPS の値を読めるようにする。ゲーム（バトリティア）が、多数の兵を描いたときの重さを調整パネルで測るために求めている（FPS を出す・消す、パネルに FPS の値を出す、パネルと重ならない位置に表示を動かす）。

*   **要件1: 表示の出し入れ（決定事項）**
    *  `Engine.fpsVisible` を読み書きできるようにする（`Engine.timeScale` と同じく、`Engine.start` の後から使えるプロパティ）。真なら FPS を最前面に表示し、偽なら表示しない。代入はその場で（次に描くフレームから）効く。
    *  起動設定の `debug` は、`Engine.fpsVisible` の起動時の値だけを決める意味にする（真なら表示した状態で始まる。既定は偽）。`debug: true` で起動したときの見た目（左上に `FPS: 60` のような表示）は、これまでと変えない。`debug` の真偽の解釈（今の `Boolean(...)`）も変えない。`debug` に FPS の表示以外の意味は持たせない。
    *  FPS の計算は、表示の有無と `debug` の有無にかかわらず、起動したときから常に行う（要件2で、表示を消している間も値を読めるようにするため）。

*   **要件2: FPS の値を読む口（決定事項）**
    *  `Engine.fps` で FPS の値を読めるようにする（読み取り専用。`Engine.start` の後から使える）。値は今の表示と同じ計算（約1秒ごとに、その間のフレーム数を経過時間で割って四捨五入した整数）で、表示している文字と同じ値になる。
    *  最初の計算が終わるまで（起動から約1秒）は `null` を返す（今の表示が `--` を出している間に当たる）。
    *  表示を消している間も値は更新され、読める。
    *  `Engine.fps` に代入したときの扱い（エラーにするか）は、既存の読み取り専用の値の扱いに合わせて計画で決め、`oz/ENGINE_API.md` に書く。

*   **要件3: 表示の位置（決定事項）**
    *  `Engine.fpsPosition` で、表示の位置を画面の四隅から選べるようにする（読み書き、`Engine.start` の後から使える）。値は `'top-left'`（左上）・`'top-right'`（右上）・`'bottom-left'`（左下）・`'bottom-right'`（右下）の4つで、既定は `'top-left'`。代入はその場で効く。
    *  `'top-left'` の見た目（文字の大きさ・色・縁取り、隅からの距離）は今と同じにする。ほかの3つの隅も、同じ距離だけ隅から離し、文字が画面の外にはみ出さないようにする（右の隅は右寄せ、下の隅は下寄せで描く）。表示する文字の長さが `FPS: --` と `FPS: 60` などで変わっても、隅からの距離は変わらない。
    *  位置は論理解像度（起動設定の `width`・`height`）に対して決める。ウィンドウの大きさや画素の倍率が変わっても、同じ隅に付いたままにする。
    *  位置は起動設定では指定しない（`Engine.start` の設定項目は増やさない）。

*   **要件4: 引数が正しくないとき**
    *  3つとも、`Engine.start` の前に使うと、ほかの API と同じ形のエラー（`[oz] Engine.fpsVisible: Engine.start の前には使えません` のように、先頭に `[oz]` と API 名）になる。
    *  `Engine.fpsVisible` に真偽値以外を代入するとエラーになる（`debug` の `Boolean(...)` の解釈とは違い、実行中の代入は型を確かめる）。`Engine.fpsPosition` に4つ以外の値を代入するとエラーになる。エラーの種類（`Error`・`TypeError`・`RangeError`）とメッセージは、既存の API（`Engine.timeScale` の `RangeError` など）の扱いに合わせて計画で決め、`oz/ENGINE_API.md` に書く。エラーになったときは、表示の有無・位置は変わらない。

*   **要件5: 資料**
    *  `oz/ENGINE_API.md` の 14章（`debug`）を、FPS の表示の章として書き直す（`debug` の意味、`Engine.fpsVisible`・`Engine.fps`・`Engine.fpsPosition` の使い方、値が `null` の間、エラー、使い方の例）。3章の起動設定の表の `debug` の行、1章の `Engine` でできることの一覧も、合わせて直す。章の番号は変えない（ほかの資料や連絡票が章の番号で参照しているため）。
    *  `PROJECT_ARCHITECTURE.md` の 2.2章（`debug` の内容）、3章（処理フローの手順5「`debug` が有効なら」と、`Engine` が `DebugOverlay` を作る条件）、4章の `Engine`・`DebugOverlay` の責務と、自動テストの対象（要件7）に影響が出るので、『開発資料の更新予定』に挙げる。
    *  新規プロジェクトの手順書（`_doc/newgame/` の `NEW_GAME_GUIDE.md`・`GAME_RULES.md`・`settings.example.json`）を読み、今回の変更（`debug` の意味、土台のメニューの項目が増えたこと。特に `NEW_GAME_GUIDE.md` 6章の、土台の見本を消す手順）で直す必要がある箇所が残っていないかを確かめる。直す必要があれば直す。直す必要が無ければ変えず、確かめた結果（どの節を見て、なぜ直さなくてよいか）を RES に書く。
    *  `oz/` の中のファイルを変更するタスクでは、最後に指紋一覧 `oz/FINGERPRINTS.txt` を作り直し、`node --test` が `fail 0` であることを確かめる（開発資料4章「指紋一覧の規則」）。

*   **要件6: ゲームの土台で確かめられるようにする（決定事項）**
    *  プレイ中のメニュー（今の「閉じる」「スロー」「ミュート」「タイトルに戻る」の並び）に、FPS の表示の項目を足す。選ぶたびに「FPS: OFF」→「FPS: 左上」→「FPS: 右上」→「FPS: 右下」→「FPS: 左下」→「FPS: OFF」…の順に切り替わり、項目の文字が今の状態を表す。足す位置は「ミュート」の下（「タイトルに戻る」の上）とする。
    *  PC では、キー `F`（`KeyF`）でも同じ順に切り替わる。メニューを開いているときは項目のキーとして、メニューを開いていないプレイ中は、今のスロー（`S`）と同じくプレイの画面のキーとして効く。
    *  項目の文字は、今の表示の状態（`Engine.fpsVisible` と `Engine.fpsPosition`）を描くたびに読んで決める（ほかの項目の「スロー: ON」と同じ作り）。ほかの場所（`?debug` での起動など）で表示の状態が変わっていても、正しい文字が出る。表示を消しても（OFF）、`Engine.fpsPosition` の値は変えない。OFF の次は、残っている位置にかかわらず「左上」にする。
    *  切り替えの状態は保存しない（次に起動したときは、`?debug` の有無で決まる起動時の状態に戻る）。今の `js/main.js` の `?debug` の扱いは変えない。
    *  この項目はテストプレイの後も土台に残す（消さない）。切り替えの処理は、シーンのファイルに詰め込まず、今の `js/scenes/slow.js`（スローの切り替え）のように分けて置く。
    *  メニューの項目が5つになっても、画面（1280×720）に収まり、項目どうしが重ならないことを確かめる（今のメニューの項目の高さと間隔のままで収まる見込み。収まらない場合は計画の前に疑問点として報告する）。
    *  `js/` を実装するタスクでは、`oz/src/` を読まず `oz/ENGINE_API.md` だけを参照する（憲法3章）。要件5で書き直した 14章で分からないことがあれば、RES に不足として記録し、14章を直す。そのため、土台を変えるタスクは、`oz/ENGINE_API.md` を書き直すタスクより後に置く。

*   **要件7: 自動テスト**
    *  今は `DebugOverlay` を自動テストの対象にしていない（開発資料4章「自動テスト（`test/`）の規則」）。今回、Canvas を使わない部分（FPS の値の計算と、最初の計算までの `null`、位置の値の検証を `DebugOverlay` に置く場合はその検証）を、`test/DebugOverlay.test.js` で自動テストの対象に加える。描画（`draw`）と `Engine` はテストしない。開発資料4章の規則（`oz/src/` から直接 import する、テストのためにソースを変えない、など）に従う。
    *  テストにするために `DebugOverlay` の外への見せ方を変える必要がある場合は、公開されたものだけで確かめられる形を計画で決める（テストのためだけの口を足さない）。

*   **要件8: テストプレイで確かめること**
    *  次を、発注者が PC とスマートフォン（GitHub Pages で公開したページ）で確かめられるように、RES の目視確認推奨箇所に、操作と期待する結果の形で書く。
        *  `?debug` を付けて開くと、これまでどおり左上に FPS が出る。付けずに開くと出ない。
        *  プレイ中のメニューの「FPS」の項目（PC は `F` キーでも）で、OFF・左上・右上・右下・左下が順に切り替わり、項目の文字と画面の表示が合っている。4つの隅とも、文字が画面の外にはみ出さず、隅からの距離がそろっている。
        *  表示を出したり消したりしても、ゲームの動き（機体、スロー、ミュート、タイトルへの戻り）が変わらない。メニューを閉じても、タイトルに戻っても、表示の状態は保たれる。
        *  PC でウィンドウの大きさを変えたとき、スマートフォンで画面の向きを変えたときに、表示が選んだ隅に付いたままになる。
    *  FPS の値をゲームが読めること（`Engine.fps`）と、正しくない値を代入したときのエラーは、土台の画面では確かめられない。PC のブラウザの開発者ツールのコンソールで確かめる手順（例: `const { Engine } = await import('./oz/index.js');` のあとに `Engine.fps`、`Engine.fpsPosition = 'center'` など。読み込むパスは公開したページのパスに合わせる）を、目視確認推奨箇所に書く。

*   **要件9: 公開先**
    *  テストプレイは、本リポジトリを GitHub Pages で公開したページ（`/ozengine-web/` の下）で行う。コードの中のパスは `/` から始めない（相対パスにする）。
