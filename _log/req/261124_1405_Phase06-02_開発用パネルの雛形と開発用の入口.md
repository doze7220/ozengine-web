## 【実装要件】
今の土台の開発用パネル（`js/scenes/devPanel.js`）は見本なので、新規プロジェクトで見本を消すと無くなる。また、開発用の入口（FPS の表示のキー `F`、スローのキー `S`、メニューの項目「開発用パネル」）は、開発モードかどうかにかかわらず使える。これを、どのゲームでも使う最小の開発用パネル（FPS と速度）を、見本を消した後も `js/` に残る雛形として置き、土台の開発用の入口を開発モード（`Engine.debug` が `true`。`oz/ENGINE_API.md` 3章「開発モード」）のときだけ使えるようにする。

*   **要件1: 開発用パネルの雛形（決定事項）**
    *  雛形を `js/scenes/` に、`ozengine sample` の目印を付けずに置く（ファイルは1つ。今の `devPanel.js` を雛形に変える見込み。名前は計画で決める）。
    *  標準の見た目の窓で、今と同じ大きさ（600×600）・同じタイトル「開発用パネル」とし、`js/scenes/WindowScene.js` の `openWindow` で開く。タイトル、閉じるボタン、窓の外の押下で閉じることは今と同じ。
    *  タブの列に「基本」のタブが1つある。「基本」の中は縦にスクロールする領域で、上から次の順に並ぶ。項目はこれより増やさない。

       | 順 | 部品 | 内容 |
       | --- | --- | --- |
       | 1 | チェックボックス「FPS を表示する」 | `Engine.fpsVisible` の読み書き |
       | 2 | 表示「表示の位置」 | 今の位置の文字（左上・右上・右下・左下） |
       | 3 | 選択肢の列 | 左上・右上・右下・左下（`Engine.fpsPosition` の読み書き） |
       | 4 | 表示「FPS」 | `Engine.fps` の値（`null` のときは `--`） |
       | 5 | 表示「速度」 | 今の `Engine.timeScale`（例 `×0.25`。停止は `×0`） |
       | 6 | 選択肢の列 | 停止・×0.25・×0.5・×1・×2（`Engine.timeScale` の `0`・`0.25`・`0.5`・`1`・`2`。読み書き） |

    *  `Engine.timeScale` が一覧に無い値のときは、どの選択肢も選ばれていない状態になり、「速度」の表示には今の値が出る。
    *  窓を開いている間は後ろの画面の更新が止まるので、速度の変更が画面の動きに表れるのは窓を閉じた後である。停止を選んで閉じても、入力は届き、パネルを開き直して戻せる。
    *  パネルで選んだ状態は保存しない。
    *  雛形は、見本を消した後も残り、見本のコードがなくても動く（目印の付いたコードを import しない）。どこからも使わなければ、起動に影響しない。

*   **要件2: 呼ぶ側の足し方（決定事項）**
    *  呼ぶ側は、雛形のファイルを書き換えずに、次の2つを足せる。どちらも省略できる。
        *  **自分の部品:** 「基本」のスクロールする領域の、雛形の部品の下に続けて足す。呼ぶ側の関数に、領域のオブジェクトと、部品を置き始める位置と幅を渡す形とする。
        *  **自分のタブ:** 「基本」の右に並ぶタブとして足す。1つのタブは `{ label, build }` とし、`build` に、そのタブのオブジェクト（`addTabs` の戻り値の要素）を第1引数で、部品を置ける範囲（タブの列の下の矩形）を第2引数で渡す形とする。
    *  開く関数は、窓を描くレイヤー名を呼ぶ側から受け取る（雛形にレイヤー名を固定で書かない）。引数の名前と形は計画で決める。
    *  足し方（例を含む）と、次の注意を、雛形のファイルの中のコメントに書く。
        *  ヒットストップなどで `Engine.timeScale` を自分で変えるゲームでは、パネルで選んだ速度がゲームの書き込みで上書きされる。雛形はこれを解決しない。
        *  後ろの画面のパッドの配置が違うときの扱いは、`WindowScene.js` の説明に従う。

*   **要件3: 開発モードでないとき（決定事項）**
    *  開発モードでなければ、雛形の開く関数を呼んでもパネルは開かず、何も起きない（エラーにもならない）。
    *  開発モードかどうかを見るのは `Engine.debug` だけとする（URL を読むのは `js/main.js` だけ）。

*   **要件4: 土台の開発用パネルと速度の文字（決定事項）**
    *  土台の開発用パネルは、雛形に土台の項目を足したものにする。土台の項目は、目印を付けた別のファイルに置く（見本を消すと消える）。
        *  「基本」の下に続く部品: ボタン「等速に戻す」（`Engine.timeScale` を `1` にする。今の「時間」のタブのボタンと同じ働き）。
        *  タブ「情報」: 今の「情報」の表示と同じ（FPS、FPS の表示、timeScale、ミュート、BGM の音量、効果音の音量、画面の大きさ）。「スロー」の ON/OFF の行だけは、2倍や停止が入ると合わなくなるので無くす。
    *  今のパネルの「スロー」のチェックボックスは、速度の選択肢の列に置き換わる（×0.25 と ×1）。
    *  プレイ画面の右上に出る「スロー」の文字は、等速（`1`）でないときに、今の速度を「速度 ×0.25」のように出す表示に変える（停止は「速度 ×0」、2倍は「速度 ×2」）。位置・大きさ・色は今と同じ。等速のときは出さない。
    *  キー `S` は、等速なら ×0.25 に、等速でなければ等速に切り替える（今と同じ）。メニューの「タイトルに戻る」で等速に戻すことも、今と同じ。
    *  キー `F` の切り替えの順（OFF → 左上 → 右上 → 右下 → 左下 → OFF）は、今と同じ。
    *  位置の選択肢と位置の文字のように、雛形と土台の両方で使うものは、雛形の側に置いて土台が読む（同じ一覧を2か所に書かない）。

*   **要件5: 土台の開発用の入口（決定事項）**
    *  次の3つは、開発モードのときだけ使える。開発モードでないときは、キーを押しても何も起きず、メニューに項目が出ない（空きも作らず、残りの項目が中央に並ぶ）。
        *  FPS の表示のキー `F`、スローのキー `S`、メニューの項目「開発用パネル」。
    *  画面に操作の案内の文字がある場合は、使えないキーを出さない（今の土台に案内の文字が無ければ、無いことを RES に書く）。
    *  メニューを開くキー `P` と画面のボタン、メニューのほかの項目（閉じる・設定・タイトルに戻る）、設定画面、ミュートのキー `M`、旋回・ブースト・パッドは、開発モードかどうかにかかわらず、これまでどおり使える。
    *  PC ではキーボードとマウスで（`P` → 項目をクリック）、スマートフォンでは指だけで（画面のボタン → 項目）、開発用パネルを開き、すべての部品を操作できる。

*   **要件6: 見本を消した後の確認**
    *  本リポジトリの外の一時フォルダに、`index.html`・`oz/`・`js/`・`assets/` の写しを作り、`_doc/newgame/NEW_GAME_GUIDE.md` 6-2 のコマンドをその写しで実行して、次を確かめる。確かめた結果を RES に書き、写しは残さない。
        *  雛形のファイルが残り、残る `.js` のファイルの名前と数（今は6ファイル。雛形が加わり7ファイルになる見込み）。
        *  残る `.js` に、目印、消えたファイルへの import、未定義の名前が残っていない（構文チェックを含む）。`js/main.js` から雛形が読み込まれない。
        *  6-3 の手順で消える・残る素材が、今の手順書の記述と同じである。
    *  本リポジトリの土台の見本は消さない。
    *  手順書（`_doc/newgame/`）は変えない。手順書のうち、この作業で実際と合わなくなる記述（6-2 の補足の残るファイルの一覧、7-4 の見本の説明と「使わないゲームでは」の4つの `.js` など）を、節と内容の形で RES の懸念事項に挙げる。

*   **要件7: 資料**
    *  `PROJECT_ARCHITECTURE.md` の 4章の `js/scenes/` の責務（雛形、土台の項目のファイル、`fps.js`・`slow.js`・`playMenu.js`・`uiText.js` の変わった責務、目印の付いていないファイルの列挙、書いたら責務違反になることの欄）に影響が出るので、『開発資料の更新予定』に挙げる。
    *  `oz/` は変えない（`oz/ENGINE_API.md`・`oz/FINGERPRINTS.txt` を含む）。`oz/ENGINE_API.md` だけで分からないことがあれば、RES に不足として記録する。

*   **要件8: テストプレイで確かめること**
    *  次を、発注者が PC とスマートフォン（GitHub Pages で公開したページ）で確かめられるように、RES の目視確認推奨箇所に、操作と期待する結果の形で書く。
        *  `?debug` なしと `?debug=0` で開く: `F`・`S` を押しても何も起きない。メニューの項目が「閉じる」「設定」「タイトルに戻る」の3つで、中央に並ぶ。`P`・画面のボタン・設定画面・ミュート・機体の操作は今までどおり。
        *  `?debug` で開く: FPS が出て、`F`・`S`・メニューの項目「開発用パネル」が使える。パネルの「基本」「情報」のすべての部品が、PC はマウスで、スマートフォンは指だけで操作できる（スクロールを含む）。
        *  速度の5つの選択肢を選んで閉じると、機体の動きがそのとおりになる（停止では止まり、パネルを開き直して戻せる）。右上の「速度 ×…」の文字が合っている。`S` と「等速に戻す」で等速に戻る。
        *  PC で `S`・`F` を押した後にパネルを開くと、パネルの表示が今の状態に合っている。
    *  以前のテストプレイで1回だけ、`?debug` で開いた最初のときに FPS が出ないことがあった（原因は特定できておらず、再現していない）。「`?debug` で開いて FPS と開発用の入口が出る」ことを確認の項目に入れ、出なかったときは、そのときの URL と、コンソールでの `const { Engine } = await import('oz');` のあとの `Engine.debug`・`Engine.fpsVisible` の値を控えてもらうよう書く。

## 【計画書に必ず含めるべきタスクごとの作業】
AIが作成する計画書（RES）のタスクリストには、個別の実装タスクの後に、以下の作業を必ず含めること。
*   コード修正完了後、JSDocコメントの記載漏れがないことを確認する（新しいファイルの先頭行の責務定義を含む）。
*   `.js` を変更・作成したタスクでは、憲法1章の検証コマンド（構文チェックと、リポジトリのルートでの `node --test` の `fail 0`）を実行する。
*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : 憲法3章の絶対禁止事項に反する設計をしてはならない。特に、`js/` から `oz/src/` を import しない・読まない（`oz/ENGINE_API.md` だけを参照する）、`js/` に `addEventListener`・`requestAnimationFrame`・`getContext` を書かない、描画処理の中で状態を変えない（`read`・`format`・`label` の関数で状態を変えない）、`window` にプロパティを足さない、エンジンに開発用パネルを入れない。エンジンに不足があると分かった場合は、回避コードを書かず、計画に書く前に疑問点として報告する。
*   **サンプルコードの目印** : 雛形には目印を付けず、土台の項目のファイルには責務定義の直後に `/* ozengine sample */` を付ける。目印の無いコードが目印の付いたコードを import しない。目印の付いた部分をすべて消しても、エラーなく起動できる状態を保つ（憲法3章「サンプルコードの目印」）。
*   **責務の分離** : 開発資料4章の責務表に合わせる。雛形は、窓の設定、「基本」の部品と位置、呼ぶ側の部品・タブの受け入れ、開き方だけを持ち、ゲーム固有の値（機体・音・土台のレイヤー名など）と保存を持たない。メニューの項目の定義（`playMenu.js`）に窓の中身を書かない。責務の文が変わるファイルは、ファイル先頭の責務定義（3行以内）と開発資料4章の責務表の更新予定に挙げる。
*   **変更してよいファイル** : `js/scenes/` のファイル（`devPanel.js`・`fps.js`・`slow.js`・`playMenu.js`・`PlayScene.js`・`uiText.js` の変更と、雛形・土台の項目のための新規作成・改名）、`PROJECT_ARCHITECTURE.md`（最終の固定タスクのみ）、作業計画書（本RES）に限る。`oz/`・`js/main.js`・`js/ui/`・`js/effect/`・`js/entities/`・`js/scenes/` の上に挙げていないファイル（`MenuScene.js`・`WindowScene.js` を含む）・`assets/`・`index.html`・`test/`・`_doc/`・`PROJECT_CONSTITUTION.md`・`CLAUDE.md`・`README.md` は変更しない。これら以外の変更が要ると分かった場合は、計画に書く前に疑問点として報告する。
*   **外部依存の禁止** : 外部ライブラリ・npm パッケージ・`package.json`・ビルドを使わない。
*   **スコープの分割** : 雛形、土台の開発用パネル（雛形に土台の項目を足す）、速度の文字、開発用の入口の出し分け、見本を消した写しでの確認は、混同しない粒度のタスクに分ける。どのタスクが終わった時点でも、土台がエラーなく起動できる順にする。
*   **確認の範囲** : 実装AIはブラウザや実機での動作確認を行わない（発注者のテストプレイで行う）。要件8の確認事項を、RES の懸念事項・目視確認推奨箇所に挙げる。
*   **今回やらないこと** : 次は作らない・変えない。
    *  雛形の項目を FPS と速度から増やすこと。新しいデバッグ機能（当たり判定の枠の表示、コマ送り、ログの表示など）。
    *  遊ぶ人向けのメニューと設定画面の雛形。`MenuScene`・`WindowScene` の仕様の変更。開発用パネルを開く専用のキーや、タイトル画面から開く入口。
    *  開発用のコードを公開時に取り除く仕組み。FPS の計算や警告を止めること。
    *  レイヤー名・素材の名前・キーの置き場所をまとめること（この作業で新しく書く分も、今の書き方に合わせて各ファイルに書く）。
    *  手順書（`_doc/newgame/`）の変更。既存のゲームへの導入。`oz/VERSION` の更新。
