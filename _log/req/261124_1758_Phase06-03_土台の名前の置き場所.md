*   **要件2: 置き場所（決定事項）**
    *  置き場所は、`js/` の直下の新しいファイル1つとする（仮の名前は `js/names.js`。名前は計画で決める）。3種類とも1つのファイルに置き、種類ごとにまとまりを分ける（レイヤー、画像、音、キー。仮の形は下のとおり。export の名前と、各要素の名前は計画で決める）。

       ```js
       export const LAYER = {
         main: 'main',
         /* ozengine sample: begin */
         stars: 'stars', // …（trail・ship・wind・ui も）
         /* ozengine sample: end */
       };
       export const IMAGE = { /* 見本の画像の名前。範囲の目印で囲む */ };
       export const SOUND = { /* 見本の音の名前。範囲の目印で囲む */ };
       export const KEY = {
         left: 'ArrowLeft',
         right: 'ArrowRight',
         boost: 'Space',
         // メニューの開閉のキーは見本だけが使うので、範囲の目印で囲む
       };
       ```

    *  ファイル全体には目印を付けない。見本だけが使う名前は、範囲の目印（`/* ozengine sample: begin */`・`/* ozengine sample: end */`）で囲む。見本を消した後に残る名前は、`'main'` と、`virtualPadConfig.js` が使う3つのキーだけである。
    *  見本を消した後に中身が空になる種類（画像、音）も、ゲームが名前を書く置き場所として残す（空のオブジェクトになる）。何を書く場所かが、それぞれの JSDoc で分かる。この JSDoc は、見本を消した後も残る位置に書く。
    *  このファイルは名前の値だけを持ち、関数・処理・import を持たない。パス、色、大きさ、文言、レイヤーの順は持たない。
    *  複数のファイルまたは行で使う名前を書く場所とし、1か所でしか使わない名前（`'KeyS'`・`'KeyF'`・`'KeyM'`・`'Escape'`）は移さない。

## 【計画書に必ず含めるべきタスクごとの作業】
AIが作成する計画書（RES）のタスクリストには、個別の実装タスクの後に、以下の作業を必ず含めること。
*   コード修正完了後、JSDocコメントの記載漏れがないことを確認する（新しいファイルの先頭行の責務定義を含む）。
*   `.js` を変更・作成したタスクでは、憲法1章の検証コマンド（構文チェックと、リポジトリのルートでの `node --test` の `fail 0`）を実行する。
*   タスク完了後、作業レポート（本RESファイル）の詳細作業内容を記載し完成させる。
*   開発資料（`PROJECT_ARCHITECTURE.md`）の記載に影響が出る場合は、資料本体は修正せず、その旨を『開発資料の更新予定』欄に追記する。

## 【計画書に必ず含めるべき固定タスク】
AIが作成する計画書（RES）のタスクリストには、全実装タスクの後に、以下のタスクを必ず含めること。
*   各タスクで記録した『開発資料の更新予定』を確認し、開発資料（`PROJECT_ARCHITECTURE.md`）へ反映する。開発資料に影響を与えない場合は、このタスクは不要とする。
    *   ※ 実装AIによる開発資料の書き換えは、本ワークフローにおいて原則禁止であるが、**この最終タスクのみ明示的な例外とする**。後続タスクが存在せず、資料の変更によって他タスクの前提が動く危険がないためである。個別の実装タスク内で資料を書き換えてはならない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : 憲法3章の絶対禁止事項に反する設計をしてはならない。特に、`js/` から `oz/src/` を import しない・読まない（`oz/ENGINE_API.md` だけを参照する）、エンジンにレイヤー名・キーなどを書かない、`window` にプロパティを足さない。エンジンに不足があると分かった場合は、回避コードを書かず、計画に書く前に疑問点として報告する。
*   **サンプルコードの目印** : 目印の無いコードが、目印の付いたコード（範囲の目印の中の名前を含む）を参照しない。目印の付いた部分をすべて消しても、エラーなく起動できる状態を保つ（憲法3章「サンプルコードの目印」）。
*   **責務の分離** : 置き場所のファイルは名前の値だけを持つ。責務の文が変わるファイルは、ファイル先頭の責務定義（3行以内）と開発資料4章の責務表の更新予定に挙げる。
*   **変更してよいファイル** : 置き場所の新しいファイル（`js/` の直下に1つ）、`js/main.js`、`js/scenes/` の `BootScene.js`・`FlightScene.js`・`LoadScene.js`・`PlayScene.js`・`TitleScene.js`・`playDevPanel.js`・`playMenu.js`・`settingsWindow.js`、`js/ui/virtualPadConfig.js`、`PROJECT_ARCHITECTURE.md`（最終の固定タスクのみ）、作業計画書（本RES）に限る。`oz/`・`js/effect/`・`js/entities/`・上に挙げていない `js/scenes/` と `js/ui/` のファイル（`MenuScene.js`・`WindowScene.js`・`devPanel.js`・`virtualPadView.js` を含む）・`assets/`・`index.html`・`test/`・`_doc/`・`PROJECT_CONSTITUTION.md`・`CLAUDE.md`・`README.md` は変更しない。これら以外の変更が要ると分かった場合は、計画に書く前に疑問点として報告する。
*   **外部依存の禁止** : 外部ライブラリ・npm パッケージ・`package.json`・ビルドを使わない。
*   **スコープの分割** : 置き場所のファイルの作成、レイヤー名、素材の名前、キー、写しでの確認は、混同しない粒度のタスクに分ける。どのタスクが終わった時点でも、土台がエラーなく起動できる順にする。
*   **確認の範囲** : 実装AIはブラウザや実機での動作確認を行わない（発注者のテストプレイで行う）。要件7の確認事項を、RES の懸念事項・目視確認推奨箇所に挙げる。
*   **今回やらないこと** : 次は作らない・変えない。
    *  対象の13組のほかの値（色、大きさ、文言、パス、保存の名前、FPS の位置の名前、`Escape`、1か所だけのキー）をまとめること。`index.html` と `js/` にまたがる値をまとめること。
    *  名前の綴りを検査する仕組み、`Object.freeze` などの保護、名前を列挙する関数、型の仕組みを足すこと。
    *  シーンのレイヤー名の受け取り方、バーチャルパッドの定義の形、`Engine.start` に渡す設定の形を変えること。
    *  手順書（`_doc/newgame/`）の変更。既存のゲームへの導入。`oz/VERSION` の更新。
