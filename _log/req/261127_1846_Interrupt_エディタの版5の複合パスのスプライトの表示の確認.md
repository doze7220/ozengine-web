本プロンプトは、OZ Vector Editor が書き出し形式の版5（複合パス `compoundPath` を追加）で書き出した確かめ用のスプライトを、ゲームの土台のタイトル画面に並べて表示するための、**確認の間だけの一時的な変更**を行う Interrupt である。必ず以下の順序で作業を行うこと。

1. ルール（`PROJECT_CONSTITUTION.md`）を熟読・把握すること。
2. 本REQの【関連する責務】を把握すること。作業に必要な責務情報はすべてここに記載されている。開発資料（`PROJECT_ARCHITECTURE.md`）は、記載外の責務を確認する必要が生じた場合にのみ参照すること。
3. 実装対象のコードを読み、【関連する責務】に**記述されている内容と実コードが矛盾する**場合は、修正に着手せず、相違点を報告して指示を待つこと。記述にない事項の存在は相違とみなさない。
4. 相違がなければ、【実装要件】に従って実装を開始し、ソースコードの修正を実行すること。
5. コード修正が完了したら、Interrupt作業レポートテンプレート（`./_log/TEMPLATE_RES_Interrupt.md`）を元に、作業レポート（`./_log/res/261127_1846_RES_Interrupt_エディタの版5の複合パスのスプライトの表示の確認.md`）を新規作成して出力すること。
   * テンプレートの項目に従い、「原因と修正方針」「対象ファイル」「詳細作業内容」を正確に記述すること。
   * 「実装内容」に、この変更が確認用の一時的なものであり、コミットせず、確認後に設計AIが元に戻すことを明記すること。
6. 開発資料（`PROJECT_ARCHITECTURE.md`）の内容に影響がある場合は、資料本体は修正せず、その旨を作業レポートの『開発資料の更新予定』欄に明記すること（一時的な変更なので、通常は「該当なし」となる）。

## 【実装要件】
OZ Vector Editor で、フォルダを「複合パス」に切り替えられるようになり、スプライトJSの書き出し形式の版（`formatVersion`）が4から5に上がった。複合パスは、中の図形の輪郭をまとめて1つの形として塗り、重なりの数が偶数の所が抜ける（大きな円の中に小さな円を入れるとドーナツ型になる）。描き方は各スプライトJSの `draw(ctx)` の中に入っており（`ctx.fill('evenodd')` で塗る）、`draw(ctx)` を呼ぶだけでよい約束も `bounds` の形も変わらないため、エンジンとゲームの土台のコードの変更は要らない見込みである。これを画面で確かめるため、エディタから届いた確かめ用のスプライトを、確認の間だけタイトル画面に出す。

確かめ用のスプライトは `_doc/BRIDGE_FROM_VECTOREDITOR_compound_check.js` にある（エディタの書き出しファイル。未追跡のファイルで、確認後に設計AIが削除する）。原点 (0, 0) のまわりに、`bounds` が `{ minX: -239, minY: -97, maxX: 237, maxY: 97 }` の範囲で、オレンジの線と青の塗りの8つの場面を2段に並べた絵である。
* 上の段：ドーナツ（穴から後ろの黄色い四角が見える）、穴が2つの四角、内側に三角の切り欠きがある半円、線だけの丸と四角（塗りなし）。
* 下の段：左に丸い穴・右に輪の形の穴（真ん中に小さな青い丸が残る）がある四角、丸い穴が1つの四角、中心の五角形が抜けた星（後ろの黄色い丸が見える）、比べる用の普通の重なり（青い丸の上に紫の丸。穴は無い）。

*   **要件1: 確かめ用のスプライトを2通りの描き方で並べて出す（`js/scenes/TitleScene.js`）**
    *  確かめ用のスプライトを、`TitleScene.js` から相対パス（`../../_doc/BRIDGE_FROM_VECTOREDITOR_compound_check.js`）で `import` する（既定の export を使う）。
    *  タイトル画面の `ui` レイヤーの、ゲーム名・画像・ボタンを描いたあとに、次の2つを横に並べて描く。どちらも拡大・回転はしない（`ctx.translate` だけで位置を決める。`scale`・`rotate` は使わない）。画面（1280 × 720 px）の縦 410 px を原点の高さとし、(a) の原点を横 320 px、(b) の原点を横 960 px に置く（絵は縦 313〜507 px、横は (a) が 81〜557 px・(b) が 721〜1197 px になり、画像の下端 280 px とボタンの上端 540 px の間、画面の左右の端の内側に収まる）。
        * (a) スプライトの `draw(ctx)` をそのまま呼んで描いたもの。
        * (b) `CanvasCache.create(sprite, { bounds: sprite.bounds })`（倍率は指定しない＝既定の 1）で焼き付けたものの `draw(ctx)` で描いたもの。
    *  (a)・(b) のそれぞれの原点の真上（縦 296 px）に、どちらの描き方かが分かる短い文字（`(a) draw` と `(b) CanvasCache`）を、既存の `drawText`（`./uiText.js`）で描く。フォントは `24px sans-serif` とする（文字は縦 284〜308 px 付近で、画像の下端と絵の上端の間に入る。画像は横 560〜720 px なので文字とは重ならない）。
    *  焼き付けは、`TitleScene` の `init` で（`super.init()` の後で）作り、`destroy` で `dispose()` して手放す。`TitleScene` には今 `destroy` がないので、`super.destroy()` を呼んでから手放す `destroy` を足す。
    *  変更するのは `TitleScene.js` だけとする。ファイル先頭の責務定義・`/* ozengine sample */` の目印・既存の処理（ゲーム名・画像・ボタン・BGM・遷移）は変えない。
*   **要件2: 一時的な変更であることの扱い**
    *  この変更（`js/scenes/TitleScene.js`）は**コミットしない**。発注者の確認が終わったら、設計AIが `git restore` で元に戻す（実装AI・実装統括AIは元に戻す作業を行わない）。
    *  そのため、変更箇所にコメントを足すなどの「一時的であることの目印」は書かない。JSDoc も最小限でよい（元に戻すので、恒久のコードの水準に合わせる必要はない）。ただし検証コマンド（構文チェック・`node --test`）は通すこと。

## 【関連する責務】
* `js/scenes/TitleScene.js` : タイトル画面（自動操縦のデモ、ゲーム名・画像・ボタンの表示）と、BGM の開始、プレイへの遷移。`FlightScene` を継承する。`init` は先頭で `super.init()`（機体の焼き付けの作成）を呼んでからボタンの登録と BGM の開始を行う。`draw(ctx, layer, time)` は `super.draw` を呼んだあと、`ui` レイヤーでだけゲーム名（y = 70）・画像（上端 y = 120、高さ 160。横の中央）・スタートボタン（上端 y = 540、高さ 72）を描く。
* `js/scenes/FlightScene.js` : タイトルとプレイに共通の、機体・星・トレイル・風の描画と、機体の焼き付けの作成（`init`）と手放し（`destroy`）。派生クラスで `destroy` を書くときは `super.destroy()` を呼ぶ。本作業では変更しない。
* `js/scenes/uiText.js` : 文字の共通処理。`drawText(ctx, text, x, y, font, align = 'center')` で、白い文字を描く（縦は中央揃え）。本作業では変更しない。
* `CanvasCache`（`oz` から import）: `CanvasCache.create(source, { bounds, scale? })` で、`draw(ctx)` を持つオブジェクトを `bounds` の範囲で焼き付け、`draw(ctx)`・`refresh()`・`dispose()` を持つ焼き付けを返す。焼き付けの `draw(ctx)` は、スプライトの `draw(ctx)` と同じ書き方（`ctx` の変換で位置を決めてから呼ぶ）で描ける。焼き付けは四方に 2 画素の余白を取る。シーンの `init` で作り、`destroy` で手放す。
* スプライトJS（`oz/ENGINE_API.md` 23章）: 既定の export のオブジェクトの `draw(ctx)` を呼ぶだけで描ける。基準点は原点 (0, 0)、y 軸は下向き。`draw(ctx)` は `ctx` の状態を元に戻して終わる。エディタの書き出しの `bounds`（`{ minX, minY, maxX, maxY }`）は、キャンバスキャッシュの範囲としてそのまま渡してよい。それ以外のキー（`format`・`formatVersion`・`elements` など）は、エンジンも利用側も読まない。
