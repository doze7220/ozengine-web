## 【実装要件】
`oz/` に画像と音声のロード（`Assets`）、音の再生（`Sound`）、設定の保存（`Storage`）を追加する。あわせて、`js/main.js` の確認用コードで、ロードした画像の表示、SE と BGM の操作、保存した値の確認を画面で行えるようにする。

*   **要件1: 公開の形**
    *  利用側には `import { Engine, Scene, Assets, Sound, Storage } from 'oz';` で公開する。3つとも `Engine` と同じくインスタンスを作らずに使うオブジェクトとする。
    *  3つとも `Engine.start` の前から使える。`Engine` はこの3つを import せず、起動設定にも項目を足さない。
*   **要件2: `Assets`**
    *  `Assets.load({ images: { 名前: パス, ... }, sounds: { 名前: パス, ... } })` は、一覧のすべてのロードが終わると解決する Promise を返す。`images`・`sounds` はどちらも省略できる。何度呼んでもよく、同じ名前は後のものに置き換わる。
    *  パスはページ（`index.html`）からの相対パスとする（例: `./assets/images/a.png`）。import map の `assets/` は `import` にしか効かないので、使えないことを `oz/ENGINE_API.md` に書く。
    *  `Assets.image(名前)` はロード済みの画像を返す。`ctx.drawImage` にそのまま渡せる。一覧に書いていない名前と、ロードが終わっていない名前はエラーにする。
    *  `sounds` の音声はデコードして `Sound` に名前で預ける。利用側は名前で `Sound` の再生を呼ぶ。一覧では SE と BGM を区別しない。
    *  **読み込みの失敗（発注者の決定）:** 読み込めない、またはデコードできないファイルがあっても、読めた分で続行する。Promise は失敗せず、すべての処理が終わると解決する。失敗したファイルごとに、名前とパスを含む警告をコンソールに出す（先頭に `[oz] Assets.load:`）。
        *  失敗した名前の `Assets.image` は、透明な1×1の画像を返す（ページに追加しない canvas でよい）。`ctx.drawImage` にそのまま渡しても何も描かれず、エラーにならない。
        *  失敗した名前の `Sound.playSe`・`Sound.playBgm` は何もしない。流れている BGM もそのまま続く。
    *  引数が不正なときは、Promise の失敗（reject）として返す。これはファイルの問題ではなく、書き方の間違いだからである。
    *  進捗の通知は作らない。ロード中の表示は利用側がシーンで行う。
*   **要件3: `Sound`**
    *  **SE:** `Sound.playSe(名前)` で最初から鳴らす。同じ SE を重ねて鳴らせる。一覧に書いていない名前と、ロードが終わっていない名前はエラーにする。
    *  **BGM:** `Sound.playBgm(名前, { fadeMs })` でループ再生する。`Sound.stopBgm({ fadeMs })` で止める。`fadeMs` はミリ秒で、省略すると `0`（すぐに切り替わる）。0 以上の有限数でなければ `RangeError` にする。
        *  同じ曲がすでに流れているときの `playBgm` は何もしない（頭に戻らない）。シーンをまたいで同じ曲を流し続けられるようにするためである。
        *  別の曲が流れているときの `playBgm` は、前の曲を同じ `fadeMs` でフェードアウトしながら、新しい曲をフェードインする。
        *  フェードアウト中の曲を `playBgm` で再び指定すると、頭から新しく流す。フェードアウト中の音はそのまま消える。
        *  フェードインの途中で `stopBgm` を呼んでも、音量が飛ばない。その時点の音量からフェードアウトする。
        *  BGM がないときの `stopBgm` は何もしない。一覧に書いていない名前と、ロードが終わっていない名前の `playBgm` はエラーにする。
    *  **音量:** `Sound.masterVolume`（全体）・`Sound.bgmVolume`・`Sound.seVolume` のプロパティで読み書きする。`0` 〜 `1` で、既定値は `1`。範囲外や数値以外は `RangeError` にする。再生中の音にもすぐ効き、フェードの途中でも正しく掛け合わされる。ロードの前から設定できる。ミュートの専用APIは作らず、`masterVolume` を `0` にして行う。
    *  **時間:** 音はゲーム時間と無関係に実時間で進む。`timeScale` が小さくても `0` でも、ポーズ用のシーンを積んでも、BGM とフェードはそのまま進む。
    *  **最初の入力まで（自動再生制限。発注者の決定）:** 最初の入力より前の `playSe`・`playBgm` は、エラーにせず捨てる。覚えておいてあとで鳴らすことはない。BGM を流したいゲームは、最初の入力への反応の中で `playBgm` を呼ぶ（`oz/ENGINE_API.md` に例を載せる）。
        *  名前の確認は入力の前でも行う（一覧にない名前はエラーにする）。
        *  最初の入力そのものへの反応として呼んだ `playSe`・`playBgm`（例: タイトルをタップして鳴らす）は鳴る。入力の配信はフレームの中で行うので、`resume()` の完了を待たずに呼ばれることがある。この場合も捨てない。
        *  「最初の入力」は、`Sound` の再開用のイベント（次の項目）を受け取った時点とする。ただし `Escape` の `keydown` は数えない。ブラウザが解除を認めないので、数えると解除までの要求があとでまとめて鳴るためである。
    *  **AudioContext の再開の方法:** 入力の配信はフレームの中で行うので（開発資料3章）、そこからでは自動再生制限を解除できない。そこで `Sound` が自分で `window` に `pointerdown`・`pointerup`・`keydown` を capture で登録し、そのイベントの中で直接 `resume()` を呼ぶ。`Input` は経由しない（依存の向きを増やさず、canvas の外の入力でも解除できるようにするため）。
        *  ブラウザが解除を認めるイベントは、マウスの `pointerdown`、タッチとペンの `pointerup`、`Escape` 以外の `keydown` である。そのため3種類を登録し、AudioContext が実際に `running` になるまでイベントごとに `resume()` を試す。`running` になったら登録を解除する。
        *  `Engine.start` やロードの前の入力も取りこぼさないように、登録はモジュールの読み込み時に行ってよい。AudioContext そのものは、最初に必要になったとき（デコードまたは再生）に作る。音を使わないゲームでは作られない。
        *  このイベントの中ではシーンの処理を呼ばない（開発資料3章）。
        *  入力の前に AudioContext を作ると、Chrome はコンソールに黄色の警告を出す。エラーではなく動作に影響しないので許容し、`oz/ENGINE_API.md` に書く。
    *  **音の時刻:** フェードと停止の予定には `AudioContext.currentTime`（`AudioParam` の予定、`source.stop(when)`）を使う。憲法3章「時間の受け渡し」は、ゲームの更新に使う時間を対象とするものと解釈し、音の予定時刻にだけ使うことを認める（発注者の決定）。その値をゲームの更新や描画に使ってはならず、公開もしない。`setTimeout` は使わない。
*   **要件4: `Storage`**
    *  `Storage.open({ key, version, defaults })` で、保存先の名前（空でない文字列）、版番号（有限の数値）、既定値（オブジェクト）を渡す。不正な引数と2回目の呼び出しはエラーにする。
    *  `Storage.get(名前)` は値を返す。`Storage.set(名前, 値)` は値を変更し、その場で保存する。`open` の前に呼ぶとエラーにする。`defaults` にない名前はエラーにする（書き間違いを早く見つけるため）。JSON にできない値はエラーにする。
    *  1つのキーに、版番号とデータをまとめた単一の JSON を `localStorage` へ保存する。
    *  **既定値で始める場合（いずれもエラーにしない）:** 保存データがない。版番号が違う。JSON として読めない。形が違う。版番号が違うときの移行処理は作らない。古いデータは、最初の `set` まで消さない。
    *  同じ版番号で `defaults` に名前が増えていたら、その名前だけ既定値を使う。`defaults` にない保存値は捨てる。
    *  `localStorage` が使えない、または容量があふれたときは、例外を投げずにコンソールへ警告を出し、メモリの上だけで動き続ける。
    *  `get` が返す配列やオブジェクトを利用側が書き換えても、保存内容と `defaults` に影響しない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **依存の向き** : 開発資料3章の依存の向きを守る。`Sound`・`Storage` は他のエンジンモジュールを import しない。`Assets` が import してよいのは `Sound` だけとする（音声のデコードと、名前で預けるため）。`Engine`・`GameLoop`・`Input` は `Assets`・`Sound`・`Storage` を import しない。
*   **入口の一本化** : 公開するのは要件1の5つだけとする。`Assets` から `Sound` へ音声を預けるための内部の手段は、`oz/index.js` から公開しない。
*   **責務の分離** : `Assets` はロードと取得、`Sound` は AudioContext の管理と再生と音量、`Storage` は保存と読み込みに留める。BGM の状態遷移やセーブ内容の定義はエンジンに入れない。
*   **ゲーム固有知識の混入禁止** : 素材の名前、パス、保存先の名前、音量やフェード時間の固定値をエンジンに書かない（`fadeMs` と音量の既定値を除く）。
*   **DOMの制限** : エンジンはページに要素を追加しない。`new Image()` で作った画像もページに追加しない。
*   **時間の受け渡し** : `Assets`・`Storage` は時間を取得しない。`Sound` は要件3「音の時刻」の範囲でだけ `AudioContext.currentTime` を使う。
*   **ブラウザのイベントの中の処理** : `Sound` の再開用のイベントの中では、`resume()` の呼び出しと、入力があったことの記録だけを行う。シーンの処理を呼ばない。
*   **先回り実装の禁止** : やらないことに挙げた機能を作らない。空枠も作らない。
*   **`js/` の実装** : `js/main.js` を実装するタスクでは `oz/src/` を読まず、`oz/ENGINE_API.md` だけを参照する（憲法3章）。そのため、`oz/ENGINE_API.md` が揃うタスクの後に置き、計画書に明記する。分からないことはRESに不足として記録する。
*   **公開APIとドキュメント** : 公開APIを追加するタスクと同じタスクで `oz/ENGINE_API.md` を更新する（憲法3章）。
*   **スコープの粒度** : タスクは1〜数ファイル単位に分ける。
