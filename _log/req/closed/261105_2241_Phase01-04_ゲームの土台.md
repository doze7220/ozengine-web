### 画面での確認（発注者のテストプレイ。計画の参考）
*   開くと「ロード中」のあとにタイトルになり、機体が自動で飛び回り、トレイルと星が流れ、ときどきブーストして風が出る。何も操作しない間は音が鳴らず、コンソールにエラーが出ない。
*   タイトルに「Vernier Trail」、画像、「スタート」のボタンが表示され、ページに DOM の見出しはない。
*   最初の入力で BGM がフェードインで流れ始める。ボタンの内側でも外側でもプレイが始まる。
*   プレイ中、左右キーで旋回し、`Space` でブーストし、風が出て SE が鳴る。押しっぱなしでは繰り返さない。
*   `P` で背面を残して止まり、もう一度 `P` またはタップで再開する。ポーズ中も BGM は流れ続ける。
*   `S` でスローと等速が切り替わる。
*   星、トレイル、機体、風、UI がこの順に重なっている（機体がトレイルの上、風が機体の上、文字が一番上）。
*   `M` でミュートになり、ページを再読み込みしてもミュートのままである。
*   `?debug` を付けて開くと FPS が表示される。
*   リフレッシュレートが異なる画面で、機体の速さが同じである（環境があれば）。
*   目印を消したコピーを静的サーバで開くと、真っ黒な画面で、コンソールにエラーが出ない。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **`oz/src/` を読まない** : 要件1のとおり、計画立案と `js/` のタスクでは `oz/src/` を読まず、`oz/ENGINE_API.md` だけを参照する（憲法3章）。計画書にも `oz/src/` の内容を書かない。`js/` のタスクの動作確認は、検証コマンドと Grep までとする。エンジンを Node で動かす確認はしない。
*   **依存の向き** : `js/`・`assets/` → `oz` だけとする。`oz/` から利用側を import しない。`oz/src/` を直接 import しない。`assets/sprites/ship.js` は何も import しない。
*   **責務の分離** : 開発資料4章に従う。`js/main.js` にゲームロジックと描画を書かない（確認用コードの例外は、確認用コードがなくなるので使わない）。`js/scenes/` は進行と呼び出しに留め、細かい動きや描画の実装を書かない。`js/effect/` はゲーム進行に影響する処理を持たない。`js/entities/` は描画命令を直書きしない。
*   **ロジックと描画の分離** : `update` の中で描画しない。`draw` の中で状態を変更しない。
*   **時間の受け渡し** : `js/` で `performance.now()`・`Date.now()` を使わない。動きはティックで進める。
*   **操作を呼ぶ場所** : `Engine.changeScene`・`pushScene`・`popScene` は `update`・`onPointer`・`onKeyDown`・`onPress` の中と、フレーム処理の外（`Assets.load` の完了）でだけ呼ぶ。`draw`・`init`・`destroy` の中で呼ばない（`oz/ENGINE_API.md` 7章）。
*   **グローバル汚染の禁止** : `window` にプロパティを追加しない。
*   **先回り実装の禁止** : やらないことに挙げた機能を作らない。空枠も作らない。
*   **見本としての読みやすさ** : 各ファイルは短く保ち、調整値は名前付きの定数にする。全クラス、全関数、全メソッド、データ構造に JSDoc を書き、全ファイルの先頭に責務定義を書く。
*   **スコープの粒度** : タスクは1〜数ファイル単位に分ける。依存される側（スプライト、機体、演出）から順に作り、シーンと `js/main.js` を後にする。`js/main.js` を置き換えるまでは、未使用の新規ファイルがあっても画面の動作は変わらない。
*   **コピーの扱い** : 一時的なスクリプトとコピーはリポジトリの外に置く。
