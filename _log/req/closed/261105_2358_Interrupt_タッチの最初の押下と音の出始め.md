```md
### タッチの最初の押下

タッチでは、ブラウザが指を離すまで音を出すことを認めない。そのため、最初の入力がタッチの押下のときは、指を離すまで次のようになる。

* `onPointer` の `'down'` やボタンの `onPress` の中で呼んだ音は、捨てられずに鳴るが、鳴り始めは押した瞬間ではなく指を離したときになる。BGM も同じである。
* 押したままの間に `update` などから `playSe` を何度も呼ぶと、その分が指を離したときに重なって同時に鳴る。
* 2回目以降の押下では、呼んだときにすぐ鳴る。マウスでは、最初の押下でも呼んだときにすぐ鳴る。
* これは PC の Chrome のタッチの再現機能で確認した動作である。スマートフォンの実機では確認していない。
```

## 【確認結果】
発注者が、リポジトリの外に置いた一時的な確認用ページで確認した（確認後にサーバを停止した。ページはコミットしていない）。ページはエンジンの公開APIだけで音を鳴らし、次の2つのテストを行う。

* テスト1: `onPointer` の `'down'` で `playSe` を1回呼ぶ。
* テスト2: 押している間、`update` から1秒ごとに `playSe` を呼ぶ（押した瞬間には呼ばない）。指を離すと止める。

| 環境 | テスト1 | テスト2 |
| --- | --- | --- |
| PC の Chrome（マウス） | 押した瞬間に鳴る | 押した瞬間は鳴らず（1秒後に最初の呼び出しがあるため）、1秒後から鳴り始める。離してもまとめて鳴らない |
| PC の Chrome（開発者ツールのスマホモードによるタッチの再現） | 1回目は押したときに鳴らず、離したときに鳴る。2回目以降は押したときに鳴る | 押したときも押し続けても鳴らず、離したときにまとめて鳴る（発注者の耳での判断で、「判別は難しい」との補足あり） |

## 【未確認の事項】
* スマートフォンの実機では確認していない（iPhone の Safari を含む）。発注者がすぐには確認できないため、持ち越す。
* テスト2の2回目の押下（解除の後に1秒ごとに鳴るか）の結果は、報告を受けていない。
* 音を鳴らすテストは `playSe` だけで行った。ボタンの `onPress` は、`onPointer` の `'down'` と同じ押下のときに呼ばれるという `oz/ENGINE_API.md` 18章の記述からの判断であり、`playBgm` が同じ動作になることは、`oz/src/Sound.js` の読解による判断である。

* `Sound` : AudioContext の管理（入力での再開を含む）、音声のデコードと名前での保持、SE と BGM の再生、フェード、音量を担う。自分で `window` に `pointerdown`・`pointerup`・`keydown` を capture で登録し、そのイベントの中で直接 `AudioContext.resume()` を呼ぶ。入力があり AudioContext が `running` になったら登録を解除する。最初の入力より前の再生の要求は捨てる。
