## 【作業手順（厳守事項）】
本プロンプトは、OZ Vector Editor が書き出した機体のスプライトをゲームの土台で表示して確かめる（M1 の確認）ために、**確認の間だけ背景を明るくする一時的な変更**を行う Interrupt である。必ず以下の順序で作業を行うこと。

1. ルール（`PROJECT_CONSTITUTION.md`）を熟読・把握すること。
2. 本REQの【関連する責務】を把握すること。作業に必要な責務情報はすべてここに記載されている。開発資料（`PROJECT_ARCHITECTURE.md`）は、記載外の責務を確認する必要が生じた場合にのみ参照すること。
3. 実装対象のコードを読み、【関連する責務】に**記述されている内容と実コードが矛盾する**場合は、修正に着手せず、相違点を報告して指示を待つこと。記述にない事項の存在は相違とみなさない。
4. 相違がなければ、【実装要件】に従って実装を開始し、ソースコードの修正を実行すること。
5. コード修正が完了したら、Interrupt作業レポートテンプレート（`./_log/TEMPLATE_RES_Interrupt.md`）を元に、作業レポート（`./_log/res/261109_1300_RES_Interrupt_Phase02-02_M1の確認とエディタとの往復.md`）を新規作成して出力すること。
   * テンプレートの項目に従い、「原因と修正方針」「対象ファイル」「詳細作業内容」を正確に記述すること。
   * 「実装内容」に、この変更が確認用の一時的なものであり、コミットせず、確認後に設計AIが元に戻すことを明記すること。
6. 開発資料（`PROJECT_ARCHITECTURE.md`）の内容に影響がある場合は、資料本体は修正せず、その旨を作業レポートの『開発資料の更新予定』欄に明記すること。
7. すべての作業が完了したら、チャットにて「実装が完了しました。ビルド・動作確認をお願いします」と報告すること。

## 【実装要件】
OZ Vector Editor にはまだ色を変える機能がなく、書き出したスプライトの線は黒（`#000000`）である。ゲームの土台の背景は黒に近い紺のグラデーションなので、黒い線の機体が見えない。M1 の確認の間だけ、背景を明るい単色に変える。

*   **要件1: 背景のグラデーションの色を一時的に明るくする（`js/effect/Stars.js`）**
    *  定数 `BG_COLOR_START` と `BG_COLOR_END` の値を、どちらも `'#8890a0'`（明るめの灰色。黒い線がはっきり見え、白い文字・ボタンもまだ読める明るさ）に変える。
    *  変更するのはこの2つの定数の値だけとする。定数の JSDoc、描画の処理、星の描画、ファイル先頭の責務定義と `/* ozengine sample */` の目印は変更しない。
*   **要件2: 一時的な変更であることの扱い**
    *  この変更はコミットしない。発注者の確認が終わったら、設計AIが `git restore` で元に戻す（実装AIは元に戻す作業を行わない）。
    *  そのため、変更箇所にコメントを足すなどの「一時的であることの目印」は書かない（元に戻すときに差分を残さないため）。

## 【関連する責務】
* `js/effect/Stars.js` : 背景のグラデーションと、視差のある星空の生成と描画。ゲーム進行に影響する処理は持たない。背景は `BG_COLOR_START`（0）から `BG_COLOR_END`（1）への線形グラデーションで画面全体を塗り、その上に白い星を描く。
* 機体のスプライト（`assets/sprites/ship.js`）は `js/scenes/FlightScene.js` の `drawShip` が `ship` レイヤーに描く。背景は `stars` レイヤーで、`ship` レイヤーより下に描かれる。本作業ではどちらのファイルも変更しない。

## 【絶対遵守ルール (Constraints)】
* **変更してよいファイル** : `js/effect/Stars.js`（要件1の2つの定数の値のみ）、および作業レポート（RES）の新規作成のみ。`assets/sprites/ship.js`、`js/` の他のファイル、`oz/`、`index.html`、`PROJECT_ARCHITECTURE.md`、`_doc/` 配下は変更しない。
* **ついでの修正の禁止** : 要件に挙げた箇所以外（整形・命名・他の処理）は変更しない。

## 【設計AI・発注者の作業（実装AIは行わない）】
本REQのうち、以下は実装AIの作業範囲外である。設計AIと発注者がこの順で行う。

1. **発注者：エディタで機体を描いて書き出す。**
   * キャンバス名は `ship` にする（書き出すファイル名が `ship.js` になる）。
   * 機首を右（+X）に向け、原点 (0, 0) を機体の中心にして、手書きの `ship.js` と同じくらいの大きさ（横 約45 px × 縦 約36 px。目安は機首 (22, 0)、後端 x = -23、上下の端 y = ±18）で描く。
   * 書き出された `ship.js` だけを `assets/sprites/ship.js` に上書きで置く（`ship.json` は置かない）。
2. **発注者：テストプレイで確かめる。** キャッシュを使わない再読み込み（Ctrl+Shift+R）をしてから、タイトルとプレイで機体として表示されることを見る。困った点・エディタに直してほしい点があれば設計AIに伝える。
3. **設計AI：元に戻す。** 確認が終わったら `git restore js/effect/Stars.js assets/sprites/ship.js` で背景と手書きの機体に戻し、`git status` がクリーンであることを確かめる。発注者に、元の背景と手書きの機体に戻っていることを確かめてもらう。
4. **設計AI：エディタへ返信する。** `D:\ozlab\ozvectoreditor\_doc\BRIDGE_FROM_ENGINE.md` を新規作成し、2で挙がった困った点・直してほしい点を書く。なければ「往復は1回で完了」と書く。このファイルはエディタのリポジトリのものなので、本リポジトリからはコミットしない（エディタ側の取り込みはエディタのセッションに任せる）。
