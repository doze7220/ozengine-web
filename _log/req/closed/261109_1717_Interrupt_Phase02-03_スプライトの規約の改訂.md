## 【実装要件】
Phase 02-01・02-02 で、エディタの書き出しファイルを `assets/sprites/` に置くだけで、`js/` を変えずにゲームの土台に表示できることを確かめた（エディタとの往復は1回で完了し、エディタへの依頼事項はない）。読み込み側（`js/scenes/FlightScene.js`）は既定の import（`import shipSprite from 'assets/sprites/ship.js'`）で `shipSprite.draw(ctx)` を呼び、手書きの `ship.js` は `export default { draw }`（`draw(ctx)` だけ）になっている。一方、開発資料 2.1章は旧形式（名前付きの `format` と `draw(ctx, t, opts)`）のままである。これを実態に合わせて改訂する。

*   **要件1: `PROJECT_ARCHITECTURE.md` 2.1章「スプライトJS（`assets/sprites/*.js`）」を書き直す**
    *  旧形式の export の表（`format`・`draw(ctx, t = 0, opts = {})`・`source`）を削除する。
    *  **形式の定義はエディタ側への参照とする:** スプライトJSの形式（既定の export に入るデータのキー、`draw` の中身など）の唯一の記載箇所は、OZ Vector Editor のリポジトリ（`D:\ozlab\ozvectoreditor`）の `PROJECT_ARCHITECTURE.md` 2章「スプライト（書き出し形式）」の項であることを書き、本章には形式を書き写さない（二重管理を避けるため）。
    *  **エンジン側の約束だけを書く。** 次の内容を、表または箇条書きで簡潔に書く。
       *  利用側は、スプライトJSを `import` し、既定の export のオブジェクトの `draw(ctx)` を呼ぶだけである。エンジンは中身を解析せず、読み込みもしない（読み込みは利用側の `import`）。現時点では、`draw` 以外のキー（エディタの書き出しに入る `format`・`formatVersion`・`bounds`・`elements`・`source` など）は、エンジンも利用側も読まない。
       *  `draw` は `ctx` の状態を元に戻して終わる。
       *  座標の単位は px で、基準点はワールド座標の原点 (0, 0)、y 軸は下向きである。エディタの px はそのままゲームの px になる。
       *  配置（位置・回転・拡大縮小）は、呼ぶ側が `ctx` の変換で行ってから `draw` を呼ぶ。
       *  土台の機体は前方を +X とする（エディタで描くときも機首を +X に向ける）。
       *  スプライトは見た目だけを持つ。位置・HP・`update()` などの動きは `js/` 側のクラスが持つ（現行の記述を残す）。
    *  **つなぎのスプライト:** エディタで描けない絵を AI が手で書く場合（つなぎのスプライト）も、既定の export で `draw(ctx)` を持つ形にする。`format` などのデータのキーは持たなくてよい（現在の手書きの `ship.js` は `export default { draw }`）。手で書いてよい条件は憲法3章「生成物の手編集禁止」に従う旨を書く。
    *  **組み立て用のJS（名前の頭に `_`）の扱い:** 次の内容を書く。
       *  スプライトJSは外部依存のない1ファイルとする。ただし、組み立て用のJS（名前の頭に `_`。例 `_hero.js`）はこの例外とし、同じ `assets/sprites/` にあるパーツのスプライトJSを相対パス（`./body.js` など）で `import` してよい。エンジン（`oz`）・`js/`・`assets/sprites/` の外のファイルは `import` してはならない。
       *  組み立て用のJSも、既定の export で `draw(ctx)` を持つ点は同じである（配置は `ctx` の変換で行う）。
       *  組み立て用のJSは、エディタの P7（アニメーションエディタモード）で書き出す想定であり、現時点では存在せず、読み込みの実装もしない（M2 以降）。キーフレームのために時間の引数（`draw(ctx, t)` など）を足すかどうかは、そのときに決める。
       *  エディタ側の使い方の例は、上記のエディタ側の項にある旨を書く（例のコードは書き写さない）。
*   **要件2: `PROJECT_ARCHITECTURE.md` 4章の `assets/sprites/*.js` の行を実態に合わせる**
