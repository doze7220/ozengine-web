### 全体の構成（タスク1〜5）
公開するのは `Engine` と `Scene` の2つだけとする。`Time`・`Screen`・`Layers`・`Scenes`・`GameLoop`・`DebugOverlay` は公開しない。利用側に必要なのはシーン操作と `timeScale` の読み書きだけであり、クラスごと公開すると `beginFrame` などの内部操作まで利用側から呼べてしまうためである。

`Engine` が各モジュールを生成し、`GameLoop` へ引数で渡す。`Layers` と `Scenes` は互いを import しない。

1フレームの処理（`GameLoop`）は次の順序に固定する。`now` は `requestAnimationFrame` のコールバック引数で、`performance.now()` は使わない。

```text
1. scenes.consumeChanged() が true なら time.discardAccumulated()   ... フレームの外（タイマーなど）で起きたシーン操作の検知
2. time.beginFrame(now)                                             ... 開発資料3章の手順1
3. while (time.consumeTick()) {                                     ... 開発資料3章の手順3
     scenes.update(time.tickLength)
     scenes.consumeChanged() が true なら time.discardAccumulated() して break
   }
4. layers.render(ctx, scenes, time.view)                            ... 開発資料3章の手順4
5. overlay があれば overlay.update(time.view.realDelta) → overlay.draw(ctx)  ... 開発資料3章の手順5
6. requestAnimationFrame で次のフレームを予約
```

`requestAnimationFrame` の予約をフレームの最後に置くので、シーンのメソッドで例外が起きるとループは止まり、最初のエラーだけがコンソールに残る。

### 要件1: ループと時間（タスク1 `Time`、タスク4 `GameLoop`）
`Time` は DOM にも他モジュールにも依存しない。次の内部APIを持つ。

| メンバー | 内容 |
| --- | --- |
| `constructor(tickRate)` | `tickLength = 1000 / tickRate`、`timeScale = 1`、`gameTime = 0` |
| `beginFrame(now)` | 前回の `now` との差を `realDelta` にする（初回は `0`、負の値は `0` に丸める）。スキップ指定があれば、`realDelta` の更新だけ行って指定を解除する。なければ `gameDelta = min(realDelta × timeScale, tickLength × 5)` を計算し、蓄積と `gameTime` の両方に同じ値を足す |
| `consumeTick()` | 蓄積が `tickLength` 以上なら `tickLength` を引いて `true`、未満なら `false` を返す |
| `discardAccumulated()` | 蓄積を `0` にし、次の `beginFrame` のスキップを指定する |
| `tickLength` | getter |
| `timeScale` | getter / setter。setter は有限の数値かつ `0` 以上でなければ `RangeError` を投げる |
| `view` | `draw` に渡す読み取り専用オブジェクト。下記 |

* **上限の掛け方:** 上限はそのフレームで足す量（`gameDelta`）に掛ける。これにより蓄積と `gameTime` が同じ量だけ進み、「`gameTime` も同じ上限に従う」を1か所で満たせる。前フレームの端数は1ティック未満なので、1フレームのティックは最大5回である。
* **`realDelta` は丸めない:** タブから戻った直後は大きな値になる。実時間の差分という定義どおりとする。
* **`view`:** `realDelta`・`gameTime`・`timeScale` の getter だけを持つオブジェクトを constructor で1つ作り、`Object.freeze` して使い回す。`Time` 本体を `draw` へ渡すと内部操作を呼べてしまい、代入可能なオブジェクトを渡すと描画中に状態を変更できてしまうためである（憲法3章「ロジックと描画の分離」）。ES Modules は strict mode なので、`view` への代入は `TypeError` になる。
* **`dt`:** `update(dt)` の `dt` は常に `tickLength` で、`timeScale` の影響を受けない。`timeScale` を小さくすると、ティックの回数が減る。

### 要件2: 画面（タスク3 `Screen`）
* `constructor(canvas, width, height)` で `canvas.width` / `canvas.height` を設定し、表示サイズを合わせ、`window` の `resize` を登録する。解除の処理は作らない（ループを止めるAPIがないため）。
* 表示サイズは `scale = min(innerWidth / width, innerHeight / height)` で求め、`canvas.style.width` / `canvas.style.height` に `Math.floor(width * scale)px` / `Math.floor(height * scale)px` を設定する。`canvas.width` / `canvas.height` は起動時の1回だけ設定する（代入すると `ctx` の状態が初期化されるため）。
* 縦横比の計算を JS で行うのは、解像度を CSS に固定値で書かずに済ませるためである。中央寄せと余白の黒は `index.html` の CSS で行う。
* 座標変換は作らない。

### 要件3: レイヤー（タスク3 `Layers`、タスク2 `Scenes`）
`Layers` は `constructor(names)`（配列をコピーして保持）と `render(ctx, scenes, time)` を持つ。`scenes` は引数で受け取り、import しない。

```text
ctx.clearRect(0, 0, ctx.canvas.width, ctx.canvas.height)
names の順に layer を走査:
  scenes.forEachFromBottom(scene => { ctx.save(); scene.draw(ctx, layer, time); ctx.restore(); })
```

消去は `clearRect` で透明にする（背景色をエンジンに持たせないため）。透けた部分には `index.html` の CSS の黒が見える。

### 要件4: シーン（タスク2 `Scene`・`Scenes`）
`Scene` は `init()`・`update(dt)`・`draw(ctx, layer, time)`・`destroy()` を持ち、中身はすべて空とする。`onPointer` は作らない。

`Scenes` は `Time` を import しない。次の内部APIを持つ。

| メソッド | 内容 |
| --- | --- |
| `push(scene)` | スタックに積み、`scene.init()` を呼び、変更フラグを立てる（`init` の前に積む） |
| `pop()` | 空なら何もしない（フラグも立てない）。空でなければ最前面を外して `destroy()` を呼び、フラグを立てる |
| `change(scene)` | 最前面から順に全シーンを外して `destroy()` を呼び、`push(scene)` する |
| `update(dt)` | 最前面のシーンの `update(dt)` を呼ぶ。空なら何もしない |
| `forEachFromBottom(callback)` | スタックの下から順に `callback(scene)` を呼ぶ。空なら何もしない |
| `consumeChanged()` | 変更フラグを返し、`false` に戻す |

* **時間スパイク対策:** `GameLoop` が `consumeChanged()` を見て `time.discardAccumulated()` を呼ぶ。ティックの途中で操作が起きたらループを抜けるので、残りのティックは回らず、次のフレームの差分も蓄積に入らない。ティックの外（タイマーなど）で操作が起きた場合は次のフレームの先頭で検知するので、そのフレームの差分が蓄積に入らず、ティックも回らない。
* **スタックが空のとき:** シーンのメソッドは何も呼ばれず、エラーにならない。ループは動き続け、画面の消去と FPS の表示は続く。タイマーなどから `Engine.pushScene` を呼べば再開できる。
* **シーン操作を呼んでよい場所:** `update` の中と、フレーム処理の外（タイマー、Promise の完了時など）とする。`draw` の中では呼ばない（REQの指定）。`init`・`destroy` の中でも呼ばない（`change` がスタックを空にしている途中に割り込むと、順序が定まらないため）。これらの禁止を実行時に検出する処理は作らず、`oz/ENGINE_API.md` に書くだけとする。

### 要件5: デバッグ表示（タスク3 `DebugOverlay`）
* `debug` が無効なら `Engine` は `DebugOverlay` を生成せず、`GameLoop` は呼ばない。
* `update(realDelta)` はフレーム数と経過時間を足し、経過時間が 1000 ミリ秒以上になったら `Math.round(フレーム数 × 1000 / 経過時間)` を表示値にして、両方を `0` に戻す。時間は引数だけで受け取る。
* `draw(ctx)` は `save` / `restore` の中で、左上の (8, 8) に `FPS: <値>` を描く（最初の計算が終わるまでは `FPS: --`）。設定は `16px monospace`、`textBaseline = 'top'`、黒の縁取り（`strokeText`）と白の塗り（`fillText`）とする。描画中に状態を変更しない。

### 要件6: 起動設定（タスク5 `Engine`）
`Engine` は次の公開APIを持つオブジェクトとして `export const` で定義する。実行中の状態（`Time` と `Scenes`）はモジュール内の変数に持ち、`Engine` のプロパティとしては公開しない。

| 公開API | 内容 |
| --- | --- |
| `Engine.start(config)` | 設定を検証して起動する。2回呼ぶとエラー。戻り値なし |
| `Engine.changeScene(scene)` | スタックを全部外して1つ積む |
| `Engine.pushScene(scene)` | 上に積む |
| `Engine.popScene()` | 最前面を外す |
| `Engine.timeScale` | getter / setter |

起動の順序は、(1) 設定の検証、(2) `Screen` 生成、(3) `canvas.getContext('2d')`、(4) `Time`・`Scenes`・`Layers`・（`debug` なら）`DebugOverlay`・`GameLoop` の生成、(5) `Time` と `Scenes` をモジュール変数に保持、(6) `scenes.push(config.scene)`、(7) ループ開始とする。(5) を (6) より先に行うのは、シーンの `init` から `Engine.timeScale` を使えるようにするためである。

| 項目 | 検証 | 失敗時のエラー（`Error`、先頭に `[oz] Engine.start:` を付け、項目名を含める） |
| --- | --- | --- |
| `canvas` | 必須。`getContext` 関数を持つ | canvas 要素が渡されていない（`querySelector` の結果が `null` の場合も含む） |
| `width` / `height` | 必須。正の有限数 | 論理解像度が正しくない |
| `layers` | 必須。空でない配列 | レイヤー名の配列が渡されていない |
| `scene` | 必須。`instanceof Scene`（クラスそのものを渡した場合も失敗する） | Scene のインスタンスが渡されていない |
| `tickRate` | 任意（既定 60）。指定時は正の有限数 | tickRate が正しくない |
| `debug` | 任意（既定 `false`）。`Boolean()` で判定 | なし |

`changeScene` と `pushScene` の引数も `instanceof Scene` で検証する。`Engine.start` の前にシーン操作や `timeScale` を使ったら、原因が分かるエラーを投げる。

### 要件8: `oz/ENGINE_API.md`（タスク5）
読むだけで次の内容を実装できるようにする。`oz/src/` のファイル名や内部クラス名は書かない。

1. **概要と使えるもの:** `import { Engine, Scene } from 'oz'` の2つだけであること。実行には静的サーバが必要なこと。
2. **`index.html` の書き方:** import map、canvas、`js/main.js` の読み込み、中央寄せと黒の余白の CSS の完全な例。canvas の表示サイズはエンジンが設定するので CSS で指定しないこと。
3. **`Engine.start`:** 設定の表（必須・任意、既定値、内容）。不正な設定はエラーになること。2回呼べないこと。最小の起動例（`new Scene()` とレイヤー1枚）。
4. **画面:** `width` / `height` が Canvas の解像度と描画の座標になること。原点は左上。表示はウィンドウに収まる最大の大きさに自動で合わせられ、縦横比は保たれること。キャンバスは毎フレーム透明に消去され、シーンが描かない部分にはページの背景が見えること。
5. **シーンの作り方:** `Scene` を継承し、`init()`・`update(dt)`・`draw(ctx, layer, time)`・`destroy()` を必要なものだけ書くこと。呼ばれるタイミングの表。`new Scene()` は何も描かないシーンとして使えること。シーンを積むたびに新しいインスタンスを作ること。動くシーンの短い例。
6. **シーンの操作:** `Engine.changeScene`・`Engine.pushScene`・`Engine.popScene`。`destroy` と `init` の呼ばれる順序。積むと背面は `update` だけが止まり `draw` は続くこと、戻すと `update` が再開すること。ポーズは専用APIではなくシーンを積んで作ること。
7. **操作を呼んでよい場所:** `update` の中と、フレーム処理の外（タイマー、Promise の完了時など）。`draw`・`init`・`destroy` の中では呼ばないこと。
8. **操作の直後の時間:** 操作のあったフレームでは残りのティックが回らず、次のフレームの経過時間も進まないので、動きが飛ばないこと。
9. **スタックが空のとき:** `popScene` で空になってもエラーにならず、シーンのメソッドは何も呼ばれないこと。空のスタックへの `popScene` は何もしないこと。画面は消去され続けること。`pushScene` や `changeScene` で再開できること。
10. **レイヤーの重なり方:** `layers` の順に奥から手前へ描かれること。シーンの中の描く順序には左右されないこと。`layers: ['bg', 'fg']`、スタック `[A, B]` の場合の呼び出し順 `A/bg → B/bg → A/fg → B/fg` を示し、手前のシーンの奥のレイヤーは、奥のシーンの手前のレイヤーより先に描かれること（全体を覆いたいシーンは手前のレイヤーに描くこと）を書く。`draw` の呼び出しごとに `ctx` の状態が保護されること。
11. **時間:** `update(dt)` の `dt`（ティック長のミリ秒、`timeScale` の影響を受けない）。`time` の表（`realDelta`・`gameTime`・`timeScale`）。`time` は読み取り専用であること。1フレームの進行の上限は5ティック分で、タブを裏に回してから戻しても飛ばないこと（`gameTime` も同じ上限に従い、`realDelta` は丸められないこと）。
12. **`timeScale`:** `Engine.timeScale` の読み書き。`1` が等速、小さくすると遅くなり、`0` なら `update` は呼ばれず `draw` は続くこと。負の値や数値以外はエラーになること。描画の補間はしないので、小さくするとティック単位で段階的に動くこと。
13. **動きの指針:** 動きは `update(dt)` で進め、`time.gameTime` は周期的な動き（`Math.sin` など）に使うこと。`update` の中で描画せず、`draw` の中で状態を変更しないこと。`ctx` の状態を変更するときは `save` / `restore` を対で使うこと。
14. **`debug`:** `true` なら FPS が最前面に表示されること。実行中には切り替えられないこと。
15. **例外:** シーンのメソッドで例外が起きるとループが止まり、コンソールにエラーが残ること。

今回作っていない機能（入力、ボタン、アセット、サウンド、セーブ）は載せない。

## 5. 懸念事項・要確認ポイント
* **憲法の検証コマンドは差し替え済み（発注者の承認済み）:** 計画立案時に Node v24.15.0 で試したところ、`package.json` のないフォルダでは、`export` や `import` を含む `.js` の構文エラーを `node --check <ファイル>` が検出せず、終了コード0で終わった（例: `export function f() { return 1 +; }`）。`node --input-type=module --check < <ファイル>` なら検出する。発注者の承認により、憲法1章の検証コマンドは `node --input-type=module --check < <変更した .js ファイル>` に差し替え済みである。本計画ではこのコマンドだけを使う。
* **発注者承認済みの仕様（REQに明記がなく、計画で決めたもの）:**
    *   `init`・`destroy` の中のシーン操作も禁止とした（REQの明記は `draw` のみ）。
    *   シーンのメソッドで例外が起きるとループが止まる（毎フレーム同じエラーが出続けるのを避ける）。
    *   `Engine.start` の2回目はエラーとした。
    *   負の値や数値以外の `timeScale` はエラーとした。
    *   上限を「そのフレームで足す量」に掛けた（phaseout は蓄積全体に掛けている）。1フレーム最大5ティックは同じである。
    *   タブから戻った直後の `realDelta` は丸めない。このため、戻った直後の1回は FPS の表示値が低くなる。
    *   `changeScene`・`pushScene` の引数を `instanceof Scene` で検証する。
    *   `Engine.start` の前にシーン操作や `timeScale` を使ったらエラーを投げる。
    *   `tickRate` を指定したときは正の有限数であることを検証する。
* **現場設計AIの判断で進める内部構造の変更（開発資料3章の依存図の組み替え）:** `Engine` がすべてのモジュールを import して `GameLoop` へ引数で渡す形に組み替え、未実装の `Input`・`Buttons` の図上の位置も `Engine` の先へ移す。公開APIと動作に影響せず、逆向きの import も生じない。Phase 01-02 の `Input`・`Buttons` の配置もこの形を前提にする。
* **目視確認が必要な項目（実装AIはブラウザで確認できない）:** すべてのタスクの完了後に、静的サーバで `index.html` を開いて確認する。
    1. 赤、緑、青の3つの正方形が左右を行き来し、常に重なり合い、手前から青、緑、赤の順に見える。
    2. 端から端まで約4秒で動く（ストップウォッチで確認）。リフレッシュレートの異なる画面でも同じ速さである。
    3. タブを裏に回して戻しても、図形が大きく飛ばない。
    4. ウィンドウの大きさを変えると、Canvas が縦横比を保ったまま最大の大きさに追従し、中央に寄り、余白が黒い。スクロールバーが出ない。
    5. `?debug` を付けると FPS が最前面に表示され、付けないと表示されない。
