1フレームの処理（`GameLoop.#frame`）は次の順序とする。

```text
1. scenes.consumeChanged() が true なら time.discardAccumulated()   ... フレームの外で起きたシーン操作の検知（従来どおり）
2. time.beginFrame(now)                                             ... 開発資料3章の手順1
3. input.dispatch()                                                 ... 開発資料3章の手順2（新設）
4. scenes.consumeChanged() が true なら time.discardAccumulated()   ... 配信の中で起きたシーン操作の検知（新設）
5. while (time.consumeTick()) {                                     ... 開発資料3章の手順3（従来どおり）
     scenes.update(time.tickLength)
     scenes.consumeChanged() が true なら time.discardAccumulated() して break
   }
6. layers.render(ctx, scenes, time.view)                            ... 従来どおり
7. overlay があれば overlay.update(...) → overlay.draw(ctx)         ... 従来どおり
8. requestAnimationFrame で次のフレームを予約                        ... 従来どおり
```

* **手順4で分岐を増やさない:** `discardAccumulated()` は蓄積を `0` にし、次の `beginFrame` のスキップを指定する。蓄積が `0` なら手順5の `consumeTick()` は `false` を返すので、そのフレームのティックは回らず、次のフレームの `realDelta` も蓄積に入らない。`Time` は変更しない。
* **`Input` は `Time` を知らない:** シーン操作の検知は既存の `Scenes` の変更フラグを `GameLoop` が見る形で行う。
* **`draw` から入力の処理が呼ばれない:** `input.dispatch()` を呼ぶのは手順3だけである。ブラウザのイベントの中でも呼ばない。
* **例外:** `onPointer`・`onKeyDown`・`onPress` の例外は捕まえない。手順8に届かないのでループが止まり、コンソールにエラーが残る（`update`・`draw` と同じ）。
* **`timeScale` の変更:** 手順3で変更すると、手順2で足した分はそのまま残る。新しい値は次のフレームの `beginFrame` から効く。×0 にしたフレームに、蓄積済みの分のティックが回ることがある。

### 要件1: 入力の配信の順序（タスク2 `Input`、タスク3 `GameLoop`）
`Input` の処理は、受信と配信の2段階に分ける。

* **受信（ブラウザのイベントの中）:** イベントを内部の配列 `#queue` に届いた順に積むだけとする。シーンやボタンのメソッドを呼ばない。
* **配信（`dispatch()`）:** `#queue` を取り出して空にし、キーの状態を確定してから（要件3）、取り出した配列を先頭から順に配る。

```js
dispatch() {
  const events = this.#queue;
  this.#queue = [];
  this.#confirmKeys(events);
  for (const event of events) this.#deliver(event);
}
```

* 最前面のシーンは、イベントごとに `scenes.top` で取り直す。これにより、配信の途中でシーン操作が起きても、残りの入力は新しい最前面のシーンへ届く。
* `scenes.top` が `null`（スタックが空）のとき、配る先のない入力は捨てる。キーの状態と押下の状態の更新は続ける。
* `Input` は `performance.now()`、`Date`、`event.timeStamp` を使わない。

`#queue` の要素は次のとおりとする。

| `kind` | 他の項目 | 積むタイミング |
| --- | --- | --- |
| `'pointer'` | `type`（`'down'`・`'move'`・`'up'`）、`x`、`y`（論理座標） | 要件2 |
| `'keydown'` | `code` | `keydown` で `repeat` が偽のとき |
| `'keyup'` | `code` | `keyup` |
| `'blur'` | なし | `window` の `blur` |

### 要件2: ポインタ（タスク1 `Screen`、タスク2 `Input`）
**`Screen.toLogical(clientX, clientY)`** は `{ x, y }` を返す。Pointer Events の `clientX`・`clientY` を受け取り、canvas の `getBoundingClientRect()` を使って次の式で変換する。呼ぶたびに矩形を取るので、ウィンドウの大きさを変えてもずれない。範囲を超えた値は丸めない。

```text
x = (clientX - rect.left) * 論理幅 / rect.width
y = (clientY - rect.top) * 論理高さ / rect.height
```

`Screen` のファイルは既存の書き方（`_canvas` などの `_` 付きメンバー）に合わせる。先頭の責務定義の「座標変換は現時点では未実装」は、座標変換を担う内容に書き換える。

**論理座標への変換は受信時に行う。** 溜めている間にウィンドウの大きさが変わっても、押した時点の位置が保たれるためである。

**`Input` のコンストラクタ** は次を行う。

* `canvas.style.touchAction = 'none'` を設定する。
* canvas に `pointerdown`・`pointermove`・`pointerup` を同じハンドラで、`pointercancel`・`lostpointercapture` を別の同じハンドラで登録する。
* `window` に `keydown`・`keyup`・`blur` を登録する。
* 解除の処理は作らない（`Screen` と同じく、ループを止めるAPIがないため）。

**ポインタのハンドラ** は、次の順に判定する。押下中のポインタを `#pressedId`（押していないときは `null`）で持つ。

```js
#onPointerEvent(e) {
  if (!e.isPrimary) return;
  if (this.#pressedId !== null && e.pointerId !== this.#pressedId) return;
  const { x, y } = this.#screen.toLogical(e.clientX, e.clientY);
  this.#lastX = x;
  this.#lastY = y;
  const mainPressed = (e.buttons & 1) !== 0;
  if (this.#pressedId === null) {
    if (e.button === 0 && mainPressed) {
      this.#pressedId = e.pointerId;
      this.#canvas.setPointerCapture(e.pointerId);
      this.#enqueuePointer('down', x, y);
      return;
    }
  } else if (!mainPressed) {
    this.#pressedId = null;
    this.#enqueuePointer('up', x, y);
    return;
  }
  if (e.type === 'pointermove') this.#enqueuePointer('move', x, y);
}
```

この形にする理由は次のとおりである。`e.type === 'pointerup'` と `e.button === 0` だけで判定すると、次の場面で誤動作する。

| 場面 | ブラウザが送るもの | 結果 |
| --- | --- | --- |
| 左を押したまま右を押し、左だけ離す | 左を離したときは `pointerup` ではなく `pointermove`（`button: 0`、`buttons: 2`） | `buttons` の第0ビットで見るので `'up'` になる |
| 右を押したまま左を押す | 左を押したときは `pointerdown` ではなく `pointermove`（`button: 0`、`buttons: 3`） | `button === 0` かつ第0ビットで `'down'` になる |
| canvas の外で左を押してから canvas へ入る | `pointermove`（`button: -1`、`buttons: 1`） | `button` が `0` でないので `'down'` にならず、`'move'` になる。そのあと離しても `'up'` にならない |
| 右だけ押す、右だけ離す、中ボタン | `pointerdown`・`pointerup`（`button: 2` など、`buttons` の第0ビットは `0`） | 何も届かない |
| マウスとタッチを同時に使う（どちらも `isPrimary` が真になる） | 押していないマウスの `pointermove`（`buttons: 0`） | `#pressedId` と違うので捨てる。タッチの押下は切れない |
| 離す操作を受け取れなかった | 次の `pointermove`（`buttons: 0`） | `'up'` を作るので押しっぱなしにならない |

**`pointercancel`・`lostpointercapture` のハンドラ:** `e.pointerId === #pressedId` のときだけ、`#pressedId` を `null` にして、`'up'` を積む。座標は `#lastX`・`#lastY` を使う（これらのイベントの座標は当てにできないため）。押していないときは何もしない。通常の `pointerup` の後は `#pressedId` が `null` なので、続く `lostpointercapture` では何も起きない。

`lostpointercapture` も受けるのは、押下中のポインタの離す操作を受け取れなかった場合の救済のためである。タッチは接触ごとに `pointerId` が変わるので、`#pressedId` が残ると以後のタッチがすべて捨てられ、再読み込みするまで入力できなくなるおそれがある。

**連続した `'move'` をまとめる:** `#enqueuePointer` は、`type` が `'move'` で `#queue` の最後の要素も `'move'` のポインタなら、最後の要素を置き換える。`'down'`・`'up'` やキーの要素を挟むとまとめない。

**`preventDefault` は呼ばない。** スクロールと拡大は `touch-action` で止める。右クリックのメニューも止めない。

**配信（`#deliver` のポインタの部分）** は次のとおりとする。ボタンが消費した押下を `#consumed` で持つ。

```js
#deliverPointer({ type, x, y }) {
  const top = this.#scenes.top;
  if (type === 'down') {
    const button = top ? this.#buttons.find(top, x, y) : null;
    this.#consumed = button !== null;
    if (button) {
      const { onPress } = button;
      onPress();
      return;
    }
  } else if (this.#consumed) {
    if (type === 'up') this.#consumed = false;
    return;
  }
  if (top) top.onPointer({ type, x, y });
}
```

* `#consumed` はシーンに結び付けない。`onPress` の中でシーンが変わっても、その押下の `'move'` と `'up'` は新しいシーンにも届かない。
* `onPress` は `button` から取り出して呼ぶ（`this` として内部のデータを渡さないため）。引数は渡さず、戻り値は使わない。
* `onPointer` の戻り値は使わない。
* ボタンで消費していない押下の最中に最前面のシーンが変わると、新しいシーンには `'down'` のない `'move'`・`'up'` が届く（REQの指定どおり、`oz/ENGINE_API.md` に書く）。

### 要件3: キーボード（タスク2 `Input`、タスク3 `Engine`）
受信では `e.code` を積むだけとする。`e.repeat` が真の `keydown` は積まない。`preventDefault` は呼ばない。キー割り当ての固定値を持たない。

**`isKeyDown` の値は、`dispatch()` の最初に、そのフレームの全イベントについて一度に確定する。** 配信しながら順に更新すると、同じフレームの `onKeyDown` の間で `isKeyDown` の値が変わり、「1フレームの間は変わらない」を満たせないためである。確定は配信の前に終わるので、そのフレームのどの `onKeyDown` からも、同じ値が見える。

押している状態を `#keysDown`（`Set`）で持つ。同じフレームの中で押して離したキーのために、次のフレームの確定で外すキーを `#releaseNext`（`Set`）で持つ。

```js
#confirmKeys(events) {
  for (const code of this.#releaseNext) this.#keysDown.delete(code);
  this.#releaseNext.clear();
  const pressedNow = new Set();
  const release = (code) => {
    if (pressedNow.has(code)) this.#releaseNext.add(code);
    else this.#keysDown.delete(code);
  };
  for (const event of events) {
    if (event.kind === 'keydown') {
      this.#keysDown.add(event.code);
      pressedNow.add(event.code);
      this.#releaseNext.delete(event.code);
    } else if (event.kind === 'keyup') {
      release(event.code);
    } else if (event.kind === 'blur') {
      for (const code of this.#keysDown) release(code);
    }
  }
}
```

| 同じフレームの中のイベント | `onKeyDown` | そのフレームの `isKeyDown` | 次のフレームの `isKeyDown` |
| --- | --- | --- | --- |
| 押す | 1回 | `true` | `true` |
| 押す → 離す | 1回 | `true` | `false` |
| 押す → 離す → 押す | 2回 | `true` | `true` |
| 離す（前のフレームから押している） | なし | `false` | `false` |
| `blur`（前のフレームから押している） | なし | `false` | `false` |
| 押す → `blur` | 1回 | `true` | `false` |

* `blur` は、押している全部のキーを離す操作として扱う。同じフレームに押したキーは、離す操作と同じ規則で次のフレームに外れる。
* `#deliver` のキーの部分は、`'keydown'` のときだけ最前面のシーンの `onKeyDown(code)` を呼ぶ。`'keyup'`・`'blur'` はシーンへ配らない。
* すでに押している状態のキーに、`repeat` が偽の `keydown` が来たら、`onKeyDown` を呼ぶ（離す操作を受け取れなかった場合に、新しい押下を落とさないため）。
* `Input.isKeyDown(code)` は `#keysDown.has(code)` を返す。文字列以外や未知のコードは `false` になる。

### 要件4: ボタン（タスク1 `Buttons`、タスク3 `Engine`）
`Buttons` は他のモジュールを import せず、DOM にも時間にも触れない。シーンをキーとする `WeakMap` にボタンの配列を持つ（スタックから外れたシーンの登録を残さないため）。

| メソッド | 内容 |
| --- | --- |
| `add(scene, { x, y, width, height, onPress })` | シーンのボタンの配列の末尾に追加する。値はコピーして持つ（登録後に元のオブジェクトを変更しても影響しない）。引数は検証しない（`Engine` が検証する） |
| `find(scene, x, y)` | シーンのボタンを後に登録したものから順に調べ、`x <= px < x + width` かつ `y <= py < y + height` を満たす最初のボタンを返す。なければ `null` を返す |

* `Buttons` は `onPress` を呼ばない（配信は `Input` の責務）。
* 最前面のシーンだけを調べるので、背面のシーンのボタンは反応せず、戻ると再び反応する。スタックから外れたシーンのボタンは調べられない。

**`Engine.addButton(scene, button)`** は次の順に検証し、失敗したら `[oz] Engine.addButton:` で始まり項目名を含む `Error` を投げる。

| 順 | 検証 | 失敗の内容 |
| --- | --- | --- |
| 1 | 起動済み | `Engine.start` の前には使えません |
| 2 | `scene instanceof Scene`（既存の `validateScene` を使う） | scene が渡されていない |
| 3 | `button` が `null` でないオブジェクト | ボタンの設定が渡されていない |
| 4 | `x`・`y` が有限の数値 | x / y が正しくない |
| 5 | `width`・`height` が正の有限数（既存の `isPositiveFinite` を使う） | width / height が正しくない |
| 6 | `onPress` が関数 | onPress が関数でない |

**`SampleScene`**（`constructor(variant, shapes)`。`variant` は色違いの番号 `0` か `1`）

| 色違い | 背景の色 | ボタンの先頭の x |
| --- | --- | --- |
| `0` | `#16213e` | `40` |
| `1` | `#3b1f2b` | `660` |

* **`init()`:** 3つのボタンを `Engine.addButton(this, ...)` で登録し、描画のために位置を `this` に持つ。ボタンは `init` で登録する（`config.scene` は `Engine.start` の前に作るので、constructor では呼べない）。
* **`update(dt)`:** 従来の図形の移動のまま変えない。
* **`onPointer(pointer)`:** 状態だけを更新する。
    * `'down'`: ボタンの外を押した回数を増やす。押した位置を記録し、跡を空にし、離した位置を消す。
    * `'move'`: 跡の配列の末尾に位置を足す。40個を超えたら先頭を捨てる。
    * `'up'`: 離した位置を記録する。
* **`onKeyDown(code)`:** キーを押した回数を増やす（どのキーでも増える）。`Digit1`・`Digit2`・`Digit3` なら、それぞれ速さの変更、切り替え、積むを実行する。`Escape` の分岐は書かない（元のシーンでは回数が増えるだけで、何も起きない）。
* **操作の処理:** ボタンとキーで同じメソッドを呼ぶ。
    * 速さ: `SPEED_STEPS = [1, 0.25, 0]` のうち、`Engine.timeScale` の次の値を代入する。
    * 切替: `Engine.changeScene(new SampleScene(1 - this.variant, this.shapes))`。`shapes` を同じ配列のまま渡すので、図形の位置と向きが引き継がれる。
    * 積む: `Engine.pushScene(new SampleOverlayScene())`。
* **`draw(ctx, layer, time)`:** 状態を変更しない。`Engine.isKeyDown('Space')` と `time.timeScale` は読むだけである。
    * `back` レイヤー: 背景の色で画面全体を塗る。そのあと該当する図形を描く。
    * `middle` レイヤー: 該当する図形を描く。
    * `front` レイヤー: 該当する図形、ボタン、説明の文字、ポインタの印の順に描く。
    * 図形の色は `Engine.isKeyDown('Space')` が真なら `pressedColor`、偽なら `color` とする。
    * ボタンの文字は `速さ ×<現在の倍率> [1]`、`切替 [2]`、`積む [3]` とする。倍率は `time.timeScale` を使う。
    * 説明の文字は `押した位置: (x, y)`（四捨五入。まだ押していなければ `-`）、`ボタンの外を押した回数: n`、`キーを押した回数: n`、`Space を押している間は図形の色が変わる` の4行とする。
    * ポインタの印は、押した位置に十字（中心から±12）、跡の各点に半径3の丸（塗り）、離した位置に半径12の丸（線）を描く。

**`SampleOverlayScene`**（積んだ画面）

* **`init()`:** `戻す` のボタンを登録する。`onPress` は `Engine.popScene()` を呼ぶ。
* **`onPointer(pointer)`:** `'down'` のときだけ、この画面でボタンの外を押した回数を増やす。
* **`onKeyDown(code)`:** `Escape` のときだけ `Engine.popScene()` を呼ぶ。
* **`update(dt)`:** 書かない。
* **`draw(ctx, layer, time)`:** `front` レイヤーだけに描く。画面全体を `rgba(0, 0, 0, 0.5)` で塗り、`戻す [Esc]` のボタンと、`積んだ画面`、`この画面でボタンの外を押した回数: n` の文字を描く。

**共通の関数** `drawSampleButton(ctx, button, label)` は、ボタンの矩形と文字を描く。`ctx` の状態を変更する描画は `save` / `restore` で囲む。

16. **ポインタ入力:**
    * `onPointer(pointer)` の `pointer` は `{ type, x, y }` である。`type` は `'down'`・`'move'`・`'up'`、`x`・`y` は描画と同じ論理座標である。戻り値は使わない。
    * 最前面のシーンだけに届く。
    * マウス、タッチ、ペンを同じように扱う。主ポインタの主ボタンだけを扱い、マルチタッチ、右クリック、中クリックは扱わない。
    * 押さずにマウスを動かしても `'move'` が届く。連続した `'move'` は1フレームに1つにまとめられることがある。
    * 押したまま canvas の外へ出ても `'up'` が届く。このとき `x`・`y` は論理解像度の範囲外の値になることがある。
    * 押下の中断も `'up'` として届く。
    * タッチでページがスクロールや拡大をしないように、エンジンが canvas の `touch-action` を `none` に設定する。
    * 座標がずれるので、canvas の CSS に `border`・`padding` を付けない。
    * 押下を受けたシーンの操作で最前面のシーンが変わると、新しいシーンには `'down'` のない `'move'`・`'up'` が届くことがある。
    * 短いコード例を載せる。
17. **キーボード入力:**
    * キーは `KeyboardEvent.code` の文字列（`'Space'`、`'KeyA'`、`'Digit1'`、`'Escape'` など）で指定する。
    * `onKeyDown(code)` は押した瞬間に、最前面のシーンだけに届く。キーリピートでは呼ばれない。
    * `Engine.isKeyDown(code)` は押している間 `true` を返す。どのメソッドの中からでも呼べる（`Engine.start` の前はエラー）。値は入力を確定するときだけ変わり、1フレームの間は変わらない。
    * 押してから離すまでが1フレームより短くても、`onKeyDown` は必ず呼ばれ、そのフレームの間は `isKeyDown` が `true` になり、次のフレームで `false` になる。
    * `isKeyDown` は実時間のフレーム単位で変わるため、`timeScale` が小さいときは、ティックの間に押して離したキーが `update` から見えないことがある。取りこぼしたくない操作は `onKeyDown` を使う。
    * ウィンドウからフォーカスが外れると、押している状態はすべて解除される。
    * ブラウザの既定の動作（F5、F12 など）は止めない。
    * 短いコード例を載せる。
18. **ボタン:**
    * `Engine.addButton(scene, { x, y, width, height, onPress })` の各項目（論理座標、`width`・`height` は正の有限数、`onPress` は引数なしで呼ばれる関数）を書く。不正な引数はエラーになる。`Engine.start` の前はエラーになる。
    * `init` の中で登録する（最初のシーンの `init` でも使える）。constructor の中では、`Engine.start` の前に作るシーンで使えない。
    * ポインタの `'down'` の位置が矩形の内側なら `onPress()` が呼ばれる。その押下は、離すまでの `'move'`・`'up'` も含めて、シーンの `onPointer` に届かない。`onPress` の中でシーンが変わっても、新しいシーンにも届かない。
    * 左端と上端を含み、右端と下端を含まない。重なっている場合は、後に登録したものだけが反応する。
    * 反応するのは最前面のシーンのボタンだけである。背面になると反応せず、戻ると再び反応する。スタックから外れたシーンのボタンは反応しない。
    * エンジンはボタンを描かない。利用側がシーンの `draw` で描く。
    * 削除、移動、有効無効の切り替えはできない。
    * `draw` を含む短いコード例を載せる。
19. **入力の届くタイミングと順序:**
    * 入力は `timeScale` に関係なく毎フレーム1回、`update` の前に届く。`timeScale` が `0` の間も届き、スロー中も遅れない。
    * `onPointer`・`onKeyDown`・`onPress` は、`draw` の中やブラウザのイベントの中からは呼ばれない。
    * 1フレームの順序（時間を進める → 届いた順に入力を配る → `update` を0回以上 → `draw`）を書く。
    * ポインタはボタン → 最前面のシーンの順に、キーは最前面のシーンに届く。

    *   入力の配信の中で変更した `timeScale` は、次のフレームの時間から効く。×0 にしたフレームに、蓄積済みの分の `update` が回ることがある。
    *   積んだ画面の間も、`Space` による背面の図形の色の変化は働く（`isKeyDown` はシーンを問わないため）。
    *   回数の表示はシーンごととする。切り替えると新しいシーンの回数は `0` から始まる。積んだ画面はボタンの外を押した回数だけを表示し、キーの回数と印は表示しない。
* **開発資料3章の依存図の変更:** 現在の図は `Input → Screen` を例外として認めているが、インスタンスを引数で受け取るので import が不要になる。REQの「`Input` が import してよいのは `Screen` だけ」の範囲内である。図の例外を削除する（『開発資料の更新予定』に記載）。
