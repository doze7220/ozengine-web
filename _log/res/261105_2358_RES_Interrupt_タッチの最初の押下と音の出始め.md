# RES: 作業レポート Interrupt : タッチの最初の押下と音の出始め
* 参照元REQ: `./_log/req/261105_2358_Interrupt_タッチの最初の押下と音の出始め.md`

## 1. 作業目的
タッチの最初の押下で音の出始めが遅れる（指を離すときになる）動作を、`oz/ENGINE_API.md` 21章に追記する。

## 2. 実装内容
* 原因: タッチでは、ブラウザが指を離すまで音を出すことを認めない。`Sound` は `pointerdown`・`pointerup`・`keydown` で `resume()` を呼ぶため、タッチの最初の押下で呼んだ音は捨てられずに指を離したときに鳴る。
* 修正方針: ソースコードは変更せず、資料に動作を追記する。`oz/ENGINE_API.md` 21章の「最初の入力まで」の該当行の末尾に1文を追加し、21章末尾に「タッチの最初の押下」節を追加した。
* 事前確認: `oz/src/Sound.js` と REQ の【関連する責務】に相違はなかった。

## 3. 対象ファイル
* `./oz/ENGINE_API.md` : 更新

## 4. 詳細作業内容
* **作業内容**:
  * 21章「最初の入力まで」の `最初の入力そのものへの反応（...）の中で呼んだ分は鳴る。` の行末に、`タッチの押下では、鳴り始めが指を離すときになる（「タッチの最初の押下」を参照）。` を追加した。
  * 21章末尾（コード例の後、22章の前）に「### タッチの最初の押下」節を REQ の文面のまま追加した。
  * 【確認結果】（REQ からの転記）:
    発注者が、リポジトリの外に置いた一時的な確認用ページで確認した（確認後にサーバを停止した。ページはコミットしていない）。ページはエンジンの公開APIだけで音を鳴らし、次の2つのテストを行う。
    * テスト1: `onPointer` の `'down'` で `playSe` を1回呼ぶ。
    * テスト2: 押している間、`update` から1秒ごとに `playSe` を呼ぶ（押した瞬間には呼ばない）。指を離すと止める。

    | 環境 | テスト1 | テスト2 |
    | --- | --- | --- |
    | PC の Chrome（マウス） | 押した瞬間に鳴る | 押した瞬間は鳴らず（1秒後に最初の呼び出しがあるため）、1秒後から鳴り始める。離してもまとめて鳴らない |
    | PC の Chrome（開発者ツールのスマホモードによるタッチの再現） | 1回目は押したときに鳴らず、離したときに鳴る。2回目以降は押したときに鳴る | 押したときも押し続けても鳴らず、離したときにまとめて鳴る（発注者の耳での判断で、「判別は難しい」との補足あり） |
