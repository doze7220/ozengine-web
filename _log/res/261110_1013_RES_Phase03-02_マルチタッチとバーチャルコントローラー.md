## 2. アーキテクチャ設計

### 要件1: 役割の分担（決定事項）
*   **エンジンが持つもの:** タッチの指ごとの受信（`Input`）、指をパッドへ振り分けることと「指で触れたか」の記録（`VirtualPads`）、パッドのスティックとボタンの当たり判定・押下状態・キーへの変換・つまみの位置（`VirtualPad`）、キーボードとパッドのキーをまとめた確定（`Keys`）、表示してよいかの判定（`VirtualPads` の `touched` を `Engine.virtualPadState` の `visible` として返す）。
*   **利用側が持つもの:** 配置（位置と大きさ）とキーの割り当て（`js/ui/virtualPadConfig.js` の `VIRTUAL_PAD_LAYOUT`）、画像のファイル名とつまみの描画の大きさ（同じファイルの `VIRTUAL_PAD_LOOK`）、画像の読み込みと描画（`js/ui/virtualPadView.js`）、ON / OFF（`js/main.js`）。
*   エンジンは `assets/` を参照せず、画像を読み込まず、描かない。配置・キーの割り当て・遊びの大きさの既定値をエンジンに書かない（すべて `Engine.addVirtualPad` の引数で必須とする）。エンジンに書く定数は、斜めの判定の角度（8方向を45度ずつに分けるための `Math.sin(Math.PI / 8)`）だけで、これはゲーム固有の値ではない。

#### 公開APIの形（決定）
シーンごとの登録とする（画面のボタンと同じく、登録したシーンが最前面のときだけ反応する）。これにより、メニューを積むと自動でパッドが反応しなくなり、タイトルでは登録しないので反応しない。ON / OFF は起動設定の項目にする。`oz/index.js` の export は増やさない（`Engine` の操作として足す）。

| API | 内容 |
| --- | --- |
| `Engine.start({ ..., virtualPad })` | 任意。既定 `false`。真ならバーチャルパッドの仕組みを有効にする（`debug` と同じく `Boolean(...)` で解釈し、型の検証はしない） |
| `Engine.addVirtualPad(scene, layout)` | シーンにパッドを登録する。引数の検証は ON / OFF に関係なく行う。OFF のときは検証だけして何もしない。同じシーンへの2回目の登録はエラー（ON のときだけ判定）。`init` の中で呼ぶ（画面のボタンと同じ） |
| `Engine.virtualPadEnabled` | 読み取りのみ（getter）。起動設定で ON なら `true` |
| `Engine.virtualPadTouched` | 読み取りのみ（getter）。ON で、canvas の上を指で触れたことがあれば `true`。OFF のときは常に `false` |
| `Engine.virtualPadState(scene)` | シーンのパッドの描画用の状態の写し（毎回新しいオブジェクト）。OFF のとき、または登録していないシーンでは `null` |

*   4つの操作とも `Engine.start` の前はエラー（`[oz] <API名>: Engine.start の前には使えません`）。`scene` が `Scene` のインスタンスでないとエラー（`validateScene` を使う）。
*   `Engine.virtualPadState(scene)` の戻り値:

    ```text
    {
      visible: boolean,                 // 表示してよいか（= Engine.virtualPadTouched）
      stick: {                          // layout に stick が無ければ null
        x, y, radius,                   // 登録した値
        knobX, knobY,                   // つまみの中心（論理座標）。指が無ければ (x, y)
        active: boolean,                // 指で操作しているか
      } | null,
      buttons: [                        // layout.buttons と同じ順。無ければ空の配列
        { x, y, radius, key, pressed: boolean },
      ],
    }
    ```

*   値は入力の確定（毎フレームの配信の始め）でだけ変わり、1フレームの間は変わらない。`draw` から呼んでよい（読み取りのみ）。
*   この状態は描画のためのものである。特に `knobX`・`knobY` は描画用であり、ゲームのロジックの入力にはキー（`Engine.isKeyDown`・`onKeyDown`）を使う（アナログ値を読む API は作らない。REQ 要件2）。これを 24章に書く。

#### `layout`（`Engine.addVirtualPad` の第2引数）
| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `stick` | 任意 | スティック。`{ x, y, radius, deadZone, keys }` |
| `stick.x`・`stick.y` | 必須 | 中心の論理座標。有限の数値 |
| `stick.radius` | 必須 | 半径。正の有限数。当たり判定の円であり、つまみが動ける範囲でもある |
| `stick.deadZone` | 必須 | 遊びの大きさ。`radius` に対する割合で、`0` 以上 `1` 未満の有限の数値 |
| `stick.keys` | 必須 | `{ left, right, up, down }` のうち、使う方向だけを書いたオブジェクト（空でもよい）。値は空でない文字列（`KeyboardEvent.code`） |
| `buttons` | 任意 | ボタンの配列（空でもよい）。各要素は `{ x, y, radius, key }` |
| `buttons[i].x`・`y` | 必須 | 中心の論理座標。有限の数値 |
| `buttons[i].radius` | 必須 | 半径。正の有限数 |
| `buttons[i].key` | 必須 | 空でない文字列（`KeyboardEvent.code`） |

*   `layout`・`stick`・`stick.keys`・`buttons` の各要素に、表にない項目があるとエラー（書き間違いを見つけるため。画像のファイル名などは別のオブジェクトに書く）。`stick` が無く、`buttons` も無いか空ならエラー。`stick` に `null` を書いた場合は「無い」と同じに扱わずエラーにする（`undefined` のときだけ省略とみなす）。
*   エラーは `Error`、先頭は `[oz] Engine.addVirtualPad:`、項目名を含める（例 `stick.radius は正の有限数で指定してください`、`buttons[0].key は空でない文字列で指定してください`、`stick.keys に使えない項目 Left があります`）。
*   値はコピーして持つ。登録後に元のオブジェクトを変えても影響しない。

### 要件2: バーチャルパッドの入力はキーボードと同じに見える

#### スティックの方向とキー（`VirtualPad`）
*   スティックを操作する指の位置から中心を引いた `(dx, dy)` と、その長さ `dist = Math.hypot(dx, dy)` で判定する。指が円の外へ出ても、`(dx, dy)` は丸めずにそのまま使う。
*   `dist < deadZone * radius` なら、どの方向も押さない（遊び）。
*   それ以外は `t = dist * Math.sin(Math.PI / 8)` として、`dx > t` で右、`dx < -t` で左、`dy > t` で下、`dy < -t` で上を押す（8方向を45度ずつに分ける。斜めでは2方向が同時に押される）。`stick.keys` に割り当てのない方向は何も押さない。
*   つまみの中心 `(knobX, knobY)` は、`dist <= radius` なら指の位置、外なら `(dx, dy)` を長さ `radius` に縮めた位置（中心から半径 `radius` の円の中に収める）。指が無ければ中心。つまみの絵の大きさ（`knobRadius`）は利用側の見た目の値なのでエンジンは知らず、絵が土台の円の外へ出ないように収めるのは利用側の描画で行う（要件6「描き方」）。
*   `knobX`・`knobY` は描画用の値である。ゲームのロジックの入力にはキー（`Engine.isKeyDown`・`onKeyDown`）を使う（倒し具合の数値を読む API は作らない。REQ 要件2）。

#### ボタン（`VirtualPad`）
*   指を離すまで押したまま（指がボタンの円の外へ出ても押したまま）。同じボタンを複数の指で押したら、全部の指を離すまで押したまま。押し始めていない指が上を通っても押さない。

#### パッドの押下状態から入力の列へ（`VirtualPads`）
*   `VirtualPad` は「今パッドで押しているキーの集合」（`heldKeys()`）を返す。`VirtualPads` は指のイベントを1つ処理するたびに、その前後の集合の差から `{ kind: 'keyup', code, source: 'pad' }`（先に）と `{ kind: 'keydown', code, source: 'pad' }`（後に）を作り、指のイベントがあった位置に差し込む（届いた順を保つ）。

#### キーの確定（新 `Keys`）
キーボードとパッドの2つの入力元（`source`。キーボードは `'keyboard'`、パッドは `'pad'`）をまとめて確定する。今の `Input` の `#confirmKeys` と `#keysDown`・`#releaseNext` をここへ移し、入力元を足す。キーボードだけのときの動作は今と同じにする。

*   `confirm(events)` は、そのフレームの全イベントについて押下状態を一度に確定し、配る列（ポインタのイベントと、`onKeyDown` を呼ぶ `keydown`）を返す。`isDown(code)` は押している状態かを返す。
*   アルゴリズム（`#down: Set<string>`、`#releaseNext: Set<string>`、`#sources: Map<string, Set<string>>`）:
    1.  `#releaseNext` のキーを `#down` から外し、`#releaseNext` を空にする。`pressedNow = new Set()`、`out = []`。
    2.  `release(code)`: `pressedNow` にあれば `#releaseNext` に足し、なければ `#down` から外す（今と同じ）。
    3.  イベントを順に見る。
        *   `'keydown'`: 入力元の集合を取り（無ければ作る）、自分以外の入力元が押しているか（`heldByOther`）を先に求める。集合に自分を足し、`#down` と `pressedNow` に足し、`#releaseNext` から外す。`heldByOther` が偽なら `out` に足す。
        *   `'keyup'`: 集合が無い、または自分が集合に無ければ何もしない。自分を外し、集合が空になったら `#sources` から消して `release(code)`。
        *   `'blur'`: `#sources` の全キーを `release` し、`#sources` を空にする（キーボードもパッドも解除する）。
        *   `'pointer'`: そのまま `out` に足す。
    4.  `out` を返す。
*   キーボードだけなら、`keydown` は（キーアップを取りこぼして押したままのキーでも）今と同じく必ず配られる。キーボードで押しているキーをパッドでも押した（またはその逆）ときは `onKeyDown` を呼ばない。片方を離しても、もう片方が押していれば押したまま。

#### 時期
*   `Input.dispatch()` の中だけで、振り分け（`VirtualPads.route`）→ 確定（`Keys.confirm`）→ 配信、の順に行う。ブラウザのイベントの中ではイベントを溜めるだけ（今と同じ）。1フレームより短い押下も、`onKeyDown` と1フレームの `isKeyDown` になる（`Keys` が今の規則を引き継ぐ）。

### 要件3: マルチタッチと `onPointer`

#### 受信（`Input`、イベントの中）
*   ON（`Input` に `VirtualPads` が渡されたとき）で `pointerType === 'touch'` のポインタは、主ポインタかどうかに関係なく指ごとに扱う。`#touches: Map<number, {x, y}>`（押している指と最後の論理座標）を持つ。
    *   `pointerdown`（`button === 0`）: 登録し、`setPointerCapture`、`'down'` を溜める。
    *   `pointermove`: 登録された指なら座標を更新して `'move'` を溜める。
    *   `pointerup`: 登録された指なら消して `'up'` を溜める。
    *   `pointercancel`・`lostpointercapture`: 登録された指なら消して、最後の座標で `'up'` を溜める（`pointerup` の後の `lostpointercapture` は登録が無いので無視される）。
*   マウスとペン（ON のとき）と、OFF のときのすべてのポインタは、今の処理（主ポインタの主ボタンだけ、`#pressedId`）のまま。ペンはマウスと同じ扱いで、パッドには反応しない（決定）。
*   溜めるポインタのイベントは `{ kind: 'pointer', type, x, y, id, touch }`（`id` は `pointerId`、`touch` は `pointerType === 'touch'`）。キーボードのイベントには `source: 'keyboard'` を付ける。連続した `'move'` をまとめる規則は、「末尾が同じ `id` の `'move'` なら置き換える」に変える。

#### 振り分け（`VirtualPads.route(events, top)`、配信の中）
*   `top` は配信の始めの最前面のシーン。そのシーンに登録されたパッドを「反応するパッド」（無ければ `null`）とする。
*   最初に、指を持っているパッドのうち反応するパッドでないものを解除する（`releaseAll()`。押していたキーの `keyup` を列の先頭に入れる）。解除されたパッドの指は、離すまでそのパッドが持ち続け、何も押さない（「死んだ指」）。
*   イベントを順に見る。
    *   `'blur'`: 指を持っている全パッドを解除してから（`keyup` を足す）、`'blur'` をそのまま足す。
    *   タッチでないポインタ、キーのイベント: そのまま足す。
    *   タッチの `'down'`: まず `touched = true` にする。
    *   指がすでにパッドのもの（`#owners: Map<id, VirtualPad>` にある）なら、そのパッドの `move` / `up` を呼び、キーの差を足し、ポインタのイベントは捨てる。`'up'` なら `#owners` から消す。
    *   タッチの `'down'` で反応するパッドがあり、`pad.down(id, x, y)` が `true`（スティックかボタンの円の内側）なら、`#owners` に登録し、キーの差を足し、イベントを捨てる。
    *   それ以外はそのまま足す。
*   `touched` は、最初のタッチの `'down'` を処理するときに立つので、その指からパッドが反応する。

#### 単一ポインタの選び出し（`Input.#deliverPointer`、配信の中）
パッドが処理しなかったポインタ（マウス、ペン、パッドの外で押し始めた指）は、`onPointer` に1本だけ届ける。今の「主ポインタだけ」の動作を、パッドの指を除いた範囲で再現する。

*   `#selectedId`（届けているポインタ。無ければ `null`）と `#downIds: Set<number>`（パッドの外で押しているポインタ。選んだポインタ自身も含む）を持つ。
*   `'down'`: `#downIds` が空のときだけ選ぶ（`#selectedId = id`）。選んだかどうかに関係なく、必ず `#downIds` に足す（選んだポインタ自身も足す。これにより、選んだポインタを押している間の2本目の `'down'` では `#downIds` が空でないので、選択を奪わない）。選ばなかったポインタは、離すまで届かない。選んだときは今の処理（画面のボタン → 最前面のシーン、`#consumed`）を行う。
*   `'move'`: 選んだポインタなら今の処理（`#consumed` なら捨てる）。`#downIds` にある別のポインタなら捨てる。押していないポインタ（マウスのホバー）は、`#selectedId` が `null` のときだけ届ける。
*   `'up'`: `#downIds` から外す。選んだポインタなら `#selectedId = null` にして今の処理（`#consumed` なら戻して捨てる）。それ以外は捨てる。
*   OFF のときは、イベントの中で主ポインタ1本に絞られた列だけが来るので、上の規則でも今と同じ結果になる。ON でパッドを使っていない間（触れる前、タイトル）も、パッドの指が無いので、ブラウザの主ポインタの規則と同じ結果になる。
*   `onPointer` の `pointer` は `{ type, x, y }` のまま（`id` は渡さない）。

#### `oz/ENGINE_API.md` 16章に書く内容（タスク4・タスク5。振り分けは要件9）
*   `onPointer` は単一ポインタ。パッドの外で押しているポインタが同時に2本以上あるときは、ほかに押しているポインタ（パッドの指を除く）が無いときに押し始めた1本だけが、離すまで届く。そのあいだに押し始めたポインタは、離すまで届かない。
*   パッドが処理した指は、離すまで `onPointer` にも画面のボタンにも届かない。
*   「マルチタッチは扱わない」の記述を、上の内容に直す。右クリック・中クリックを扱わないことは残す。

### 要件4: バーチャルパッドが反応するシーン
*   反応の条件: ON、`touched` が真、配信の始めの最前面のシーンにパッドが登録されている、指のタッチである、押し始めの位置がスティックかボタンの円の内側。
*   土台では `PlayScene` だけが `init` で登録する。タイトル・ロード中は登録しないので、表示も反応もしない。メニュー（`MenuScene`）を積むと、最前面のシーンにパッドが無いので反応せず、指はメニューのボタンに届く。
*   **メニューを開いた時点で押していたパッドのキー（決定）:** 離した扱いにする。次のフレームの配信の始めに、パッドのキーの `keyup` が作られる。そのとき触れていた指は、離すまでどこにも届かず、メニューを閉じても何も押さない（指を離して押し直す）。キーボードのキーは今までどおり押したまま残る。これを 24章に書く。
*   メニューの暗幕の下にパッドの絵が見えるか: `PlayScene` が `ui` レイヤーに描き、`MenuScene` の暗幕が上に重なるので、暗く見える（問わない項目）。

### 要件5: ON / OFF と表示の条件（決定事項）
*   `js/main.js` の `config` に `virtualPad: true` を書く（目印の外）。OFF にするには `false` にする。
*   OFF: `Engine` は `VirtualPads` を作らず、`Input` は今のポインタの処理だけを行う。`Engine.addVirtualPad` は検証だけ、`Engine.virtualPadState` は `null`、`Engine.virtualPadTouched` は `false`。土台の画像の読み込み（`loadVirtualPadImages`）は `Engine.virtualPadEnabled` が偽なら何も読まない。
*   ON: 指で触れるまで `visible` は偽で、パッドは反応しない。触れた後は、そのページを開いている間ずっと真。マウスとキーボードだけの PC では偽のまま。

### 要件6: 配置と見た目（決定事項）
#### 配置の値（論理解像度 1280×720、横向きのスマートフォン）
| 部品 | 値 | 根拠 |
| --- | --- | --- |

#### 描き方（`js/ui/virtualPadView.js`）
*   `drawVirtualPad(ctx, scene)`: `Engine.virtualPadState(scene)` が `null` か `visible` が偽なら何も描かない。
*   スティックの土台は、中心 `(x, y)` に直径 `2 * radius` で描く。つまみは、指の位置 `(knobX, knobY)` を、中心 `(x, y)` から半径 `limit = radius - knobRadius` の円の中に収めた位置（clamp）に、直径 `2 * knobRadius` で描く。具体的には、ずれ `(ox, oy) = (knobX - x, knobY - y)` とその長さ `len = Math.hypot(ox, oy)` を求め、`len <= limit` ならそのまま、`len > limit` なら `(ox, oy)` に `limit / len` を掛けて縮める（`limit` が `0` 以下なら中心に描く）。これにより、つまみは円の内側では指にそのまま付いて動き、指が外へ出ても絵が土台の円の外へ出ない（REQ 要件6）。指を離すと `knobX, knobY` が中心に戻るので、つまみも戻る。
*   ボタンは、中心 `(x, y)` に直径 `2 * radius` で、`pressed` なら押している間の画像、そうでなければ通常の画像を描く。
*   `ctx` の状態を変えない（`drawImage` だけを使い、変えるなら `save` / `restore`）。

    *   スマートフォン: タイトルで画面のタップ（スタートボタンを含む）で開始できる。タイトルとロード中にはスティックとボタンが出ない。
    *   スマートフォン: プレイでスティック（左下）とボタン（右下）が出る。スティックで左右に旋回し、同時に別の指でボタンを押して加速できる（2本の指の同時操作）。スティックの指を円の外へ動かしても旋回が続き、つまみは土台の外へ出ない。指を離すとつまみが中央に戻る。ボタンは押している間、見た目が変わる。
    *   スマートフォン: スティックを操作しながら、別の指でメニューを開くボタン（上の中央）を押せる。メニューを開くとパッドのキーが離れ、機体が止まって見える（一時停止）。メニューを閉じた後、触れたままの指では旋回しない（指を離して押し直す）。
    *   メニュー: 閉じる・スロー ON/OFF・ミュート ON/OFF（表示が今の状態に変わる、ミュートは再読み込み後も保たれる）・タイトルに戻る（スローが解除される）が、指でもマウスでも押せる。項目の外を押しても何も起きない。キーボードの P で開閉、メニューの中で M・S が効く。
    *   スマートフォン: ページが縮小表示されず、長押し・2本の指の操作・黒い余白での操作で、拡大・スクロール・文字の選択・長押しのメニューが起きない（iOS の Safari と Android の Chrome）。
    *   マウスとキーボードだけの PC（ON のまま）: スティックとボタンが出ない。左右キー・Space・S・P・M、マウスでのタイトルのクリック、メニューを開くボタンのクリックが今までどおり動く。右クリックのメニューは今までどおり出る。
    *   `js/main.js` を `virtualPad: false` にした場合: スマートフォンで触れても何も出ず、`assets/images/vpad/` の画像が読み込まれない（開発者ツールのネットワーク）。PC の操作は今までどおり。
    *   キーボードとパッドで同じキー（例 `ArrowLeft` とスティックの左）を押し、片方を離しても旋回が続く（タッチ対応の PC、または開発者ツールのタッチの再現で）。
    *   目印を消した写し: リポジトリの写しを作り、手順書 `_doc/newgame/NEW_GAME_GUIDE.md` 6-2 の手順に従って目印の付いた部分を消す。その写しを、`js/main.js` の `virtualPad` が `true`（ON）のときと `false`（OFF）のときの両方でブラウザで起動し、開発者ツールのコンソールにエラーが出ないことを確かめる（憲法3章「サンプルコードの目印」、REQ 要件7。タスク10の実装AIの確認は構文と import の静的な確認だけであるため）。
*   **Chrome の開発者ツールのタッチの再現:** 再現を有効にした PC では、マウスのクリックがタッチとして扱われ、パッドが表示される。これは正しい動作である（「指で触れた」と判定されるため）。
*   **長押しのメニューの抑止:** `contextmenu` の `preventDefault` と `-webkit-touch-callout: none` で止める計画だが、ブラウザによって長押しのときのイベントの出方（`contextmenu` の前に `pointercancel` が来るか）が違う可能性がある。実機で確かめ、止まらない、または長押しで指が `'up'` 扱いになる場合は報告すること。
*   **iOS の拡大の抑止:** iOS の Safari は viewport の `user-scalable=no` を無視することがある。そのため `touch-action: none` を `html, body` と canvas に設定する。実機で2本の指の拡大が起きないことを確かめる。
*   **SVG の表示:** SVG を `drawImage` で描く。`width`・`height` を書いても、Safari で描画がぼやける・遅れる場合がある。問題があれば PNG への差し替え（定義のファイル名の書き換え）で回避できる。
*   **1フレームの中の端のケース:** パッドへの振り分けは配信の始めの最前面のシーンで行う。同じフレームの中で、先に `P` でメニューが開き、その後にパッドの上で指が押された場合、その指はパッドが取り、次のフレームで離した扱いになる（メニューのボタンには届かない）。1フレーム（約16ms）の中の重なりなので、実用上の問題は無いと判断した。
*   **ON で複数の種類のポインタが混ざる端のケース:** 単一ポインタの選び出しは「パッドの外で押しているポインタが無いときに押し始めた1本」で行う。タッチ対応の PC で、指を2本押して1本目を離した後にマウスを押した場合、今の動作（マウスが届く）と違い、2本目の指を離すまでマウスが届かない。ON のときだけの稀な操作なので、許容した。
*   **（タスク4）`Input` の目視確認:** `Input` の自動テストは無く、`Engine` がパッドを渡すのはタスク5からなので、タスク4の時点ではタッチの指ごとの受信と単一ポインタの選び出しは実機で確かめられない。OFF のときの `onPointer`（マウスのホバー、ドラッグ、画面のボタン）が今までどおり動くことをタスク5以降のテストプレイで確かめる。`contextmenu` の `e.pointerType` は古いブラウザで未定義のことがあり、その場合は指が1本以上あるときだけ抑止される。
*   **高解像度の画面:** `devicePixelRatio` に対応しないので、スマートフォンでは絵がややぼやける（Phase 03-03 以降）。
*   **配置の値:** 6.1インチ前後の横向きを前提に決めた値である。実機で親指が届きにくい、誤って押す場合は、`js/ui/virtualPadConfig.js` の値を直す REQ を出す。
*   **`PROJECT_ARCHITECTURE.md` 4章の `js/main.js` の記述:** 開発資料には「`Engine.start` に渡す設定（解像度、レイヤー、最初のシーン、`debug` など）の用意」とあり、`virtualPad` を足しても責務の範囲内と判断した（更新予定に挙げた）。
