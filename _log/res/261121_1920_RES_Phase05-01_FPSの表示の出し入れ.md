# RES: 作業計画・作業レポート Phase 05-01 : FPS の表示の出し入れ
* 参照元REQ: `./_log/req/261121_1920_Phase05-01_FPSの表示の出し入れ.md`

## 1. 作業目的
今の FPS の表示は、起動設定の `debug` が真のときだけ左上に出て、実行中には切り替えられず、ゲームが FPS の値を読む口もない。これを、実行中に表示を出し入れでき（`Engine.fpsVisible`）、表示の位置を画面の四隅から選べ（`Engine.fpsPosition`）、ゲームが FPS の値を読める（`Engine.fps`）ようにする。ゲーム（バトリティア）が、多数の兵を描いたときの重さを調整パネルで測るために求めている。

あわせて、`oz/ENGINE_API.md` の 14章を FPS の表示の章として書き直し、ゲームの土台のプレイ中のメニューとキー `F` で表示を切り替えて確かめられるようにし、`DebugOverlay` の Canvas を使わない部分を自動テストの対象に加え、新規プロジェクトの手順書に直すところが無いかを確かめる。

`oz/index.js`・`oz/VERSION`・`js/main.js`・`index.html`・`assets/` は変えない。起動設定の項目は増やさない。

## 2. アーキテクチャ設計

### 今の作り（計画のために確かめた結果）
* `Engine.start` は `Boolean(config.debug)` が真のときだけ `new DebugOverlay(width, height)` を作り、偽なら `null` を `GameLoop` に渡す。
* `GameLoop.#frame` は、`Layers.render` の後に `if (this.#overlay) { overlay.update(time.view.realDelta); overlay.draw(ctx); }` を行う（3章の手順5）。
* `DebugOverlay` は `update(realDelta)` でフレーム数と経過時間を足し、`1000` ミリ秒以上になったら `String(Math.round(frames * 1000 / elapsed))` を表示の文字にして集計を 0 に戻す。最初の計算までは `'--'`。`draw(ctx)` は `save` → `setTransform(画素数 ÷ 論理解像度)` → `font = '16px monospace'`・`textBaseline = 'top'`・`lineWidth = 3`・`strokeStyle = '#000'`・`fillStyle = '#fff'` → `strokeText`／`fillText`（`FPS: <文字>`、位置 `(8, 8)`）→ `restore`。`textAlign` は設定しておらず既定（`'start'`。左から右の向きでは `'left'` と同じ）。
* 既存の読み取り専用の値: `Engine.virtualPadEnabled`・`Engine.virtualPadTouched` は getter だけを持ち、setter が無い。`draw` に渡す `time` は getter だけの凍結したオブジェクトで、ENGINE_API 11章に「代入するとエラー（`TypeError`）」と書いてある。どちらも、代入したときに `TypeError` になるのは、代入する側のコードが strict モード（ES Modules の中は常に strict）のときで、strict でないコード（開発者ツールのコンソールなど）からの代入はエラーにならず無視される（JavaScript の仕様）。
* 既存のプロパティの代入の検証: `Engine.timeScale` は数値以外・負・有限でない値で `RangeError`（`Time` が投げる。文面 `timeScale must be a finite number >= 0`）。`Sound.masterVolume` などは数値以外を含め範囲外で `RangeError`（文面 `[oz] Sound.masterVolume: 0以上1以下の数値で指定してください: <値>`）。起動前の使用は `Error`（文面 `[oz] <API名>: Engine.start の前には使えません`）。
* 土台のメニュー（`js/scenes/MenuScene.js`）は項目の高さ `80`、間隔 `24` で画面の中央に縦に並べる。5項目なら全体の高さは `5 × 80 + 4 × 24 = 496`、上端 `(720 − 496) / 2 = 112`、下端 `608` で、1280×720 に収まり、項目どうしは重ならない（要件6の確認。今の高さと間隔のままでよい）。メニューを開くボタン（上の中央 `y: 20〜80`）とも重ならない。

### 要件1: 表示の出し入れ
* **表示の有無を持つ場所:** `DebugOverlay` が「表示するか」（`visible`）を持つ。表示の有無は「表示」の責務の一部であり、`DebugOverlay` の責務（FPS の計算と表示）に収まる。`Engine` は値の検証と委譲だけを行う。
* **`DebugOverlay` は常に作る:** `Engine.start` は `debug` にかかわらず `DebugOverlay` を作って `GameLoop` に渡し、作った直後に `overlay.visible = Boolean(config.debug)` を設定する（`debug` は表示の有無の起動時の値だけを決める。解釈は今の `Boolean(...)` のまま）。
* **`draw` を呼ぶかどうかの分岐の置き場所:** `GameLoop` は毎フレーム、今と同じ位置（`Layers.render` の後）で `overlay.update(realDelta)` と `overlay.draw(ctx)` を順に呼ぶだけにする（`GameLoop` に表示の有無の分岐を持たせない）。`DebugOverlay.draw` は、表示しないとき何も描かずに戻る（`ctx` に触れない）。これにより、FPS の計算（`update`）は表示の有無と `debug` の有無にかかわらず毎フレーム行われる。1フレームの処理順序（3章）は変わらない。
* **`GameLoop` の変更:** `overlay` が常に渡されるので、`#frame` の `if (this.#overlay)` を外し、`#overlay` の型の JSDoc と constructor の `deps.overlay` の JSDoc（「表示しない場合は null」）を直す。これは JSDoc と実際の渡し方を一致させるための最小の変更で、`GameLoop` の責務（3章の順序の呼び出し）は変わらない。
* **代入の効き方:** `Engine.fpsVisible` への代入は `DebugOverlay` の値をその場で変え、次に `DebugOverlay.draw` が呼ばれたときから効く（入力の配信や `update` の中で代入すると、そのフレームの最後の表示から効く）。

### 要件2: FPS の値を読む口
* `DebugOverlay` は、表示用の文字の代わりに数値の FPS を持つ（`_fps`。最初の計算までは `null`）。計算は今と同じ（`Math.round((frames * 1000) / elapsed)`、`elapsed >= 1000` で更新して集計を 0 に戻す）。getter `fps`（`number|null`）で読めるようにする。`draw` は `FPS: ${fps === null ? '--' : fps}` を描く（今と同じ文字になる）。
* `Engine.fps` は getter だけを持ち、起動前ならエラー、起動後は `overlay.fps` を返す。値が変わるのは各フレームの最後（シーンの `draw` の後の `overlay.update`）なので、1フレームの間（入力の配信・`update`・`draw`）は変わらない。`draw` から読んでよい（読み取りのみ）。
* **代入したときの扱い（決定）:** 既存の読み取り専用の値（`Engine.virtualPadEnabled`・`Engine.virtualPadTouched`、`draw` の `time`）に合わせ、setter を持たない。代入すると、strict モードのコード（ES Modules の中。ゲームのコードは常にこれ）では JavaScript が `TypeError` を投げ、値は変わらない（起動の前後にかかわらず `TypeError`。`[oz]` の文面ではない）。strict でないコード（開発者ツールのコンソールなど）では、エラーにならず無視され、値は変わらない。これを `oz/ENGINE_API.md` 14章に書く。

### 要件3: 表示の位置
* `DebugOverlay` が位置（`position`。既定 `'top-left'`）を持ち、`draw` で使う。位置の値の一覧は `DebugOverlay.js` が唯一の定義として持ち、凍結した配列 `FPS_POSITIONS`（`['top-left', 'top-right', 'bottom-left', 'bottom-right']`）として export する（`Engine` が検証に使う。`oz/index.js` からは出さない。エンジン内部の export であり、公開APIは増えない）。
* 隅からの距離は今の `8`（論理座標）を定数（例 `MARGIN = 8`）にして、四隅で共通に使う。位置ごとの寄せ方を表（例 `LAYOUTS`。位置 → `{ align, baseline, right: boolean, bottom: boolean }`）にまとめる。
  * `'top-left'`: `textAlign = 'left'`、`textBaseline = 'top'`、座標 `(MARGIN, MARGIN)`（今と同じ見た目）。
  * `'top-right'`: `textAlign = 'right'`、`textBaseline = 'top'`、座標 `(width − MARGIN, MARGIN)`。
  * `'bottom-left'`: `textAlign = 'left'`、`textBaseline = 'bottom'`、座標 `(MARGIN, height − MARGIN)`。
  * `'bottom-right'`: `textAlign = 'right'`、`textBaseline = 'bottom'`、座標 `(width − MARGIN, height − MARGIN)`。
  * `width`・`height` は constructor で受け取った論理解像度（起動設定の `width`・`height`）。変換は今と同じく `draw` の中で `setTransform(画素数 ÷ 論理解像度)` を設定するので、ウィンドウの大きさや画素の倍率が変わっても同じ隅に付く。右の隅は右寄せ、下の隅は下寄せで描くので、文字の長さ（`FPS: --` と `FPS: 60`）が変わっても隅からの距離は変わらず、画面の外にはみ出さない。
  * 文字の大きさ・色・縁取り（`16px monospace`、白、黒の太さ `3` の縁）は変えない。`top-left` で `textAlign` を明示的に `'left'` にするのは今の既定（`'start'`）と同じ見た目である。
* `Engine.fpsPosition` の代入は `DebugOverlay` の値をその場で変え、次の表示から効く。起動設定では指定しない。

### 要件4: 引数が正しくないとき（決定）
* `Engine` に、起動済みを確かめて `DebugOverlay` を返す補助関数（例 `requireOverlay(apiName)`。`overlay === null` なら `Error`）を置く。3つの API の読み書きの最初に呼ぶ。
* **起動前:** 読み書きとも `Error`、文面 `[oz] Engine.fpsVisible: Engine.start の前には使えません`（`Engine.fps`・`Engine.fpsPosition` も同じ形）。起動前の代入では、値の検証より先にこのエラーになる。（`Engine.fps` への起動前の代入は、setter が無いので要件2の `TypeError` になる。）
* **`Engine.fpsVisible` に真偽値（`typeof value === 'boolean'`）以外:** `RangeError`、文面 `[oz] Engine.fpsVisible: true か false で指定してください: <String(value)>`。既存のプロパティの代入（`Engine.timeScale`・`Sound.masterVolume`）が型の違いも含めて `RangeError` にしているので、それに合わせる。文面の形は `Sound.masterVolume` と同じ（先頭に `[oz]` と API 名、末尾に値）。
* **`Engine.fpsPosition` に4つ以外（`FPS_POSITIONS.includes(value)` が偽）:** `RangeError`、文面 `[oz] Engine.fpsPosition: 'top-left'・'top-right'・'bottom-left'・'bottom-right' のどれかで指定してください: <String(value)>`。
* 検証は `DebugOverlay` に値を渡す前に `Engine` で行い、エラーのときは `DebugOverlay` の値を変えないので、表示の有無・位置は変わらない。`DebugOverlay` の setter は検証しない（`Engine` が検証した値だけを渡すことを JSDoc に書く）。
* フレーム処理の中でこれらのエラーを起こすと、ほかのエラーと同じくループが止まる（ENGINE_API 15章の扱い）。14章に書く。

### 要件7: 自動テスト
* `test/DebugOverlay.test.js` を新しく作る。`../oz/src/DebugOverlay.js` から `DebugOverlay` と `FPS_POSITIONS` を直接 import する。`DebugOverlay.js` は読み込み時も `update`・getter・setter でも `window` と Canvas を使わないので、偽の `window` は要らない。
* 確かめること（公開されたもの（`fps`・`visible`・`position` の getter・setter、`update`、`FPS_POSITIONS`）だけを通す。`_frames` などの内部は読まない）:
  * 作った直後: `fps` が `null`、`visible` が `false`、`position` が `'top-left'`。
  * 最初の計算まで `null`: 合計が `1000` 未満の間（例 `20` ミリ秒 × 49 回 = 980）は `null` のまま。
  * 計算: 合計がちょうど `1000` になったフレームで更新される（例 `20` × 50 回 → `50`）。
  * 四捨五入: 例 `400` ミリ秒 × 3 回（合計 1200）→ `Math.round(2.5) = 3`、`150` × 7 回（合計 1050）→ `Math.round(6.666…) = 7`。
  * 更新後の集計の戻り: 更新の後は、次に合計が `1000` に達するまで前の値を保ち、達したら次の1秒の値になる（例 1秒目 `20`×50 → `50`、続けて `25`×39 では `50` のまま、40回目で `40`）。
  * 初回の `realDelta = 0` を含む場合: `update(0)` もフレームに数える（今の計算どおり。例 `update(0)` の後 `20`×50 → `51`）。
  * 表示の有無と無関係: `visible` が `false` のままでも、途中で `true`／`false` を切り替えても、`fps` は同じように更新される。
  * 位置: `FPS_POSITIONS` が4つの値をこの順で持ち、凍結されている（`Object.isFrozen`）。4つのそれぞれを `position` に代入すると読み戻せる。`visible` に `true`／`false` を代入すると読み戻せる。
* 描画（`draw`）と `Engine` はテストしない。値の検証（`RangeError`）は `Engine` にあるのでテストしない（`Engine` はテストしないモジュール）。テストのためにソースを変えない（`fps`・`FPS_POSITIONS` は `Engine` が使うために置く）。

## 5. 懸念事項・要確認ポイント
* **(タスク1) モジュール変数 `overlay`:** `Engine.start` 内のローカル変数は `newOverlay` とし、モジュール変数 `overlay` との名前の衝突（シャドーイング）を避けた。タスク3では `requireOverlay` がモジュール変数 `overlay` を使う。起動前判定は `overlay === null`。
* **隅からの距離の見え方:** 上の隅は `textBaseline = 'top'`、下の隅は `'bottom'` で、文字の枠（16px の em の枠）の端を隅から `8` の位置にそろえる。字の形（`FPS: 60` は大文字と数字で、下にはみ出す字が無い）のため、下の隅では文字の見た目の下端が枠の下端より上にあり、上の隅より少し離れて見えることがある。目視で、四隅の距離がそろって見えるかを確かめてほしい。
* **右上の表示と土台の状態表示の重なり:** 土台のタイトルとプレイの画面は、右上に「ミュート中」（1行目、中心 `y = 30`、24px）と「スロー」（2行目）を出す。FPS を右上に出すと、`FPS: 60` と「ミュート中」が縦に近く、少し重なって見える可能性がある（FPS は最前面に描かれる）。土台の状態表示の位置は今回変えない（求められていない）。左下・右下はバーチャルパッドの近くだが、FPS は最前面に描かれ、パッドの押下の判定には影響しない。
* **`Engine.fps` への代入:** 既存の読み取り専用の値に合わせて setter を持たないので、コンソール（strict モードでない）からの代入はエラーにならず無視される。コンソールでは `Engine.fps = 5` の後に `Engine.fps` が変わっていないことで確かめる（strict モードでの `TypeError` は下の手順で確かめられる）。
* **目視確認推奨箇所（要件8。公開したページ `https://<アカウント>.github.io/ozengine-web/` で行う）:**
    1.  **`?debug` の有無（PC・スマートフォン）:** ページの URL の末尾に `?debug` を付けて開く → これまでどおり左上に `FPS: --`、約1秒後から `FPS: 60` などが出る。`?debug` を付けずに開く → FPS は出ない。
    2.  **メニューの項目での切り替え（PC・スマートフォン）:** プレイの画面で「メニュー」を押してメニューを開く → 項目が上から「閉じる」「スロー: OFF」「ミュート: …」「FPS: OFF」（`?debug` 付きなら「FPS: 左上」）「タイトルに戻る」の5つで、画面に収まり重ならない。「FPS」の項目を押すたびに、項目の文字が「FPS: OFF」→「FPS: 左上」→「FPS: 右上」→「FPS: 右下」→「FPS: 左下」→「FPS: OFF」…と変わり、画面の FPS の表示が、その文字のとおりの隅に出る（OFF のときは出ない）。メニューの暗幕の上にも、FPS の表示は最前面に出る。
    3.  **キー `F`（PC）:** メニューを開いた状態で `F` を押す → 2 と同じ順に切り替わり、項目の文字と表示が合っている。メニューを閉じたプレイ中に `F` を押す → 同じ順に切り替わる（メニューを開くと、項目の文字が今の状態を表している）。タイトル画面の `F` では何も起きない。
    4.  **四隅の見え方（PC・スマートフォン）:** 左上・右上・右下・左下のどれでも、文字が画面の外にはみ出さず、隅からの距離がそろって見える。`FPS: --` から `FPS: 60` に変わっても、隅からの距離が変わらない（右の隅では右端の位置が動かない）。
    5.  **ゲームの動きが変わらないこと（PC・スマートフォン）:** 表示を出したり消したりしても、機体の旋回・ブースト、スロー、ミュート、タイトルへの戻りは今までどおり動く。表示を右下などにしてからメニューを閉じても、「タイトルに戻る」でタイトルに戻っても、同じ隅に表示が出たまま（OFF にしていれば出ないまま）である。ページを読み込み直すと、`?debug` の有無で決まる起動時の状態に戻る。
    6.  **大きさと向きの変化:** PC でウィンドウの大きさを変える → 表示は選んだ隅に付いたまま、はみ出さない。スマートフォンで画面の向きを縦・横に変える → 同じく、選んだ隅に付いたままである。
    7.  **`Engine.fps` とエラー（PC の開発者ツールのコンソール。ゲームを開いたページで行う）:**
        *   `const { Engine } = await import('./oz/index.js');` を実行する（公開したページからの相対パス。ページと同じモジュールが読まれる）。
        *   `Engine.fps` → 起動から約1秒たっていれば `60` などの整数（画面の表示と同じ値）。表示を OFF にしていても数値が返り、何度か読むと変わることがある。
        *   `Engine.fpsVisible`・`Engine.fpsPosition` → 今の状態（例 `true`・`'bottom-right'`）が返り、メニューの項目の文字と合っている。
        *   `Engine.fpsVisible = true; Engine.fpsPosition = 'top-right';` → 右上に表示が出る（その後メニューを開くと「FPS: 右上」）。
        *   `Engine.fpsPosition = 'center'` → `RangeError: [oz] Engine.fpsPosition: 'top-left'・'top-right'・'bottom-left'・'bottom-right' のどれかで指定してください: center` が出て、表示の位置は変わらない（`Engine.fpsPosition` が前の値のまま）。
        *   `Engine.fpsVisible = 1`（または `'true'`）→ `RangeError: [oz] Engine.fpsVisible: true か false で指定してください: 1` が出て、表示の有無は変わらない。
        *   `Engine.fps = 5` → エラーは出ず、`Engine.fps` は変わらない（コンソールは strict モードでないため）。`(() => { 'use strict'; Engine.fps = 5; })()` → `TypeError` が出る（ゲームのコード（ES Modules）での代入はこちらになる）。
