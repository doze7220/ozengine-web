# RES: 作業計画・作業レポート Phase 05-02 : 窓と部品の土台
* 参照元REQ: `./_log/req/261121_2143_Phase05-02_窓と部品の土台.md`

## 1. 作業目的
画面に重ねて開く窓と、その中に並べる UI 部品の共通の仕組み（描き方の差し替え、値のつなぎ方、ポインタの受け方）をエンジンに入れ、最も単純な部品であるボタンと、数値・文字の表示で使えるようにする。エンジンは素っ気ない標準の見た目で描き、ゲームは部品の種類ごとに描く関数を渡して見た目を差し替えられる。ゲーム（バトリティア）が、開発用の調整パネル（標準の見た目）と遊ぶ人向けの設定画面（ゲームの絵柄）を作るために求めている。

利用側には `oz/index.js` から新しい名前 `Ui` を1つ公開する。後の作業でチェックボックス・スライダー・選択肢の列・タブ・スクロールする領域を同じ仕組みの上に足すので、それらが乗る土台にする（今回はそれらを作らない）。

あわせて、`oz/ENGINE_API.md` に 26章（UI 部品）を足し、Canvas を使わない部分を自動テストの対象にし、ゲームの土台のプレイ中のメニューに「UI の見本」を足して2種類の見本の窓（標準の見た目／差し替えた見た目）で確かめられるようにし、新規プロジェクトの手順書に直すところが無いかを確かめる。

`Buttons`・`Input`・`Scenes`・`GameLoop`・`Engine.addButton` の仕様、`oz/VERSION`・`js/main.js`・`index.html`・`assets/` は変えない。`Engine` に足すのは、起動時に論理解像度を `Ui` へ渡すことだけである。

  * `UiWindow` → `UiSpec`・`UiMetrics`・`UiRect`・`UiButton`・`UiValue`
  * `UiButton`・`UiValue` → `UiSpec`・`UiMetrics`・`UiRect`
  * `UiRenderer` → `UiStandardLook`

### 要件2: 窓をシーンの中に置く形（決定）
* 窓はシーンが持つ。シーンは `init` で `Ui.createWindow` を呼び、`onPointer(pointer)` で `this.window.onPointer(pointer)`、`draw(ctx, layer)` で選んだレイヤーのときに `this.window.draw(ctx)` を呼ぶ（それぞれ1行）。窓は `Engine.addButton`・入力の仕組みに登録しない。ポインタはシーンから渡されたものだけで動く。
* **窓を置いたシーンの派生クラスはエンジンに足さない（判断）:** `Scene` の派生クラスを UI 部品のファイルに置くと `Scene` を import することになり、要件1（ほかのエンジンモジュールを import しない）に反する。シーンへ渡す手間は3行（`init`・`onPointer`・`draw`）で済むので、`oz/ENGINE_API.md` の使い方の例で示す。ゲーム自身のシーンの中に窓を置く形は、そのまま使える。
* **背面に入力が届かないこと:** 窓を置いたシーンを `Engine.pushScene` で積めば、最前面のシーンにだけ入力が届く（16章）ので成り立つ。背面のシーンの `Engine.addButton` のボタンも反応しない（18章）。
* **`Engine.addButton` との重なり（注意として 26章に書く）:** 窓を置いたシーン自身が `Engine.addButton` で窓と重なる位置にボタンを登録すると、そのボタンが押下を独占し、離すまでの `'move'`・`'up'` も含めて `onPointer` に届かないので、窓には届かない。窓の外（暗幕の上）に登録した場合も、そのボタンの押下は窓に届かず、窓の外を押したことにならない（閉じない）。
* **バーチャルパッド（確かめた結果。26章に書く）:** パッドが処理した指は `onPointer` に届かない（16章・24章）ので、窓にも部品にも届かない。今の作りのまま成り立ち、UI 部品の側で何もしなくてよい。ただし、パッドが反応するのは最前面のシーンに登録したパッドだけなので、背面のシーンのパッドの位置を押した指は、窓を置いたシーンの `onPointer` に届き、窓の外の押下として扱われる（標準の設定なら窓が閉じる）。パッドの位置で窓を閉じたくないときは、窓を置いたシーンにも同じ配置のパッドを登録する（そのシーンの `init` で `Engine.addVirtualPad`）。そのとき窓とパッドの円が重なると、重なった部分を押した指はパッドが受け取り、部品には届かないので、窓をパッドの円と重ねない。これを 26章の注意に書く。

### 要件3: 窓
* **`Ui.createWindow(options)` の項目（`options` の項目。表にない項目はエラー）:**

  | 項目 | 必須 | 既定 | 内容 |
  | --- | --- | --- | --- |
  | `title` | 必須 | - | タイトルバーの文字。文字列（空文字も可） |
  | `width`・`height` | 必須 | - | 窓の全体（タイトルバーを含む）の大きさ（論理座標）。正の有限数で、どちらも `titleBarHeight` より大きい |
  | `x`・`y` | 任意 | 中央 | 窓の左上（論理座標）。有限の数値。省略した軸は画面の中央に置く（`x = (画面の幅 − width) / 2`、`y = (画面の高さ − height) / 2`。丸めない） |
  | `onClose` | 必須 | - | 閉じるときに引数なしで呼ぶ関数 |
  | `closeOnOutside` | 任意 | `true` | 窓の外を押して離したら閉じるか。`true` か `false` |
  | `titleBarHeight` | 任意 | `88` | タイトルバーの高さ。閉じるボタンは、この長さの正方形 |
  | `textSize` | 任意 | `36` | 文字の大きさ（標準の見た目で使い、描く関数にも渡す）。正の有限数 |
  | `look` | 任意 | - | 種類ごとの描く関数（要件7） |

  任意の項目は、書かないか `undefined` にすると既定になる（`null` はエラー）。値はコピーして持ち、後から元のオブジェクトを変えても影響しない（`look` も中身を写して持つ）。
* **窓の形（`UiWindow` が constructor で求め、後から変わらない。窓の移動・大きさの変更はしない）:**
  * 窓の全体: `{ x, y, width, height }`。
  * タイトルバー: `{ x, y, width, height: titleBarHeight }`（窓の上端、全幅）。
  * 閉じるボタン: `{ x: x + width − titleBarHeight, y, width: titleBarHeight, height: titleBarHeight }`（タイトルバーの右端の正方形）。
  * 窓の内側: `{ x, y: y + titleBarHeight, width, height: height − titleBarHeight }`。部品の位置の原点は、この左上。
  * 暗幕: `{ x: 0, y: 0, width: 画面の幅, height: 画面の高さ }`（論理解像度の全体）。
* **窓の外へはみ出した部品の扱い（決定: 窓の内側で切り取る）:** 部品の矩形のうち、窓の内側に入っている部分だけを描き、その部分だけが押せる（描画は `UiRenderer` が窓の内側の矩形で `clip` し、当たり判定は部品の矩形と窓の内側の矩形の重なり（`UiRect` の `intersectRect`）で行う）。全部が外にある部品は、描かれず押せない。後の作業のスクロールする領域で、同じ切り取りを使える。
* **閉じるボタン:** `UiButton` を1つ内部で作って使う（部品のボタンと同じく、離したときに反応する・取り消せる）。押されたときに `onClose()` を呼ぶ。シーンを外すのは呼ぶ側が `onClose` の中で行う（`Engine.popScene()`）。
* **窓の外の押下と、閉じるかの判定（`UiWindow.onPointer`）:** 要件5に書く。窓の外の押下は、`closeOnOutside` にかかわらず、部品にもタイトルバーにも届かない（背面のシーンには、窓を置いたシーンを積んでいるので届かない）。
* **窓の中の、部品の無いところ・タイトルバー（閉じるボタンを除く）の押下:** 何も起きない（その押下は離すまで、どの部品にも反応させない）。

### 要件4: ボタンと、数値・文字の表示
* **窓の `addButton(spec)`（表にない項目はエラー）:**

  | 項目 | 必須 | 既定 | 内容 |
  | --- | --- | --- | --- |
  | `x`・`y` | 必須 | - | 窓の内側の左上を原点とする位置（論理座標）。有限の数値 |
  | `width` | 必須 | - | 幅。正の有限数 |
  | `height` | 任意 | `88` | 高さ。正の有限数 |
  | `label` | 必須 | - | 文字。文字列、または描くたびに呼ぶ関数（引数なし。戻り値は `String(...)` で文字にする） |
  | `onPress` | 必須 | - | 押されたとき（離したとき）に引数なしで呼ぶ関数 |
  | `enabled` | 任意 | 常に押せる | 押せるかを返す関数（引数なし）。描くたびと、押したとき・離したときに呼び、偽（`Boolean(...)` で偽）なら押せない |

* **窓の `addValue(spec)`（数値・文字の表示。表にない項目はエラー）:**

  | 項目 | 必須 | 既定 | 内容 |
  | --- | --- | --- | --- |
  | `x`・`y`・`width`・`height` | `addButton` と同じ | | |
  | `label` | 必須 | - | 項目名。`addButton` の `label` と同じ形 |
  | `read` | 必須 | - | 値を読む関数（引数なし）。描くたびに1回呼ぶ |
  | `format` | 任意 | `String(value)` | 読んだ値を表示の文字にする関数（引数は読んだ値）。戻り値は `String(...)` で文字にする |

  * **`null` と数値の整え方（決定）:** 呼ぶ側が `format` で決める（例 `format: (v) => (v === null ? '--' : String(v))`、`(v) => v.toFixed(2)`）。省略したときは `String(value)`（`null` は `'null'`、`undefined` は `'undefined'` と出る。何が読めているかがそのまま見える）。
  * 押しても何も起きない（その押下は離すまで、どの部品にも反応させない）。
* **部品の重なり:** 後に足した部品が上に描かれ、押したときも後に足した部品だけが調べられる（`Buttons` と同じく、左端・上端を含み、右端・下端を含まない）。数値・文字の表示が上にあると、下のボタンは押せない。
* **文字が部品の幅に収まらないとき（決定）:** 標準の見た目は、`fillText` の第4引数（`maxWidth`）で、文字を横に縮めて部品の中に収める（切らない、はみ出さない）。差し替えた描く関数では、呼ぶ側が扱いを決める（`info` の矩形と文字を渡す）。窓のタイトルも同じ（閉じるボタンの手前までに縮める）。
* 部品の追加は、窓を作った後いつでもできる（`init` の中で足すのを例にする）。削除・移動はできない。

### 要件5: ポインタの受け方（決定）
* **`UiWindow` の押下の持ち主（キャプチャ）:** `#capture` に「押し始めの持ち主」を持つ。値は `null`（押していない）、部品（`UiButton`。閉じるボタンを含む）、`OUTSIDE`（窓の外で押し始めた）、`NONE`（窓の中の、反応しないところで押し始めた）のどれか（`OUTSIDE`・`NONE` はモジュールの中の `Symbol`）。
* **`'down'`（`#capture` が `null` のとき。`null` でないときの `'down'` は無視する。エンジンは単一ポインタなので届かない）:**
  1. 窓の全体の外なら `OUTSIDE`。
  2. 閉じるボタンの矩形の中で、閉じるボタンの `pointerDown(x, y)` が真なら、閉じるボタン。
  3. 窓の内側なら、部品を後に足したものから調べ、当たりの矩形が点を含む最初の部品の `pointerDown(x, y)` を呼ぶ。真ならその部品、偽（数値・文字の表示、押せないボタン）なら `NONE`。含む部品が無ければ `NONE`。
  4. それ以外（タイトルバーの閉じるボタン以外）は `NONE`。
* **`'move'`:** `#capture` が部品なら、その部品の `pointerMove(x, y)` を呼ぶ（ほかの部品には何もしない）。それ以外は何もしない。
* **`'up'`:** 持ち主を変数に取り出して `#capture = null` にしてから（呼んだ関数の中で窓を開き直したりシーンを変えたりしてもよいように）、持ち主が部品ならその `pointerUp(x, y)` を呼ぶ。`OUTSIDE` で、`closeOnOutside` が真で、離した位置が窓の全体の外なら `onClose()` を呼ぶ。`NONE` と `null` なら何もしない。
* **`'down'` の無い `'move'`・`'up'`:** `#capture` が `null` なので、どの部品も反応せず、窓も閉じない。
* **`UiButton` の押下の流れ:**
  * `pointerDown(x, y)`: 当たりの矩形が点を含み、押せる（`enabled` が無い、または `Boolean(enabled())` が真）なら `#pressed = true` にして `true` を返す。そうでなければ状態を変えずに `false` を返す（押せないボタンは押されている見た目にならない）。
  * `pointerMove(x, y)`: `#pressed = 当たりの矩形が点を含む`（外へずらすと押されている見た目が消え、戻すと付く）。
  * `pointerUp(x, y)`: `#pressed = false` にしてから、当たりの矩形が点を含み、かつ押せるなら `onPress()` を呼ぶ。外で離したら何も起きない（取り消し）。外へずらしてから戻して離すと反応する。
  * 状態の変更はポインタを受けたときだけ行い、描くための情報（`info`）は状態を読むだけ（憲法3章「ロジックと描画の分離」）。
* **後の作業が乗る形（今回は作らない。設計に書くだけ）:**
  * 部品は共通の形（`hitTest(x, y)`、`pointerDown(x, y) → 持ち主になるか`、持ち主のときだけ呼ばれる `pointerMove`・`pointerUp`、`info(textSize)`、種類の名前 `kind`）を持ち、`UiWindow` はこの形だけで振り分ける。
  * スライダーは、`pointerDown` で `true` を返して持ち主になり、`pointerMove` で（部品の外へずれても）値を書く関数を呼ぶ。チェックボックス・選択肢の列は、ボタンと同じく離したときに反応する。
  * スクロールする領域は、中の部品を持つ部品として持ち主になり、中の部品へ振り分ける。ずらす距離が決めた量を超えたら、中の部品に取り消し（その時に足す `pointerCancel()`。ボタンなら `#pressed = false` にするだけ）を呼んで、以後の `'move'` を自分で使う。中の部品の当たりの矩形と描画は、今回の窓の内側と同じ切り取り（`intersectRect` と `clip`）を使う。
  * タブは、押されたら表示する部品の組を切り替える部品として足す。

### 要件6: 値のつなぎ方（決定）
* **共通の形:** 値を持つ部品は、呼ぶ側から `read`（値を読む関数、引数なし）を受け取り、描くたびに（`UiWindow.view()` の中で）1回呼ぶ。後の作業で書く部品は、同じ設定オブジェクトに `write`（値を書く関数、引数は新しい値）を受け取り、操作で値を変えたらその場で呼ぶ。部品は値を自分で持たず、書き換えもしない（次に描くときに `read` で読み直すので、外から変わっても表示が追従する）。保存（22章 `Storage`）はゲームが `write` の中で行う（部品は `Storage` を使わない）。
* **今回の実体:** 数値・文字の表示の `read`（と `format`）だけ。`read` を検証する処理（`UiSpec` の関数の検証）は、後の作業の `write` にもそのまま使う。`write` を受け取る処理・呼ぶ処理は今回作らない（先回りしない）。
* **「描くたびに読む」のそろえ方:** ボタンの `label`（文字列または関数）、`enabled`（関数）も、`view()` の中で描くたびに読む。文字の読み出しは `UiSpec` の `readText(text)`（関数なら呼んで `String(...)`、文字列ならそのまま）に1つにまとめる。`view()` はこれらを呼ぶだけで、窓と部品の状態を変えない。呼ぶ側の関数は状態を変えないこと（`draw` の中から呼ばれるため）を 26章に書く。
* `read`・`format`・`label`・`enabled` を呼ぶのは `view()`（`draw` の中）と、`enabled` だけは押したとき・離したとき。`addValue`・`addButton`・`onPointer` は `read`・`format`・`label` を呼ばない。

### 要件7: 見た目の差し替え（決定）
* **描く関数の種類（`LOOK_KINDS`。`UiSpec.js` が凍結した配列として唯一の定義を持つ）:** `backdrop`（暗幕）、`window`（窓の地と枠）、`titleBar`（タイトルバーとタイトルの文字）、`closeButton`（閉じるボタン）、`button`（部品のボタン）、`value`（数値・文字の表示）の6つ。タイトルバーと閉じるボタンを窓と分けるので、色の違うタイトルバーだけ、など一部だけを差し替えられる。
* **渡す単位（決定: 窓ごとにまとめて渡す）:** `Ui.createWindow` の `look`（種類の名前 → 描く関数のオブジェクト）。渡した種類はその関数で、渡さなかった種類は標準の見た目で描く。同じ `look` のオブジェクトを複数の窓に渡して、ゲームの絵柄をそろえられる。`look` に知らない名前があるとエラー、値が関数でないとエラー。

* **`info`（描くたびに新しいオブジェクト。書き換えても窓と部品に影響しない。座標はすべて画面の論理座標（窓の内側からの位置ではない））:**

  | 種類 | `info` の項目 |
  | --- | --- |
  | `backdrop` | `x`・`y`・`width`・`height`（論理解像度の全体） |
  | `window` | `x`・`y`・`width`・`height`（窓の全体）、`title`、`textSize` |
  | `titleBar` | `x`・`y`・`width`・`height`（タイトルバー。全幅で、閉じるボタンの部分を含む）、`title`、`textSize` |
  | `closeButton` | `x`・`y`・`width`・`height`、`pressed`（押されているか）、`textSize` |
  | `button` | `x`・`y`・`width`・`height`、`label`（読んだ文字）、`pressed`、`enabled`（押せるか）、`textSize` |
  | `value` | `x`・`y`・`width`・`height`、`label`（読んだ文字）、`value`（`read` の戻り値そのもの）、`text`（`format` で整えた文字）、`textSize` |

* 見た目を差し替えても、押したと判定される範囲（部品の矩形と窓の内側の重なり、閉じるボタンの正方形、窓の全体）は変わらない。描く関数は矩形の内側に描くことを勧める（はみ出しても押せる範囲は変わらない。部品は窓の内側で切り取られる）。

* **標準の見た目（`UiStandardLook.js`。画像・フォントの読み込みは使わず、フォントは `${textSize}px sans-serif`）。** 色・太さの定数はこのファイルの中だけに置く（ゲーム固有の値ではない、素っ気ない灰色と白）:

### 要件8: 既定の大きさ（決定）
* **決めた値（`UiMetrics.js` に論理座標の数値として置き、論理解像度・画素の倍率から自動では変えない）:** タイトルバーの高さ `DEFAULT_TITLE_BAR_HEIGHT = 88`（閉じるボタンは一辺 `88` の正方形）、部品の高さ `DEFAULT_PART_HEIGHT = 88`（`height` を省略したとき）、文字の大きさ `DEFAULT_TEXT_SIZE = 36`。
* **考え方:** 論理解像度の短い辺が 720 のゲームを、スマートフォンでゲームの短い辺を画面の短い辺（およそ 360〜430 CSS 画素）に合わせて表示すると（縦長のバトリティアは縦に持って、横長の土台は横に持って）、論理座標の 1 は約 0.5〜0.6 CSS 画素になる。押しやすい目安の 44 CSS 画素は、狭い方の 360 CSS 画素で論理座標 `44 × 720 / 360 = 88`。文字 `36` は約 18〜21 CSS 画素。
* 論理解像度の短い辺が違うゲームでは、呼ぶ側が `titleBarHeight`・`textSize`・部品ごとの `height` を渡す（目安は `既定 × 短い辺 / 720`）。横長のゲームを縦に持ったスマートフォンで表示すると、長い辺が画面の幅に合うので約 0.3 倍になり、既定の大きさでは小さい（約 26 CSS 画素）。これらを 26章に書く。
* 見本の窓の大きさの確かめ: 土台（1280×720）を横に持ったスマートフォン（例 844×390 CSS 画素）では、高さで合わせて約 0.54 倍になり、ボタンの高さ `88` は約 48 CSS 画素。

    7.  **大きさと向きの変化:** PC でウィンドウの大きさを変える、スマートフォンで画面の向きを変える → 窓の表示と、押して反応する位置がずれない。
    8.  **繰り返し:** タイトルに戻る・プレイを始める・窓を開いて閉じる（閉じるボタン、外を押す、見た目の切り替えを含む）を何度か繰り返す → 開発者ツールのコンソールにエラーが出ない。
    9.  **エラー（PC の開発者ツールのコンソール。ゲームを開いたページで行う）:** `const { Ui } = await import('./oz/index.js');` の後、`Ui.createWindow({ title: 'x', width: 300, height: 200, onClose() {}, closeOnOutsde: false })` → `Error: [oz] Ui.createWindow: options に使えない項目 closeOnOutsde があります`。`Ui.createWindow({ title: 'x', width: 300, height: 200, onClose() {}, look: { buton() {} } })` → `Error: [oz] Ui.createWindow: look に使えない項目 buton があります`。
