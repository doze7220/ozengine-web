# RES: 作業計画・作業レポート Phase 05-03 : 値を変える部品
* 参照元REQ: `./_log/req/261122_0137_Phase05-03_値を変える部品.md`

## 1. 作業目的
Phase 05-02 でエンジンに入った UI 部品の土台（`Ui`。`oz/ENGINE_API.md` 26章）の上に、値を変える3種類の部品（チェックボックス、スライダー、選択肢の列）を足す。ゲーム（バトリティア）が、開発用の調整パネル（標準の見た目）と遊ぶ人向けの設定画面（ゲームの絵柄。音量のスライダーなど）を作るために求めている。

3種類とも、呼ぶ側から値を読む関数 `read` と値を書く関数 `write` を受け取り、値を自分で持たない（描くたびに `read` で読み直す）。`write` を呼ぶのはポインタを受けたとき（窓の `onPointer` の中）だけで、描画の中では呼ばない。スライダーは、溝のどこかを押すと値がその位置へ飛び、そのままドラッグで追う。指が少しずれても意図しない値にならないように、刻みに合わせて止め、小数の誤差を出さず、外へずれてもドラッグを続け、離したときの位置では値を変えず、刻みの境目に遊び（ヒステリシス）を入れる。

あわせて、見た目の差し替え（`look`）に3種類を足し、標準の見た目で3種類を描き、Canvas を使わない部分を自動テストの対象にし、`oz/ENGINE_API.md` 26章に使い方を書き、ゲームの土台に3種類を並べた見本の窓（標準／差し替え）を足して確かめられるようにし、新規プロジェクトの手順書に直すところが無いかを確かめる。

05-02 の窓・ボタン・数値・文字の表示の動き、既存の `look` の種類と `info` の項目は変えない（26章の「`addButton`・`addValue`・`onPointer` は `label`・`read`・`format` を呼ばない」の記述だけを、正しい形に直す）。`Engine`・`Buttons`・`Input`・`Scenes`・`GameLoop`・`Sound`、`oz/index.js`・`oz/VERSION`・`js/main.js`・`index.html`・`assets/`、プレイ中のメニュー（`MenuScene`・`playMenu.js`）は変えない。

### 要件2: 値のつなぎ方（決定）
* **共通:** 3種類とも `read`（引数なし。値を読む関数）と `write`（引数は新しい値1つ。戻り値は使わない）を必須で受け取る。部品は値を自分で持たない（スライダーのドラッグ中の「今の刻みの番号」は、遊びのためのポインタの状態で、表示には使わない）。描くたびに（`view()` の中で）`read` を1回呼んで表示を合わせるので、値が外から変わっても次の描画で追従する。
* **`write` を呼ぶのはポインタを受けたときだけ（窓の `onPointer` の中）。** `view()`（`draw` の中）では `write` を呼ばない。今の値（`read` の戻り値）と同じ値になる操作では `write` を呼ばない（比べ方は部品ごと。下の表）。
* **`read`・`write` が呼ばれる時（決定）:**

  | 部品 | `view()`（描くたび） | `'down'` | `'move'` | `'up'` |
  | --- | --- | --- | --- | --- |
  | チェックボックス | `read` 1回 | 呼ばない | 呼ばない | 部品の当たりの矩形の中で離したとき: `read` 1回 → `write(!Boolean(読んだ値))` |
  | スライダー | `read` 1回 | `read` 1回 → 位置の刻みの値が読んだ値と `===` で違えば `write(刻みの値)` | 刻みの番号が変わったときだけ: `read` 1回 → `===` で違えば `write(刻みの値)` | 呼ばない（値を変えない） |
  | 選択肢の列 | `read` 1回 | 呼ばない | 呼ばない | 押し始めた選択肢の上で離したとき: `read` 1回 → その選択肢の値と `===` で違えば `write(選択肢の値)` |

  チェックボックスの `!Boolean(v)` は `Boolean(v)` と必ず違うので、離したときは必ず `write` を呼ぶ。
* **足す操作（`addCheckbox` など）は `label`・`read`・`write`・`format` を呼ばない。** 26章の「`addButton`・`addValue`・`onPointer` は `label`・`read`・`format` を呼ばない」は、「部品を足す操作は `label`・`read`・`write`・`format`・`enabled` を呼ばない。`onPointer` は `label`・`format` を呼ばない。`read` は、数値・文字の表示では `onPointer` から呼ばれないが、チェックボックス・スライダー・選択肢の列では、上の表のとおり押したとき・ずらしたとき・離したときにも呼ばれる（`enabled` は 05-02 のとおり押したとき・離したときにも呼ばれる）」の形に直す（05-02 の動きは変わらない）。
* **保存:** ゲームが `write` の中で行う（部品は `Storage` を使わない）。`write`（と、ポインタを受けたときの `read`）が投げた例外は包み直さずに伝わる（`onPress` と同じ。フレーム処理の中ならループが止まる。15章）。部品の状態は、`write` を呼ぶ前に戻しておく（チェックボックス・選択肢の列は押されている状態を解いてから呼ぶ。スライダーの `'down'` は `write` の後に押されている状態にする）。
* `write` は窓の `onPointer` の中から呼ばれるので、シーンの操作（`Engine.popScene` など）をしてよい（7章）。`read`・`label`・`format` は `draw` の中からも呼ばれるので、状態を変えないこと。

### 要件3: チェックボックス（決定）
* **`addCheckbox(spec)` の項目（表にない項目はエラー）:** `x`・`y`・`width`・`height`（既定 `88`）、`label`（必須。文字列か、描くたびに呼ぶ関数）、`read`（必須）、`write`（必須）。
* **入り・切り:** `read` の戻り値を `Boolean(...)` で真偽にしたものが入り（`true`）か切り（`false`）。
* **押し方（ボタンと同じ）:**
  * `pointerDown(x, y)`: 当たりの矩形が点を含むなら `#pressed = true` にして `true`（持ち主になる）。含まなければ `false`。押せなくする指定は無い（`enabled` は作らない）。
  * `pointerMove(x, y)`: `#pressed = 当たりの矩形が点を含む`。
  * `pointerUp(x, y)`: `#pressed = false` にしてから、当たりの矩形が点を含むなら `write(!Boolean(read()))`。外で離したら何も起きない（取り消し）。外へずらしてから戻して離すと反応する。
* 押して反応する範囲は、箱だけでなく部品の矩形の全体（窓の内側との重なり）。箱の位置と大きさは描く関数が決める（標準の見た目は要件6）。
* **`info`:** `{ x, y, width, height, label, checked, pressed, textSize }`（`label` は読んだ文字、`checked` は `Boolean(read())`）。

### 要件4: スライダー（決定）
* **`addSlider(spec)` の項目（表にない項目はエラー）:**

  | 項目 | 必須 | 既定 | 内容 |
  | --- | --- | --- | --- |
  | `x`・`y`・`width`・`height` | | `height` は `132` | `addButton` と同じ形。`width` は `SLIDER_KNOB_SIZE`（`64`）より大きくする |
  | `label` | 必須 | - | 項目名。`addButton` の `label` と同じ形 |
  | `min`・`max` | 必須 | - | 最小・最大。有限の数値で、`min < max` |
  | `step` | 必須 | - | 刻み。正の有限数で、`max - min` 以下、`max - min` が `step` の整数倍 |
  | `read` | 必須 | - | 値を読む関数（引数なし） |
  | `write` | 必須 | - | 値を書く関数（引数は刻みの値） |
  | `format` | 任意 | `String(value)` | 読んだ値を値の文字にする関数（`addValue` の `format` と同じ形） |

* **`step` を省略したときの扱い（決定: 必須）:** 刻みなしの連続した値は作らない。理由: (1) 要件の「値は刻みに合わせて止まる」「小数の誤差を出さない」「遊び」は刻みがあって成り立つ。(2) 連続した値では、指の細かい揺れがそのまま `write` に渡り、音量などが揺れる。(3) 使い道（音量 0〜1 の 0.1 刻み、調整パネルの数値）は刻みを決められる。必要になったら後から任意にできる（必須を任意にしても、今の使い方は変わらない）。
* **`max - min` が `step` の整数倍でないとき（決定: エラー）:** 最後の刻みを `max` にする形は、最後の1刻みだけ幅が違い、位置と値の対応が分かりにくい。整数倍かの判定は小数の誤差を見込み、`n = (max - min) / step`、`k = Math.round(n)` として、`|n - k| ≤ k × 1e-9` なら整数倍とみなす（例: `min 0・max 0.3・step 0.1` は `n = 2.9999999999999996` で整数倍）。刻みの数は `k`（値は `k + 1` 通り）。`step > max - min` は、整数倍の検査より先に別のエラーにする（要件9）。許す誤差 `1e-9` は `UiSlider.js` の中の定数（位置の大きさではないので `UiMetrics.js` に置かない）。
* **刻みの値（小数の誤差を出さない。決定）:** 刻みの番号 `i`（`0`〜`k` の整数）の値は、`i === 0` なら `min`、`i === k` なら `max` そのもの、それ以外は `min + i × step` を、`min`・`max`・`step` のうち小数の桁が最も多いものの桁数 `d` で丸めた数（`Number((min + i * step).toFixed(d))`）。桁数は、`0`〜`20` のうち `Number(v.toFixed(d)) === v` になる最小の `d`（どれでもならない数が1つでもあれば丸めず、`min + i * step` のまま）。毎回 `i` から求めるので、誤差は積み重ならない。例: `min 0・max 1・step 0.1` で `i = 3` は `0.3`（`0.30000000000000004` にならない）、`min -1・max 1・step 0.1` で `i = 3` は `-0.7`、`min 0.5・max 2・step 0.25` で `i = 3` は `1.25`。`write` に渡すのはこの刻みの値だけ。
* **形（決定。エンジンが求め、見た目を差し替えても変わらない。部品の矩形 `{ x, y, width, height }` から）:**
  * 文字の段 `textRow`: `{ x, y, width, height: height / 3 }`（上の 1/3。左に項目名、右に値の文字を描く）。
  * 溝の段: 下の 2/3（上端 `y + height / 3`、高さ `height × 2 / 3`、中心 `cy = y + height × 2 / 3`）。
  * つまみの大きさ `knobSize = Math.min(SLIDER_KNOB_SIZE, 溝の段の高さ)`（既定の高さ `132` なら溝の段 `88`、つまみ `64`）。
  * 溝 `track`: `{ x: x + knobSize / 2, y: cy - SLIDER_GROOVE_HEIGHT / 2, width: width - knobSize, height: SLIDER_GROOVE_HEIGHT }`。つまみの中心は溝の左端（`min`）から右端（`max`）まで動き、つまみは部品の矩形からはみ出さない。溝は部品の幅のほぼ全体（両端のつまみの半分を除く）。
  * 刻みの番号 `i` の位置（つまみの中心の x）: `track.x + track.width × i / k`。
  * つまみ `knob`: `{ x: 中心 - knobSize / 2, y: cy - knobSize / 2, width: knobSize, height: knobSize }`。
* **押して反応する範囲:** 部品の矩形の全体（窓の内側との重なり）。縦の位置は使わない。
* **位置から刻みの番号へ（ポインタの x から。決定）:** `t = (px - track.x) / track.width` を `0`〜`1` に寄せ（溝の端より外は `min`・`max` に寄せる）、`r = t × k`。
  * `'down'`: 番号 `i = Math.round(r)`。値が `read()` と `===` で違えば `write(値)`。その後 `#pressed = true`、ドラッグ中の番号 `#dragIndex = i` にして `true`（持ち主になる）。当たりの矩形の外なら `false`。**押した位置へ飛ぶ。遊びは使わない。**
  * `'move'`（持ち主のとき。指が部品・窓の内側・窓の外へずれても、離すまで横の位置で追う）: `px ≤ track.x` なら番号 `0`、`px ≥ track.x + track.width` なら番号 `k`（端の外は遊びなしで端に止まる）。それ以外は `c = Math.round(r)` が `#dragIndex` と違い、かつ `|px − 位置(#dragIndex)| ≥ 刻みの幅 / 2 + SLIDER_HYSTERESIS`（刻みの幅 = `track.width / k`）のときだけ、番号を `c` にする。番号が変わったら `#dragIndex` を更新し、値が `read()` と `===` で違えば `write(値)`。番号が変わらなければ `read` も `write` も呼ばない。
  * `'up'`: `#pressed = false`、`#dragIndex = null` にするだけ。**離した位置では値を変えない**（最後の `'move'` までで決まった値のまま）。ボタンと違い、取り消しは無い（外で離しても、それまでに書いた値はそのまま）。
* **遊び（ヒステリシス。決定: 入れる）:** 幅 `SLIDER_HYSTERESIS = 8`（論理座標。土台の表示で約 4〜5 CSS 画素）。刻みの境目（隣の刻みとの中点）を、境目の向こうへ 8 以上越えるまで番号を変えない。境目の近くで指が細かく揺れても、値が行き来しない。押した瞬間と、端の外へずらしたときは遊びを使わない。例（溝 `track.x = 132`・`track.width = 500`・`k = 10`、刻みの幅 50）: 押して番号 3（x 282）→ x 314 へずらす（中点 307 を 7 越えた）では変わらない → x 316（9 越えた）で番号 4 → x 307 へ戻しても 4 のまま → x 298（4 の位置 332 から 34 ≥ 33）で 3。
* **`read` の戻り値が範囲外・刻みに合っていない・数でないとき（決定。操作するまで `write` を呼ばない）:**
  * つまみの中心: 値が `number` で `NaN` でなければ、`(v − min) / (max − min)` を `0`〜`1` に寄せた位置（範囲外は端、`Infinity`・`-Infinity` も端。刻みに合っていない値は、刻みに寄せずにその値の位置）。`NaN` と数でない値（`undefined`・`null`・文字列など）は左端（`min` の位置）。
  * 値の文字: いつも `read` の戻り値そのものを `format` に渡す（無ければ `String(value)`。寄せた値ではない）。
  * `info.value` は `read` の戻り値そのもの。
* **`info`:** `{ x, y, width, height, label, value, text, min, max, step, textRow, track, knob, pressed, textSize }`（`textRow`・`track`・`knob` は `{ x, y, width, height }` の新しいオブジェクト、`pressed` はドラッグ中か）。描く関数は、渡された `track` と `knob` のとおりに描けばよい（位置と値の対応はエンジンが決める）。
* 溝の向きは横だけ（縦のスライダーは作らない）。
* **後の作業への備え（今回は作らない）:** スクロールする領域の中に置くと、スライダーは押した瞬間に値を書くので、縦のずらしをスクロールとして扱う前に値が変わってしまう。後の作業で、領域の中の部品への `'down'` を遅らせるか、スライダーが押した瞬間の書き込みを、横へ動かすまで遅らせる形を検討する（5章）。今回は取り消し（`pointerCancel`）も、タップとドラッグを分ける距離の判定も作らない。

### 要件5: 選択肢の列（決定）
* **`addChoices(spec)` の項目（表にない項目はエラー）:**

  | 項目 | 必須 | 既定 | 内容 |
  | --- | --- | --- | --- |
  | `x`・`y`・`width` | | | `addButton` と同じ |
  | `height` | 任意 | 横なら `88`、縦なら `88 × 選択肢の数` | 列の全体の高さ。正の有限数 |
  | `choices` | 必須 | - | 選択肢の配列。要素は `{ label, value }`（`label` は文字列か、描くたびに呼ぶ関数。`value` は `undefined` 以外の値） |
  | `direction` | 任意 | `'horizontal'` | 並べる向き。`'horizontal'`（幅を等分して横に並べる）か `'vertical'`（高さを等分して縦に並べる） |
  | `read` | 必須 | - | 値を読む関数（引数なし） |
  | `write` | 必須 | - | 値を書く関数（引数は選ばれた選択肢の `value`） |

* **選択肢の一覧の写し:** 足した時点で、要素ごとに `{ label, value }` を写した新しい配列を持つ（後から元の配列や要素を変えても影響しない）。選択肢が0個はエラー。
* **値が重なる選択肢（決定: エラー）:** 2つの選択肢の `value` が `===` で同じならエラー（どちらが選ばれているか決まらないため）。比べ方は `===`（`NaN` は重ならないが、`read` が `NaN` を返しても選ばれない）。
* **等分（決定。選択肢どうしの間は空けない）:** 選択肢の数を `n`、境を `b_i = rect.x + rect.width × i / n`（縦は `rect.y + rect.height × i / n`）として、選択肢 `i` の矩形は、横なら `{ x: b_i, y: rect.y, width: b_{i+1} − b_i, height: rect.height }`、縦なら `{ x: rect.x, y: b_i, width: rect.width, height: b_{i+1} − b_i }`。選択肢は隙間なく並び、矩形のどこを押しても、どれか1つの選択肢に当たる（左端・上端を含み、右端・下端を含まない。境 `b_i` を含む側が `i`）。間を空けない理由: 隙間を押したときの扱いが要らず、押せる範囲が最も広い。見た目の区切りは描く関数が決める（標準の見た目は枠で区切る）。
* **選ばれている見た目:** `read()` の戻り値と `===` で同じ `value` の選択肢が選ばれている（重なりはエラーなので高々1つ）。無ければ、どれも選ばれていない。
* **押し方（ボタンと同じ）:**
  * `pointerDown(x, y)`: 当たりの矩形が点を含むなら、点を含む選択肢の番号を `#pressedIndex` に、`#pressed = true` にして `true`。含まなければ `false`。
  * `pointerMove(x, y)`: `#pressed = 当たりの矩形が点を含み、かつ点を含む選択肢が #pressedIndex`（ほかの選択肢の上へずらすと、押されている見た目が消える）。
  * `pointerUp(x, y)`: 番号を取り出し、`#pressed = false`・`#pressedIndex = null` にしてから、当たりの矩形が点を含み、点を含む選択肢が押し始めた選択肢なら、`read()` がその `value` と `===` で違うときだけ `write(value)`。外で離す・ほかの選択肢の上で離すと何も起きない。外へずらしてから戻して離すと反応する。
* **`info`（決定: 列の全体を1回の呼び出しで描く）:** `{ x, y, width, height, direction, choices, textSize }`。`choices` は選択肢ごとの `{ x, y, width, height, label, value, selected, pressed }` の新しい配列（`label` は読んだ文字、`value` は選択肢の値、`selected` は選ばれているか、`pressed` は押されているか）。1回で描くので、つながった形（区切りの線、角の丸みを両端だけにする、など）を描く関数が描ける。

    2.  **チェックボックス:** 「スロー」の上で押す → 押されている見た目（明るい灰色）になり、まだ変わらない。離す → 箱のレ点が付き（入り）、右の「ゲームの速さ」の選ばれているものが「4分の1」に替わる。もう一度押して離す → レ点が消え、「等速」が選ばれる。押したまま部品の外へずらして離す → 切り替わらない。外へずらしてから戻して離す → 切り替わる。箱ではなく項目名（「スロー」の文字）の上を押して離しても切り替わる。「ミュート」も同じに動き、入りにすると音が消え、切りにすると戻る。プレイ中のメニューの「ミュート: …」の表示と合っている（窓を閉じてメニューを開いて確かめる）。ページを読み込み直してもミュートの状態が保たれる。
    3.  **スライダー:** 「BGM の音量」の溝のどこかを押す → つまみがその位置へ飛び、値の文字が `0%`〜`100%` の 10% 刻みで変わり、BGM の音量がその場で変わる（ミュートを切っているとき）。押したまま左右へドラッグ → つまみと値の文字が 10% 刻みで追う。ドラッグ中に指（マウス）を上下に部品の外、窓の外までずらしても、離すまで横の位置で追い、窓の外で離しても窓は閉じない。離す瞬間に値が変わらない（離す直前の値のまま）。左端・右端の外までずらす → `0%`・`100%` で止まる。刻みの境目の近くで指を細かく揺らしても、値が行き来しない。窓を閉じても音量は保たれる（読み込み直すと元に戻る。保存しない）。
    4.  **選択肢の列（横）「FPS の表示」:** 「左上」を押して離す → 「左上」が選ばれた見た目になり、画面の左上に FPS の表示が出る。「右上」「右下」「左下」も同じ。「OFF」→ 表示が消える。押したままほかの選択肢の上へずらして離す → どれも選ばれない（今の選択のまま）。窓の左の見出し「FPS」に FPS の値が出る。窓を閉じ、プレイ中のメニューの「FPS」の項目で表示を変えてから、もう一度窓を開く → 選ばれているものが合っている。
    5.  **選択肢の列（縦）「ゲームの速さ」:** 「2分の1」を押して離す → 「2分の1」が選ばれ、「スロー」のレ点が付く。「等速」→ 「スロー」のレ点が消える（等速のときだけ切り）。窓を閉じる → プレイがその速さで動く。
    6.  **見た目を差し替えた窓:** 3種類の部品が、標準の見た目と区別のつく見た目（淡い青の地、橙の箱とレ点、青い溝と橙の丸いつまみ、角の丸い選択肢）で描かれ、部品の矩形からはみ出さない。押して反応する範囲と、スライダーの位置と値の対応（同じ位置で同じ値）は、標準の見た目の窓と同じ。窓の外を押しても閉じず、閉じるボタンでだけ閉じる。
    7.  **スマートフォン:** 3種類の部品が指で操作しやすい大きさである（スライダーのつまみが指の下からはみ出して見え、指で追える。選択肢を押し間違えにくい）。窓を開く前に一度画面に触れてパッドを出しておき、窓を開いた状態でパッドの位置を押しても、部品は反応せず、標準の窓も閉じない。
    8.  **大きさと向きの変化:** PC でウィンドウの大きさを変える、スマートフォンで画面の向きを変える → 部品の表示と、押して反応する位置（スライダーの位置と値の対応を含む）がずれない。
    9.  **繰り返し:** 窓を開いて閉じる・見本の窓を切り替える（「値を変える部品へ」「最初の見本へ」「見た目を切り替える」）を何度か繰り返す → 開発者ツールのコンソールにエラーが出ない。
    10. **エラー（PC の開発者ツールのコンソール。ゲームを開いたページで行う）:** `const { Ui } = await import('./oz/index.js');` の後、`const w = Ui.createWindow({ title: 'x', width: 600, height: 400, onClose() {} });` → `w.addSlider({ x: 0, y: 0, width: 400, label: 'a', min: 0, max: 1, step: 0.3, read: () => 0, write() {} })` → `Error: [oz] 窓の addSlider: max - min は step の整数倍にしてください`。`w.addChoices({ x: 0, y: 0, width: 400, choices: [], read: () => 0, write() {} })` → `Error: [oz] 窓の addChoices: choices に選択肢がありません`。
