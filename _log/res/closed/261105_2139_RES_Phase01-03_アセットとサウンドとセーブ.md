### 要件2: `Assets`（タスク2 `oz/src/Assets.js`）
**モジュール内の状態**

| 名前 | 内容 |
| --- | --- |
| `images` | `Map<名前, HTMLImageElement \| HTMLCanvasElement>`。完了した画像と、失敗の代わりの透明な画像 |
| `latestImageLoad` / `latestSoundLoad` | `Map<名前, トークン>`。名前ごとに、最後に開始したロードの印（`load` の呼び出しごとの `{}`） |
| `blankImage` | 透明な1×1の canvas。最初の失敗のときに `document.createElement('canvas')` で1回だけ作り、全失敗で共有する。ページに追加せず、`getContext` も呼ばない |

**`Assets.load(list)`**: `async` メソッドとする（検証の `throw` がそのまま reject になり、同期的に例外が出ない）。戻り値は `undefined` で解決する Promise である。

1. 引数をすべて検証する。不正なら何も始めず `Error`（先頭に `[oz] Assets.load:`、項目名を含む）で reject する。
    * `list` がオブジェクトでない（`undefined`・`null`・配列・数値など）
    * `images`・`sounds` 以外の項目がある（`image:` のような書き間違いを見つけるため）
    * `images`・`sounds` が、`undefined` でなくオブジェクトでもない（`null`・配列を含む）
    * 名前が空文字列、またはパスが空でない文字列でない
2. 一覧の順に、名前ごとのトークンを同期的に更新してからロードを開始する。
3. すべての処理（成功、失敗とも）を `Promise.all` で待って解決する。各ファイルの処理は失敗しない Promise とする。

**画像:** `new Image()` を作り、`onload` / `onerror` を設定してから `src` にパスを入れる。ページに追加しない。完了時にトークンが最新なら `images` に入れる。失敗なら警告を出し、トークンが最新なら `blankImage` を入れる。

**音声:** `fetch(パス)` → `response.ok` の確認（偽なら失敗扱い）→ `arrayBuffer()` → `decodeSound(arrayBuffer)` を `try` / `catch` で囲む。完了時にトークンが最新なら `storeSound(名前, バッファ)`。失敗なら警告を出し、トークンが最新なら `storeSound(名前, null)`。

**警告:** 失敗したファイルごとに `console.warn` で、先頭に `[oz] Assets.load:`、名前、パス、理由（分かれば）を出す。古いトークンのロードの失敗でも出す。

**同じ名前の再ロード（REQに細則がないので、本計画で次のとおり定める）:** 後に開始したロードの結果だけが残る。ロードが先に終わった順ではない。

| 場面 | `Assets.image`・`Sound.playSe`・`Sound.playBgm` の結果 |
| --- | --- |
| ロード済みの名前の再ロード中 | 前のものを使う（ループを止めないため） |
| まだ完了していない名前の再ロード中（先のロードが先に終わっても） | 未ロードとしてエラー |
| 再ロードの完了後 | 新しいものを使う |
| 再ロードが失敗 | 失敗の扱い（透明な画像、音は何もしない）に置き換わる |
| 再生中の曲の名前の再ロード | 流れている音はそのまま続く。同じ名前の `playBgm` は何もしない（従来どおり） |

**`Assets.image(名前)`:** `images` になければ `Error`（`[oz] Assets.image: "名前" はロードされていません（一覧にない名前か、ロードが終わっていません）`）を投げる。あれば返す。

`images` と `sounds` の名前は別々に管理する。同じ名前を両方に使ってよい。時間を取得しない。進捗の通知はない。

### 要件3: `Sound`（タスク1 `oz/src/Sound.js`）
**モジュール内の状態**

| 名前 | 内容 |
| --- | --- |
| `context` | `AudioContext \| null`。最初のデコードで作る |
| `masterGain`・`bgmGain`・`seGain` | 音量の `GainNode`。`context` と同時に作る |
| `inputSeen` | 最初の入力を受け取ったか |
| `buffers` | `Map<名前, AudioBuffer \| null>`。`null` はロードの失敗。名前がなければ未ロード |
| `volumes` | `{ master, bgm, se }`。既定値 `1` |
| `currentBgm` | 流れている曲の情報、または `null` |

**音の経路:**

```text
BGM: source(loop) → そのBGM専用の gain（フェード 0〜1） → bgmGain → masterGain → destination
SE : source → seGain → masterGain → destination
```

* フェードは曲ごとの `gain` に、音量は `bgmGain`・`seGain`・`masterGain` に掛けるので、経路の掛け算だけで「フェードの途中でも正しく掛け合わされる」。
* **音量の読み取りには `volumes` の値を返す。** `gain.value` は 32bit 浮動小数なので、`0.1` を入れても `0.1` に戻らず、利用側の `indexOf` などが壊れる。
* 音量の設定は `volumes` を更新し、`context` があれば `gain.value` にも入れる。`context` を作るときに `volumes` を反映する（ロードの前から設定できる）。

**内部関数（`Assets` 専用の export）**

* `decodeSound(arrayBuffer)` : `context` がなければ作る（`createContext`）。`window.AudioContext` がない、または生成に失敗したら reject する（`Assets` の警告になる）。`webkitAudioContext` への代替はしない。`context.decodeAudioData(arrayBuffer)` の Promise を返す。
* `storeSound(name, buffer)` : `buffers` に入れる。`buffer` は `AudioBuffer` または `null`。

`createContext` は、`inputSeen` がすでに真なら作った直後に `resume()` を呼ぶ（入力のあとで初めて作る場合に、ジェスチャーの記録が効くブラウザで動かすため）。

**再開用のイベント:** モジュールの読み込み時に `window.addEventListener(type, onGesture, { capture: true })` を `pointerdown`・`pointerup`・`keydown` に登録する。

```js
function onGesture(e) {
  if (e.type === 'keydown' && e.code === 'Escape') return;
  inputSeen = true;
  if (context) resumeContext();
}
function resumeContext() {
  context.resume().then(removeGestureListenersIfDone, () => {});
}
function removeGestureListenersIfDone() {
  if (inputSeen && context.state === 'running') /* 3種類を capture を指定して解除する */;
}
```

* イベントの中でするのは `resume()` の呼び出しと入力の記録だけである。シーンの処理を呼ばない。`Input` を経由しない。
* 解除の条件は **「`inputSeen` が真」かつ「`running`」** とする。`running` だけで解除すると、入力なしで `running` になったブラウザ（サイトの利用実績で自動再生を許す場合）で `inputSeen` が永久に立たず、音が鳴らなくなる。
* 再開の対象は `resume()` の呼び出しごとに判定する。`resume()` が完了しないブラウザの動作（許可されるまで Promise が保留）でも、次のイベントで再び試すので問題ない。
* ポインタの種類やボタン、`repeat` では絞り込まない。

**名前の確認（`requireSound(name, apiName)`）:** `buffers` に名前がなければ `Error`（`[oz] <apiName>: "名前" はロードされていません（一覧にない名前か、ロードが終わっていません）`）を投げる。あれば値（`null` を含む）を返す。

**`Sound.playSe(name)`** の順序:

1. `requireSound` （エラーならここで投げる）
2. `null` なら何もしない
3. `inputSeen` が偽なら何もしない（捨てる）
4. `createBufferSource` → `buffer` を設定 → `seGain` に接続 → `onended` で切断 → `start()`

ノードを毎回作るので、同じ SE を重ねて鳴らせる。`context` が `suspended` でも開始を予約するので、入力の直後で `resume()` が終わっていなくても鳴る。

**`Sound.playBgm(name, options)`** の順序:

1. `fadeMs` の検証（`RangeError`）
2. `requireSound`
3. `null` なら何もしない（流れている BGM はそのまま）
4. `inputSeen` が偽なら何もしない
5. `currentBgm` が同じ名前なら何もしない（フェードインの途中でも何もしない）
6. `currentBgm` があれば `fadeOutAndStop(currentBgm, 秒)`
7. 新しい曲を始めて `currentBgm` にする

**`Sound.stopBgm(options)`:** `fadeMs` を検証する。`currentBgm` がなければ何もしない。あれば `fadeOutAndStop(currentBgm, 秒)` のあと `currentBgm = null` とする。

* `fadeMs` の検証: `options?.fadeMs` が `undefined` なら `0`。`0` 以上の有限数でなければ `RangeError`（先頭に `[oz] Sound.playBgm:` など）。入力の前でも検証する。
* **フェードアウト中の曲は、`currentBgm` から外すだけで追跡しない。** 停止の予定（`source.stop(when)`）と `onended` の切断だけが残る。したがって、フェードアウト中の曲を `playBgm` で指定すると、`currentBgm` が別物なので手順7で頭から新しく流れ、フェードアウト中の音はそのまま消える。

**曲の情報（`currentBgm`）:** `{ name, source, gainNode, fromLevel, toLevel, startTime, endTime }`。後ろの4つは最後に予定したフェードの内容で、時刻は `context.currentTime` の秒である。

**現在のレベル（`currentLevel(voice, now)`）:** `gain.value` を読まず、記録から直線の式で計算する。`AudioParam.value` がフェードの途中の値を返すかはブラウザに依存し、`cancelAndHoldAtTime` は Firefox にないためである。

```text
endTime <= startTime なら toLevel。そうでなければ
fromLevel + (toLevel - fromLevel) × clamp((now - startTime) / (endTime - startTime), 0, 1)
```

**新しい曲を始める（`seconds` は `fadeMs / 1000`）:**

```text
now = context.currentTime
source.loop = true、source → gainNode → bgmGain に接続、onended で切断
seconds > 0: gain.setValueAtTime(0, now)、gain.linearRampToValueAtTime(1, now + seconds)
seconds = 0: gain は既定値 1 のまま
source.start()
記録: seconds > 0 なら from=0, to=1, start=now, end=now+seconds。seconds = 0 なら from=to=1
```

**`fadeOutAndStop(voice, seconds)`:**

```text
now = context.currentTime
level = currentLevel(voice, now)
gain.cancelScheduledValues(now)
gain.setValueAtTime(level, now)
seconds > 0: gain.linearRampToValueAtTime(0, now + seconds)
source.stop(now + seconds)
```

これにより、フェードインの途中の `stopBgm` や曲の切り替えでも音量が飛ばない。

**音量のプロパティ:** `Sound.masterVolume`・`Sound.bgmVolume`・`Sound.seVolume` を getter / setter とする。`typeof value === 'number'` かつ `0 <= value <= 1` でなければ `RangeError`（`NaN` もここで弾く）。変更しない。

**時間:** `AudioContext.currentTime` は上の予定時刻にだけ使い、公開しない。`setTimeout`、`performance.now`、`Date` を使わない。`timeScale` やシーンの状態を知らないので、`timeScale` が `0` でもシーンを積んでも音はそのまま進む。タブの表示状態も見ない。

**持ち込まないもの（phaseout）:** ピンチ BGM、状態遷移、フィルタ、アナライザ、ビジュアライザ、ピッチ、ずらし再生、`setTimeout` の停止、`GameState`・`AppConfig` への依存。

### 要件4: `Storage`（タスク3 `oz/src/Storage.js`）
**モジュール内の状態:** `storageKey`（`null` なら `open` の前）、`version`、`values`（`Map<名前, 値>`。`defaults` の名前だけを持つ）。

**保存の形:** 指定した `key` に `JSON.stringify({ version, data: { 名前: 値, ... } })` を1つ保存する。

**JSON にできる値の判定（`assertJson(value, apiName)`）:** 再帰で確認する。許すのは `null`、真偽値、文字列、有限の数値、配列、プレーンなオブジェクト（プロトタイプが `Object.prototype` か `null`）だけである。`undefined`・関数・シンボル・BigInt・`NaN`・`Infinity`・`Date`・`Map`・循環参照はエラーにする。`JSON.stringify` は `NaN` を黙って `null` に、`Map` を `{}` に変えるので、それだけでは足りない。

**`Storage.open({ key, version, defaults })`:** 次は `Error`（先頭に `[oz] Storage.open:`、項目名を含む）を投げ、開いていない状態のまま残す。

* すでに開いている（2回目）
* 引数がオブジェクトでない
* `key` が空でない文字列でない
* `version` が有限の数値でない
* `defaults` がオブジェクトでない（`null`・配列を含む）。空のオブジェクトは許す
* `defaults` の値が JSON にできない

読み込みは次の順で行う。

| 場面 | 結果 | 警告 |
| --- | --- | --- |
| `localStorage` の取得や `getItem` が例外を投げる（`window.localStorage` の参照も `try` の中に置く。`null` の場合を含む） | 全部既定値 | あり（`[oz] Storage.open:`） |
| 保存データがない | 全部既定値 | なし |
| JSON として読めない | 全部既定値 | なし |
| 形が違う（オブジェクトでない、配列、`data` がオブジェクトでない、または配列） | 全部既定値 | なし |
| `version` が違う | 全部既定値 | なし |
| 上記以外 | `defaults` の名前ごとに、保存値が `Object.hasOwn` であれば保存値、なければ既定値。`defaults` にない保存値は捨てる | なし |

`open` は `localStorage` へ書き込まない（古いデータは最初の `set` まで消さない）。`defaults` は `open` の時点でコピーを取るので、あとで元のオブジェクトを変更しても影響しない。

**`Storage.get(名前)`:** `open` の前と `defaults` にない名前は `Error`（`[oz] Storage.get:`）。値のコピーを返す（`JSON.parse(JSON.stringify(値))`）。

**`Storage.set(名前, 値)`:** `open` の前、`defaults` にない名前、JSON にできない値は `Error`（`[oz] Storage.set:`）で、状態を変えない。値のコピーを `values` に入れ、全体を `setItem` する。`setItem` と `localStorage` の参照を `try` で囲み、例外なら `console.warn`（`[oz] Storage.set:`）を出してメモリの上で続ける。失敗した `set` のたびに警告を出す。次の `set` で再び保存を試す。

`values` は `Map` なので、`__proto__` や `constructor` という名前の問題は起きない。保存時の `data` は `Object.fromEntries(values)` で作る。時間を取得しない。

## 5. 懸念事項・要確認ポイント
計画の時点で、REQに細則がなく本計画で定めたもの、および発注者のテストプレイで確かめてほしいものを記録する。

* **同じ名前の再ロード中の動作（本計画で決定）:** REQは「同じ名前は後のものに置き換わる」「ロードが終わっていない名前はエラー」と定めるが、ロード済みの名前の再ロード中については定めていない。ループを止めないよう、完了までは前のものを使うとした（要件2の表）。
* **JSON にできない値の範囲（本計画で決定）:** `NaN`・`Date` など、`JSON.stringify` が例外を出さずに別の値へ変えるものもエラーとした（要件4）。
* **`Assets.load` の未知の項目（本計画で決定）:** `image:` のような書き間違いを見つけるため、`images`・`sounds` 以外の項目を不正な引数とした（要件2）。
* **解除前に数えられる入力:** REQの定義により、タッチの `pointerdown` や、ブラウザが解除を認めないキー（ブラウザ予約のショートカットなど）も最初の入力に数える。そのあと解除までの間に要求した音は、解除の時点でまとめて鳴ることがある。タッチでは `pointerup` がすぐ続くので通常は問題にならない。実機で気になる場合は発注者の判断を仰ぐ。
* **解除後の中断:** REQのとおり `running` になったらイベントの登録を解除するので、iOS の割り込みなどでブラウザが AudioContext を止めた場合に自動では再開しない。今回は対応しない。
* **MP3 のループ:** MP3 は先頭と末尾に無音が入ることがあるので、BGM のつなぎ目がわずかに聞こえる可能性がある。テストプレイで確認する。
* **確認用コードの `5` キー:** BGM を流す状態のまま最初の入力として `5` を押すと、止める状態へ切り替わるだけで音は鳴らない（要件5の切り替えのとおり）。もう一度押すと流れ始める。
* **読み込みに失敗した画像の確認用の表示:** 透明な1×1の画像は縦横比が 1:1 なので、200×200 の範囲に何も描かれない。
* **目視の確認:** 音の聞こえ方、フェードの滑らかさ、ブラウザの自動再生制限の実際の動作は Node のスタブでは確かめられない。REQの「画面での確認」のとおり、発注者のテストプレイで確認する。
* **Node の確認の手順の変更:** `oz/index.js` の import の時点で `window` が必要になる（要件3）。今後の Node の確認では、スタブを用意してから動的 import する。
* **タスク4（目視の確認）:** `5` を最初の入力にした場合の動作、`?savever=2` での実ブラウザの `localStorage`、画像の見た目と配置（右上、文字と重ならないこと）は実機で確認してほしい。ENGINE_API.md の不足は見つからなかった。
