# RES: 作業計画・作業レポート Phase 05-04 : タブとスクロールする領域
* 参照元REQ: `./_log/req/261122_1008_Phase05-04_タブとスクロールする領域.md`

## 1. 作業目的
Phase 05-02・05-03 でエンジンに入った UI 部品（`Ui`。`oz/ENGINE_API.md` 26章）に、窓の中の部品をまとめる2種類の仕組み、タブとスクロールする領域を足す。ゲーム（バトリティア）の開発用の調整パネルは項目が多く、窓の中に収めるために求めている。

タブの列は、列の矩形をタブの数で等分して横に並べ、選ばれているタブの部品だけを描き、押せるようにする（どのタブにも入れない部品は常に出る）。スクロールする領域は、窓の内側の矩形を1つ持ち、その中に部品を並べ、指（マウス）で縦にずらすと中身が指に付いて動く（慣性・ホイール・横のスクロールは作らない）。領域の中では、押した位置から決まった距離を越えて動くまではタップ（部品を押す）、越えたらドラッグ（スクロール）として扱い、領域の中のスライダーは動かした向きで決める。

あわせて、見た目の差し替え（`look`）に2種類を足し、標準の見た目で描き、Canvas を使わない部分を自動テストの対象にし、`oz/ENGINE_API.md` 26章に使い方を書き、05-03 から持ち越した軽微な点（スライダーの丸めの説明、`step ≤ max - min` の誤差）を片付け、ゲームの土台にタブとスクロールする領域を使った見本の窓（標準／差し替え）を足して確かめられるようにし、新規プロジェクトの手順書に直すところが無いかを確かめる。

05-02・05-03 の窓と5種類の部品の動き、既存の `look` の種類と `info` の項目は、スクロールする領域の中に置いたときの動きを除いて変えない。`Engine`・`Buttons`・`Input`・`Scenes`・`GameLoop`・`Sound`、`oz/index.js`・`oz/VERSION`・`js/main.js`・`index.html`・`assets/`、プレイ中のメニュー（`MenuScene`・`playMenu.js`）は変えない。

## 2. アーキテクチャ設計

### 今の作り（計画のために確かめた結果）
* `UiWindow` は、部品を共通の形（`kind`、`hitTest(x, y)`、`pointerDown(x, y)` → 持ち主になるか、持ち主のときだけ呼ばれる `pointerMove(x, y)`・`pointerUp(x, y)`、`info(textSize)`）だけで扱う。`'down'` で `#findOwner` が後に足した部品から `hitTest` → `pointerDown` を呼び、`'move'` は持ち主の `pointerMove`、`'up'` は `#capture = null` にしてから持ち主の `pointerUp` を呼ぶ。持ち主が部品なら、指が窓の外へ出ても `'move'`・`'up'` はその部品に届き、窓は閉じない（閉じる判定は持ち主が `OUTSIDE` のときだけ）。**スクロールする領域とタブの列がこの共通の形を持てば、窓のポインタの振り分けの骨組みは変えなくてよい。**
* 5種類の部品は、constructor で受けた画面の論理座標の矩形 `rect` と当たりの矩形 `hitRect` を持ち、`hitTest` は `containsPoint(hitRect)`、`info` は `rect`（スライダーは constructor で求めた `textRow`・`track`・つまみの中心の高さ、選択肢の列は constructor で求めた境と選択肢ごとの矩形）を返す。**部品は自分の位置を後から動かせない。** constructor は `label`・`read`・`write`・`format`・`enabled` を呼ばない（作るだけなら利用側の関数は呼ばれない）。部品が持つ状態は、押されているか（スライダーはドラッグ中の番号）だけで、離せば消える。
* 窓は今、5つの足す操作のそれぞれで「検証（`validate*Spec`）→ 矩形と当たりの矩形（`#partRects`）→ 部品を作って並びに足す」を書いている。スクロールする領域でも同じ5種類を作るので、検証と作り方を1か所に集めないと二重に書くことになる。
* `UiRenderer` は暗幕 → 窓 → タイトルバー → 閉じるボタン → 部品（`view.parts` の順。窓の内側で切り取る）を、`look[kind] ?? STANDARD_LOOK[kind]` で選んだ関数を `save` / `restore` で囲んで呼ぶ。
* `UiSlider.js` の刻みの小数の桁数（`decimalPlaces`）は、`0`〜`20` の桁数 `d` のうち `Number(v.toFixed(d)) === v` となる最小の `d` を返し、どの `d` でも合わなければ `-1`。`min`・`max`・`step` のどれかが `-1` なら丸めない（`min + i × step` のまま）。node で確かめた結果: `1e-7` → 7、`1.5e-7` → 8、`1e-20` → 20、`1e-21`・`1.5e-20` → `-1`、`1e21`・`1.5e300` → 0（`toFixed` が指数の形の文字を返し、それを数に戻すと元の数になる）。**指数の形で書かれる小さな数（`1e-7` など）も、20 桁までなら桁数で丸められる。丸めないのは、0 でなく、小数第 20 位までで表せない数（およそ `1e-20` より小さい桁を持つ数）があるときだけ。**
* `step ≤ max - min` の判定は `spec.step > spec.max - spec.min` の素の比較で、`min 0.1・max 0.3・step 0.2` は `0.3 - 0.1 = 0.19999999999999998 < 0.2` のためエラーになる（node で確かめた）。整数倍の判定（`countSteps`）は同じ値を `k = 1` の整数倍として通すので、2つの判定が食い違っている。

### 要件2: タブ（決定）
* **`addTabs(spec)` の項目:** `x`・`y`（必須。有限の数値）、`width`（必須。正の有限数）、`height`（任意。既定 `DEFAULT_TAB_HEIGHT` = 88。正の有限数）、`labels`（必須。タブの名前の配列。要素は文字列か、描くたびに呼ぶ関数（ほかの部品の `label` と同じ形）。1つ以上）。表にない項目はエラー。`labels` は足した時点で写して持つ（後から元の配列を変えても影響しない）。
* **等分:** 選択肢の列の横と同じ考え方。境 `b_i = rect.x + rect.width × i / n`（`i = 0〜n`）、タブ `i` は `b_i` 以上 `b_{i+1}` 未満、全高。境の点は後ろ側のタブ。タブどうしの間は空けない。
* **押し方（ボタン・選択肢の列と同じ）:** 押すと、押した位置のタブが押されている状態になる。押し始めたタブの上にある間だけ押されている状態で、ほかのタブの上や列の外へずらすと消える。押し始めたタブの上で離したときだけ、そのタブが選ばれる（選ばれているタブを押して離しても変わらない）。外やほかのタブの上で離すと何も起きない。当たりの矩形は列の矩形と窓の内側の重なり。
* **選ばれているタブ:** タブの列（`UiTabs`）が番号で持つ。最初は 0（先頭）。`read`・`write` は使わない。ゲームから読む・変える口は作らない（`UiTabs` の `selected` の getter は窓が出し分けに使うだけで、`Ui.js` から出さない）。窓を作り直すと先頭に戻る。
* **出し分け:** 窓の部品の並びは `{ part, tab }`（`tab` はタブの番号か `null`）。`tab === null`（どのタブにも入れない部品。タブの列そのものを含む）か、`tab` が選ばれている番号の部品だけを「出ている」とし、`#findOwner` と `view()` は出ていない部品を飛ばす（描かれず、`info` も作らない＝`label`・`read` も呼ばれない。押しても反応せず、その位置にある出ているほかの部品が調べられる）。後に足した部品が上という順は、出ている部品の中で今までどおり。
* **エラー:** 2つ目のタブの列、タブが0個、タブの列をタブ・スクロールする領域に入れる、はエラー（要件7の一覧）。

### 要件3: スクロールする領域（決定）
* **`addScroll(spec)` の項目:** `x`・`y`（必須。有限の数値）、`width`・`height`（必須。正の有限数）。表にない項目はエラー。
* **領域の矩形:** 画面の論理座標で `{ 窓.x + spec.x, 内側.y + spec.y, width, height }`。見える範囲 `visible` は領域の矩形と窓の内側の重なり。
* **中身の高さ（決定: 中の部品の下端から求める）:** `contentHeight = Math.max(height, 中の部品の (y + height) の最大)`（部品が無ければ `height`）。呼ぶ側が渡す項目は作らない（部品の位置と食い違う設定をできなくするため）。部品を足すと増えることはあっても減らないので、足してもスクロールの位置は変わらない。いちばん下の部品の下端が、いちばん下までスクロールしたときの領域の下端になる（下の余白が要る場合は、呼ぶ側が部品の位置で作れないので、5章に書く）。
* **スクロールの位置:** `scrollY`（0 が上端。下へずらすほど大きい）。`0 ≤ scrollY ≤ contentHeight - height`。`contentHeight - height > 0` のときだけスクロールできる。領域（`UiScroll`）が持ち、窓を開いている間は保たれる（タブを切り替えて戻っても同じ。領域のオブジェクトは消えないため）。ゲームから読む・変える口は作らない。
* **中の部品の位置（決定: スクロールの位置が変わるたびに中の部品を作り直す）:** 中の部品は、検証済みの設定と作り方（`UiPartKinds`）を領域が持ち、今のスクロールの位置での画面の矩形 `rect = { 領域.x + s.x, 領域.y + s.y - scrollY, width, height }` と当たりの矩形 `hitRect = intersectRect(rect, visible)` で作る。スクロールの位置が変わったときは、すべての中の部品を新しく作り直す。
    * 理由: 部品は位置を後から動かせない（スライダー・選択肢の列は constructor で形を求めている）。部品のファイルに位置をずらす口を足すと、5種類のファイルにスクロールの知識が散る（REQ の「責務の分離」）。作り直しても失われる状態は無い（スクロールの位置が変わるのはドラッグ中だけで、そのとき中の部品は押されていない。後述）。constructor は利用側の関数を呼ばないので、作り直しても `label`・`read` などは呼ばれない。部品の数が数十でも、ポインタの1回ごとの作り直しは軽い。
    * 同じ理由で、ドラッグになったときの取り消しも「中の部品を作り直す」で行う（押されている状態を持たない新しい部品になる）。`UiButton.js`・`UiCheckbox.js`・`UiChoices.js` に取り消しの口（`pointerCancel` など）を足さない。
* **切り取りと当たり:** 中の部品の当たりの矩形は、部品の矩形と見える範囲（領域と窓の内側の両方）の重なり。全部が外にある部品は押せない。描くときは領域の矩形で切り取る（`UiRenderer`）。**領域の矩形と重ならない中の部品は、描く関数を呼ばない（`info` を作らない＝`read` なども呼ばれない）。**
* **ずらし方:** 領域の見える範囲の中で押すと、中の部品の有無にかかわらず、領域が持ち主になる（部品の無いところ・数値・文字の表示・押せないボタンの上でも、ずらせる）。ドラッグになったら、`'move'` のたびに `scrollY` を前の `'move'` の縦の位置との差だけ動かす（`scrollY = clamp(scrollY + (前の y - y))`。指を上へ動かすと中身が上へ動く）。上端・下端より先へは動かない（その先へ指を動かしても止まったまま。指を戻すと、戻した分だけすぐに動く）。ドラッグになった `'move'` そのものでは動かさない（決まった距離の分だけ中身が飛ばないように、ドラッグになった位置から指に付いて動く）。離したら、その位置で止まる（慣性なし。時間を使わない）。
* **位置の表示（決定: 領域の右端の内側の、縦の細い帯とつまみ。押して動かせない）:** 帯 `{ x: 領域.x + width - SCROLL_BAR_WIDTH, y: 領域.y, width: SCROLL_BAR_WIDTH, height }`、つまみの長さ `thumbH = Math.min(height, Math.max(SCROLL_THUMB_MIN_LENGTH, height × height / contentHeight))`、つまみの上端 `領域.y + (height - thumbH) × scrollY / (contentHeight - height)`。スクロールできるときだけ描く。位置の表示の上を押しても、領域のほかの場所と同じ扱い（ずらすと中身が指に付いて動く）。中の部品は、右端の `SCROLL_BAR_WIDTH` を空けて置くことを 26章で勧める。
* **入れられないもの:** スクロールする領域の中に、スクロールする領域とタブの列は入れられない（エラー）。スクロールする領域はタブに入れられる。

### 要件4: タップとドラッグの区別（決定）
* **置き場所:** `UiScrollGesture.js`（状態の移り変わりと判定）。領域（`UiScroll`）は、押した位置のいちばん上の中の部品を探して渡し、ジェスチャからの依頼（スクロールの量、取り消し）を受けて位置の計算と作り直しを行う。部品のファイルはスクロールを知らない。
* **分ける距離（決定: `SCROLL_DRAG_DISTANCE` = 20。論理座標）:** 押した位置から `dx² + dy² > 20²`（20 を越えた）になったらドラッグ、それまで（ちょうど 20 を含む）はタップ。理由:
    * 土台の表示（論理座標の 1 が約 0.5〜0.6 CSS 画素）で約 10〜12 CSS 画素。タップのときの指の揺れ（数 CSS 画素。Android の標準の判定の距離が 8 dp）より大きく、ボタンの高さ 88 の半分（44）より十分小さいので、ボタンの上でタップした指が少し揺れてもボタンの上に残る。
    * スライダーの遊び（8）より大きい。遊びが吸収する程度の揺れでは、ドラッグにもスライダーの操作にもならない。
    * 横寄りと決まった時点で、スライダーは押した位置の刻みの値を書き、そこから遊び付きで追う（後述）。既定のスライダー（幅 504〜552、刻み 10 個なら刻みの幅 約 44〜49）では、隣の刻みへ移るのは押した位置の刻みから「刻みの幅の半分 + 8」（約 30）以上離れたときなので、決まった瞬間（約 20 離れた位置）に値が2回変わることはふつう無い。
* **ボタン・チェックボックス・選択肢の列（領域の中）:** 押した瞬間に中の部品の `pointerDown` を呼ぶ（押されている見た目は押した瞬間から出す。決定。理由: 時間を使わないので「少し待ってから出す」ができず、遅らせると、離すまで見た目が変わらない）。距離の手前の `'move'` は部品の `pointerMove`、手前で離したら部品の `pointerUp`（今までどおり、外へずらすと取り消し、戻して離すと反応）。距離を越えたら（向きにかかわらず）ドラッグになり、押されていた部品を取り消す（中の部品の作り直し）。その後の `'move'`・`'up'` は部品に渡さない（離しても反応しない）。
* **スライダー（領域の中。発注者の決定）:** 押しただけでは `pointerDown` を呼ばない（値を書かない。押されている見た目にもならない）。距離の手前の `'move'` は何もしない。
    * 距離を越えたとき、横寄り（`|dx| > |dy|`）ならスライダーの操作になる: その場で `pointerDown(押した x, 押した y)`（押した位置の刻みの値を書く。05-03 の押した瞬間と同じ）→ 続けて `pointerMove(今の x, 今の y)`。以後の `'move'` は `pointerMove`（05-03 の遊び・端の外のまま。離すまで横の位置で追い、外へ出ても続く）、`'up'` は `pointerUp`（離した位置では値を変えない）。
    * 縦寄り（`|dx| ≤ |dy|`。等しいときは縦）ならスクロールのドラッグになり、値は変わらない。
    * 距離を越えずに離したときは、`pointerDown(押した x, 押した y)` → `pointerUp()` で、押した位置へ値が飛ぶ（離したときに `read` 1回 → 違えば `write` 1回）。
    * 押した位置の値を書くのは、押したときにはスクロールの位置が変わっていない（ドラッグになるまで動かない）ので、押した位置の当たりと溝の位置がそのまま使えるため。
* **窓に直接置いた部品:** 05-03 までのまま（ジェスチャは通らない）。
* **外へ出たとき:** 領域が持ち主なので、ドラッグ中（スクロール・スライダー）に指が領域の外・窓の外へ出ても、離すまで続く。離しても窓は閉じない（今の窓の仕組みのまま）。
* **状態の変更の場所:** 押されているか、ドラッグ中か、スクロールの位置、選ばれているタブの変更と、`write`・`onPress` の呼び出しは、すべて窓の `onPointer` から呼ばれる `pointerDown`・`pointerMove`・`pointerUp` の中で行う。`view()` と描く処理は状態を変えない。
* **`UiScrollGesture` の形（`UiScroll` の中だけで使う）:**
    * `constructor({ scrollBy, cancel })`: `scrollBy(dy)` はスクロールの位置を `dy` だけ動かす依頼、`cancel()` は押されていた中の部品の取り消しの依頼（領域が中の部品を作り直す）。
    * `get dragging`: スクロールのドラッグ中か（`info.dragging`）。
    * `down(x, y, child)`: `child` は押した位置のいちばん上の中の部品、または `null`。状態 `{ downX, downY, lastY, mode: 'pending', child, slider }` を作る。`child.kind === 'slider'` なら `slider` に入れて `pointerDown` を呼ばない。それ以外の部品は `child.pointerDown(x, y)` が真のときだけ `child` に入れる。
    * `move(x, y)`: 状態が無ければ何もしない。`'pending'` で距離の手前なら `child?.pointerMove(x, y)`。距離を越えたら、`slider` があり横寄りなら `'slider'`（上のとおり）、それ以外は `'drag'`（`child` があれば `cancel()` を依頼して `child = null`。`lastY = y`）。`'slider'` は `slider.pointerMove(x, y)`。`'drag'` は `scrollBy(lastY - y)` → `lastY = y`。
    * `up(x, y)`: 状態を消してから、`'pending'` なら（`slider` があれば `pointerDown(downX, downY)` → `pointerUp()`、`child` があれば `child.pointerUp(x, y)`）、`'slider'` なら `slider.pointerUp()`、`'drag'` なら何もしない。

### 要件8: 05-03 から持ち越した軽微な点（決定）
* **丸めの桁数の説明（実装は変えない）:** 26章「スライダーの値の決まり方」に、「桁数は、`0`〜`20` のうち `Number(v.toFixed(桁数)) === v` となる最小の桁数。`1e-7` のように指数の形で書かれる数も、この桁数（`1e-7` は 7）で扱う。`1e21` 以上の数は桁数 0 として扱う（`toFixed` が指数の形の文字を返すため。丸めても元の数のまま）。`min`・`max`・`step` のどれかが小数第 20 位までで表せない数（`1e-21`、`1.5e-20` など）のときは丸めず、`min + i × step` の計算のまま（小数の誤差が残ることがある）」を書き足す。実装を読み直して、この記述が実装の動きと合うことを確かめてから書く。

    3.  **スクロール:** 領域の中を押して上へずらす → 中身が指に付いて上へ動き、下の部品（「FPS の表示」の選択肢、「1 足す」など）が出てくる。いちばん下（「0 に戻す」の下端が領域の下端）で止まり、それ以上は動かない。下へずらす → 上端（「スロー」の上に余白 12）で止まる。離す → その位置で止まる（流れない）。右端の位置の表示（細い帯の中のつまみ）が、今の位置と中身の量（つまみの長さは領域の約 1/3）に合っている。領域の外（上の「タブの列」と下の「押した数」の間の外側）にはみ出した部品は見えず、領域の上端・下端で切れて見える部品の、見えていない部分を押しても反応しない。
    4.  **スクロールして押す:** いちばん下までスクロールして「1 足す」を押して離す → 「押した数」が 1 増える。「10 足す」→ 10 増える。「0 に戻す」→ 0 になる。窓を閉じて開き直しても、押した数は保たれる。
    5.  **タップとドラッグ:** 領域の中のボタン・チェックボックスの上で押す → 押されている見た目になる。少しだけ（指の揺れ程度）動かして離す → 反応する（チェックボックスなら入り・切りが替わる）。押したまま大きく上下にずらす → 押されている見た目が消えてスクロールになり、離しても反応しない。部品の無いところ（部品どうしの間）や「FPS の表示」の表示の上からもずらせる。
    6.  **領域の中のスライダー:** 「BGM の音量」の溝を押しただけ → つまみも値も変わらない。押したまま横へ動かす → つまみが押した位置へ飛び、そのまま横に追い、値の文字（`0%`〜`100%`）と BGM の音量がその場で変わる（ミュートを切っているとき。効果音の音量は次に鳴る効果音で分かる）。押したまま縦へ動かす → スクロールになり、値は変わらない。動かさずに離す → 押した位置へ値が飛ぶ。横に動かしている途中で指を領域の外・窓の外へ出しても、離すまで横の位置で追い、離しても窓は閉じない。
    7.  **値が合っている:** 「スクロール」で「スロー」を入れ、BGM・効果音の音量を変えてから「表示」を押す → 「スロー」が ON、音量の表示が変えた値と同じ。「スクロール」に戻る → スクロールの位置が切り替える前のまま。
    8.  **見た目を差し替えた窓:** タブ（淡い青と橙の角の丸いタブ）、スクロールする領域（淡い茶色の角の丸い地）、位置の表示（橙の丸いつまみ）が、標準の見た目と区別のつく見た目で描かれ、部品の矩形からはみ出さない。押して反応する範囲、タブの境、スクロールの動き（止まる位置、位置の表示の長さと位置）は、標準の見た目の窓と同じ。
    9.  **スマートフォン:** タブが指で押しやすい（高さ 88。約 44〜52 CSS 画素）。上下のスクロールと、スライダーの横の操作が意図どおりに分かれる（斜めに動かすと、横寄りならスライダー、縦寄りならスクロール）。ボタンを軽くタップすると反応し、スクロールしようとした指でボタンが反応しない。窓を開いた状態でパッドの位置を押しても、部品は反応せず、標準の窓も閉じない。
    10. **大きさと向きの変化:** PC でウィンドウの大きさを変える、スマートフォンで画面の向きを変える → 部品の表示と、押して反応する位置（スクロールした後の位置、タブの境を含む）がずれない。
    11. **繰り返し:** 窓を開いて閉じる・見本の窓を切り替える（「タブとスクロールへ」「最初の見本へ」「見た目を切り替える」「値を変える部品へ」）を何度か繰り返す → 開発者ツールのコンソールにエラーが出ない。
